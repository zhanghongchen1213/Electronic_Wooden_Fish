## 1. 板级 GPIO 与总线总表

### 1.1 GPIO 总表（唯一引脚源 = ARCHITECTURE-SPINE §板级合同）

> 下表逐行抄录 spine 板级合同（来源 09-08 附录 §3.1；新 BSP 默认合同）。**不得以 legbot 源文档的 `引脚定义.png` 或任何示例代码覆盖本表。**

| 功能 | 信号 | ESP32-S3 GPIO | 约束 |
| --- | --- | ---: | --- |
| BOOT | BOOT0 | IO0 | 启动绑带；保留下载路径 |
| PWR | 运行态输入 | IO46 | 启动绑带；固件只读，长按开关机由板级电源 |
| RESET | EN | EN | 独立按键/测试点 |
| PVDF | ADC | IO9 | ADC1_CH8；前端限流/钳位、控输入范围 |
| PVDF 唤醒 | 比较器输出 | IO11 | 低功耗 GPIO 唤醒；醒后 ADC 确认有效敲击 |
| 共享 I²C | SDA / SCL | IO1 / IO2 | BQ25895/CW2015/CST9217/ES8311/QMI8658A 共用；地址不得冲突 |
| CST9217 | TP_RST / TP_INT | IO38 / IO39 | 触摸复位与中断 |
| QMI8658A | INT1 | IO41 | 未来 WoM 扩展；INT2 不接、不占 GPIO45 |
| CO5300 | RST/CS/SCL/D0/D1/D2/D3/EN | IO4/40/5/6/7/12/42/47 | 沿用 legbot 屏幕资源基线 |
| ES8311 | I2S_DO/WS/BCLK/MCLK | IO13/14/18/21 | 沿用 legbot 音频资源基线 |
| NS4150B | PA_EN | IO48 | 静音/暂停/故障回到禁用 |
| Air780EGP | UART TX/RX | IO43/44 | 从 main_control 抽离板级引脚常量 |
| Air780EGP | DTR/RST | IO10/15 | 休眠/复位；NET_STATUS 不接 ESP32 |
| 保留 | IO8 | NC/测试点 | 不接 M100 GNSS_VCC，不配置 GPIO |
| RGB | DATA | IO3 | 状态灯，不作调试灯 |
| USB | D− / D+ | IO19/20 | 原生 USB-Serial-JTAG |

补充约束（spine §板级合同原句语义）：

- **GPIO45** 保持未接或按模组要求处理（影响 VDD_SPI 启动采样），**不连接 QMI8658A INT2**。
- **GPIO33–37** 通常与 Octal Flash/PSRAM 相关，不作为通用 GPIO。
- **启动绑带**：下载要求 GPIO0=0、GPIO46=0；PWR/QMI8658A 输出不得在复位采样窗口把 IO0/45/46 推到错误电平（见 spine 工程验证门禁）。
- **未核验参数**在样机/原理图前不得冻结（CO5300 首帧与亮度档、CST9217 实际地址、PVDF 前端与比较器料号、上拉阻值等见 §Deferred 工程项）。

### 1.3 共享 I²C 总线与器件地址

共享 I²C（IO1/2）挂载 **BQ25895 / CW2015 / CST9217 / ES8311 / QMI8658A**。spine 明确：共用一组总线与上拉；**地址以目标物料 + 实板上电扫描为准**，首版先保证无冲突：

| 器件 | 功能 | 参考地址 | EWF 职责 |
| --- | --- | --- | --- |
| BQ25895 | 充电/NVDC/PMID OTG | `0x6A`（TI 固定） | 充电状态、电源路径、OTG；IO8 控制 OTG 脚 |
| CW2015 | 电量计 | 约 `0x62` | 电量/低电量状态（FR-E-009），进低功耗状态机 |
| CST9217 | 电容触摸 | 7-bit `0x5A` | 触摸导航 + 木鱼页电子木鱼点击（仅木鱼页产生 `device_touch`） |
| ES8311 | 音频 codec | 由 CE/CDATA 配置，按目标手册确认 | codec 配置 I²C（I2S 数据走独立总线，见 §4） |
| QMI8658A | 六轴 IMU | 首版 `0x6B`（SA0=高） | 上板但默认不启用，仅未来 WoM 扩展；避开 BQ `0x6A` |

总线使用规则（spine AD-10）：共享 I²C **经单一总线仲裁访问**，禁止多服务并发抢占；业务层不直接调 `managed_components` 硬件 API（BSP 封装，AD-8）。

### 1.4 总线实例分配

> 固件正式代码尚未建立，以下为「BSP 落地时在此冻结」的基线；UART 实例号等随固件 story 定，未冻结前不承诺。legbot 示例约定保留：共享 I²C 用 `I2C_NUM_0`、ES8311 数据用 `I2S_NUM_0`、CO5300 QSPI 用 `SPI3_HOST`。

| 总线/资源 | GPIO/信号 | 连接外设 | 说明 |
| --- | --- | --- | --- |
| 共享 I²C（I2C0 约定） | SDA IO1 / SCL IO2 | BQ25895、CW2015、CST9217、ES8311、QMI8658A | 单总线仲裁 + 统一 I²C 扫描 + 错误恢复；五地址不得重复 |
| I2S0（约定） | MCLK IO21 / BCLK IO18 / WS IO14 / DO IO13（播放-only；不接 DI） | ES8311 → NS4150B → 扬声器 | codec 控制走 I²C，音频数据走 I2S |
| SPI3_HOST / QSPI | CS IO40 / SCLK IO5 / D0 IO6 / D1 IO7 / D2 IO12 / D3 IO42 / RST IO4 / EN IO47 | CO5300 AMOLED | 高带宽；优先级与 PSRAM/LVGL buffer 相关 |
| Air780EGP UART | TX IO43 / RX IO44 | Air780EGP 4G | 单一 AT 入口 + 单一事务所有权；AT/HTTPS 经验另源 `main_control` |
| Air780EGP 控制 | DTR IO10 / RST IO15 | 同上 | 休眠/复位；NET_STATUS 不接 ESP32；M100 GNSS_VCC 留 NC/TP |
| 保留 | IO8 | 不接外设 | NC/测试点，不配置 |
| USB-Serial-JTAG | D− IO19 / D+ IO20 | PC（烧录/CDC 日志/OpenOCD） | 唯一调试通道，不占 43/44 业务 UART |
| SDMMC | 不使用 | 无 SD 卡 | EWF 无 SD 卡；不初始化 SDMMC |
| BLE / Wi‑Fi | 硬件能力 | 不配置为产品通道 | 仅 ESP32-S3 自带能力保留（AD-14） |

### 1.5 电源/USB 落图合同（派生自硬件基线）

- 单 USB-C（J1）的 VBUS 进入 BQ25895，D+/D− 直连 ESP32 USB-Serial-JTAG；CC1/CC2 各 5.1 kΩ Rd 到 GND；BQ D+/D− 按不使用 BC1.2 检测方式处理。
- `BQ25895RTWR`（I²C `0x6A`，LCSC `C80200`）负责 NVDC 充电与 PMID OTG；`TPS3424` 锁存 + `TPS22965DSGR`（LCSC `C122837`）形成 `SYS_MAIN`，M100 VIN 只接该电池轨，**不得从 BQ SYS 供 4G**。
- `TLV62569DBVR`（LCSC `C141836`）为 `SYS_MAIN→3V3` 首版候选；NS4150B 使用从 3V3 分出的滤波 `3V3_AUDIO`，采用 3V3_AUDIO 低噪声供电。
- `IO8` 留作 NC/测试点，不再承载 M100 `GNSS_VCC`；M100 `GNSS_VCC` 留 `NC/TP`，NET_STATUS 不接 ESP32。逐网和推荐外围见 `docs/hardware/电子木鱼-硬件原理图设计基线.md`。

## 2. CO5300 AMOLED（QSPI）

> 与 legbot 同款模组，引脚完全沿用；显示职责由手表 UI 改为木鱼三主页（木鱼/经文/统计 + 下滑设置）。

**数据手册事实**（源文档 §3.1 / §6.2 沿用）：

| 项目 | 值 |
| --- | --- |
| 控制器 | CO5300，AMOLED/OLED |
| 分辨率 | `410 x 502`（工程圆角掩模 110px，非厂商机械 R 角声明） |
| 接口 | QSPI：CS=IO40、SCL(时钟)=IO5、D0=IO6、D1=IO7、D2=IO12、D3=IO42、RST=IO4、EN=IO47 |
| 显示偏移 | `X_GAP=22`、`Y_GAP=0` |
| 像素格式 | RGB565（初始化 `3Ah=55`；`77`=RGB888） |
| QSPI 时钟 | `80 MHz`（legbot 示例上限） |
| LVGL | `CONFIG_LV_COLOR_DEPTH=16`、`CONFIG_LV_COLOR_16_SWAP=y` |
| 亮度 | AMOLED 无 LED 背光；亮度 = OLED 亮度命令（如 `0x51`）+ 偏压电源使能，不是背光 PWM |
| 关键命令 | `FE 00` 页选、`C4 80` SPI/QSPI 设置、`3A 55` RGB565、`2A`/`2B` 行列窗口、`11` Sleep Out、`29` Display On |

**初始化要点**（源文档建议流程，顺序敏感）：拉高 `LCD_EN IO47` → 初始化 QSPI bus → `esp_lcd_new_panel_co5300` → `reset`/`init` → `set_gap(22,0)` → `disp_on_off(true)` → 交给 `esp_lvgl_port` 建 LVGL display。

**亮熄屏 / 整帧时序**：见 [troubleshooting/CO5300-熄亮屏闪屏与整帧时序](../troubleshooting/CO5300-熄亮屏闪屏与整帧时序.md)（闪屏根因 = 复位后 GRAM 未定义即 DISPON；正确次序为 DISPOFF → 整帧 → DISPON）。

**官方组件版本**：`espressif/esp_lcd_co5300 ==1.0.2`（legbot `main/idf_component.yml` 锁档，EWF 沿用）。

**已知坑**：
- **RGB565 + `CONFIG_LV_COLOR_16_SWAP=y` 是颜色正确的关键**，缺一即红蓝互换/花屏（源文档反复强调）。
- 高带宽 QSPI：LVGL buffer 依赖 PSRAM；刷新率/撕裂受优先级影响。
- AMOLED **没有传统背光**，不要用普通背光 PWM 的思维控制亮度。
- 首次上电/复位后 GRAM 未定义即 `Display On` 会闪屏（见上面 troubleshooting 链接）。
- CO5300 首帧与亮度档、FPC 供电时序属「样机/原理图冻结」工程项，未冻结前不得写入承诺性参数。

## 3. CST9217 电容触摸

**数据手册事实**（源文档 §3.2 沿用 + spine 地址）：

| 项目 | 值 |
| --- | --- |
| 控制器 | CST9217，I2C 接口，板级 `SDA IO1 / SCL IO2 / TP_RST IO38 / TP_INT IO39` |
| 地址 | 7-bit `0x5A`（spine 参考；**最终以实板上电扫描为准**） |
| I2C 速率 | 手册约 `50 kHz–400 kHz`；legbot 示例用 `100 kHz` |
| 供电 | 单电源约 `2.8 V–3.6 V` |
| 触摸能力 | 手册标注最多 5 点；当前组件实现是否支持多点需实板确认 |
| 复位 | `RSTn` 低有效 |

**EWF 职责**（PRD FR-E-007 / AD-1）：左右滑三主页、下滑设置、设置控件、完成弹窗；**只有木鱼页电子木鱼点击产生 `device_touch` 正式敲击**，经文页/统计页/设置页触摸不计数；**熄屏首次触摸只唤醒、不计数**。

**官方组件版本**：`waveshare/esp_lcd_touch_cst9217 ==1.0.4`（legbot `main/idf_component.yml` 锁档，EWF 沿用）。配套 `espressif/esp_lcd_touch ==1.2.1`。

**已知坑**：
- **只写数据手册已公开寄存器**；未公开页/寄存器不要猜测，避免把 chip 打进未知状态。
- 坐标方向、`swap_xy`/`mirror_x`/`mirror_y` 与中断极性**按目标模组实测**，不要照抄 legbot 值（EWF 与 legbot 同为 410×502，但需实板复核对齐）。
- 复位时序：先释放 `TP_RST`，等 chip 稳定再初始化；INT 用于唤醒需在 light-sleep 前配置为唤醒源并处理首次触摸只唤醒语义。
- 与 I2C 上其它器件共用总线：轮询频率受控，避免拖慢电量计/音频配置。
- 实际地址与坐标方向在样机/原理图前不得冻结（spine Deferred）。

## 4. 音频：ES8311 I2S + NS4150B PA

### 4.1 ES8311 音频 codec（I2S）

**数据手册事实**（源文档 §5.1 沿用 + spine）：

| 项目 | 值 |
| --- | --- |
| 器件 | ES8311，I2C 配置 + I2S 数据 |
| I2C 配置 | `SDA IO1 / SCL IO2`（共享 I²C）；地址 `0x18`（源文档 Arduino 类；最终以实板扫描为准） |
| I2S | MCLK IO21 / BCLK IO18 / WS IO14 / DO IO13（ESP32→codec）；DI 不接（播放-only） |
| 采样率 | 8 kHz–96 kHz（源文档 ES8311 类覆盖） |
| 位深 | 16/18/20/24/32 bit 支持 |
| 数据通道（legbot 生产语义，EWF 复用 BSP 时沿用） | I2S0 单次创建 `16 kHz / 16 bit / stereo / BOTH TX/RX`，MCLK=`384×fs≈6.144 MHz`；BSP 对上层暴露 mono：播放写左槽、右槽静音 |
| 增益初值（legbot） | PGA `30 dB`、ADC_SCALE `42 dB`（**按 EWF 目标板 RMS/底噪/削顶复核**） |

**EWF 职责**（FR-E-005 / 09-08 附录 §4.3）：ES8311＋NS4150B＋单声道扬声器输出**木鱼音**；默认音量 `50/100`，`0` 等价静音；低速一次有效敲击一声，高速计数全保留、音频按短间隔重触发或合并为可辨识节奏（**不做无控制叠加**）。音频失败**不得阻塞计数/持久化/同步**（AD-12）。

**官方组件版本**：`espressif/esp_codec_dev ==1.5.11`（legbot 锁档，含 ES8311 codec 支持；EWF 沿用）。ES8311 的寄存器/采样率表以芯片数据手册为准，BSP 在 `components/BSP/ES8311` 下二次封装。

首版硬件外围候选（非样机承诺）：PVDD/DVDD 各 100 nF、AVDD/参考端 1 µF、输出耦合 1 µF + 0 Ω；I²C 上拉 4.7 kΩ，I²S 22 pF 仅保留 DNP 料位。完整位号、LCSC 候选与验证标签见 `docs/hardware/电子木鱼-硬件原理图设计基线.md` §6.2.1。

**已知坑**：
- codec 控制走共享 I²C、音频数据走 I2S，**两条总线职责不可混**（源文档特别强调）。
- 增益初值是 legbot 手表调参值，**EWF 必须按木鱼音色/扬声器腔体重测**。
- 充电期间暂停音频（AD-13）；音量设置跨重启保留（NVS）。
- EWF **删除语音/录音业务**：legbot 的 ZTS6216 麦克风链路、WebRTC NS/AGC AFE、离线语音输入均不在 MVP 范围（codec ADC 存在但 MVP 不产品化采集）。

### 4.2 NS4150B 功放（PA_EN = IO48）

**数据手册/职责事实**：NS4150B 是 Class-D 功放使能脚；spine 约束——**静音、暂停或故障时回到禁用**。EWF 只用于木鱼音播放路径；播放结束/暂停必须关断 PA_EN 以省电并避免噪声。

**启动时序**：见 [troubleshooting/NS4150B-点击音启动时序](../troubleshooting/NS4150B-点击音启动时序.md)（PA_EN 启动安定约 150 ms；推荐 enable → delay → PCM → drain → off 顺序，避免点击爆音）。

**官方组件版本**：NS4150B 为纯功放芯片，无独立官方组件；由 BSP `components/BSP/NS4150`（legbot 目录，EWF 沿用）做使能封装。

首版外围候选：VCC 1 µF + 22 µF + 22 µF、BYPASS 1 µF、差分输入各 100 nF/100 kΩ、`PA_EN` 下拉 100 kΩ；这些值来自参考图/典型电路，最终以扬声器腔体和温升实测为准。

**已知坑**：
- PA_EN 不能与 PCM 数据同时硬切换，否则咔哒/爆音（见 troubleshooting 链接）。
- 音量 0 等价静音：建议同时关 PA_EN 而不是只把音量写 0。
- 调试/暂停/故障路径都回到禁用态（spine 约束），不要只依赖播放结束回调。

## 5. CW2015 电量计

**数据手册事实**（源文档 §5.2 沿用 + spine）：I2C 接口，`SDA IO1 / SCL IO2`，参考地址约 `0x62`；legbot 示例未覆盖，需自写 BSP。

**EWF 职责**（FR-E-009 / AD-13）：电量显示（顶部状态栏电量/充电）、低电量状态表达、低电时**先保证累计计数落盘**再执行其他（不主动断网）；充电期间暂停输入/音频但允许显示充电、电量与同步状态。

**官方组件版本**：无官方独立组件；legbot BSP `components/BSP/CW2015` 为自封装驱动，EWF 沿用并在共享 I²C 单总线仲裁下访问。

**已知坑**：
- **实际地址与电芯曲线须上电核验**（09-08 附录 §3：地址和电芯曲线需上电核验后才冻结），不能把约 `0x62` 写死为承诺。
- 与触摸/音频/IMU 共总线：轮询不要太频繁，避免抢占总线。
- 低电量关机保护阈值与「先落盘再断电」语义由固件电源 story 定，本文件不承诺具体 mV/SOC 档位。

## 6. QMI8658A 六轴 IMU（上板但默认不启用）

**数据手册事实**（源文档 §5.3 沿用 + spine）：I2C `SDA IO1 / SCL IO2`，地址 `0x6A/0x6B`（SA0）；中断 **INT1=IO41**。**INT2 不接、不占 GPIO45**（删除 legbot INT2→IO45 合同）。

**EWF 职责**：上板但**默认不启用，不参与 MVP 主计数**，仅作为未来 WoM（抬腕/运动唤醒）扩展预留（FR-E-002 / AD-14 非目标表）。legbot 的步数/抬腕亮屏/姿态识别等手表业务 **不迁移**。

**官方组件版本**：legbot BSP `components/BSP/QMI8658A` 自封装（非 managed component），EWF 沿用目录但不启用业务。

**已知坑**：
- **不要把 IO45 配置成 INT2**（spine：GPIO45 影响 VDD_SPI 启动采样；QMI8658A 输出不得在复位采样窗口把 IO0/45/46 推到错误电平）。
- 不初始化 IMU 也意味着不把它当 I²C 扫描失败判据——上板扫描时它应在，但驱动不装入业务路径。
- 若未来启用 WoM：INT1 作 light-sleep 唤醒源，先亮屏再走 `device_touch`/`physical_pvdf` 队列语义（不得新增第二条计数路径）。

## 7. PVDF 实体敲击（EWF 新增输入）

> **legbot 无此外设，EWF 新增项**（源文档 IO11=振动马达、IO9=GPS_RX，EWF 已改用途）。以下事实全部来自 spine / 09-08 附录 / PRD FR-E-002/003，本文件只锁板级锚点；**详细实现归固件 story E2.5**。

**板级事实**：

| 信号 | GPIO | 说明 |
| --- | ---: | --- |
| PVDF ADC 二次确认 | IO9 | ADC1_CH8；**前端必须限流、钳位并控制输入范围** |
| PVDF 比较器输出（唤醒） | IO11 | 低功耗 GPIO 唤醒；醒后由 ADC 判断有效敲击 |

**角色与语义**：
- PVDF 压电薄膜是 **MVP 唯一实体主传感器**（09-08 附录 §3）；事件来源固定命名 `physical_pvdf`。
- 比较器负责低功耗唤醒，ADC 波形负责**二次确认**——只有两者结合才生成一次有效敲击候选。
- 熄屏时实体有效敲击**直接计数并触发短暂亮屏**（09-08 附录 §4.2）。
- 一次有效敲击推进下一个「可消费」汉字；1 秒 1–20 次输入不丢字不重字（FR-E-003）；充电中、完成遮罩中、故障锁定中直接忽略输入（AD-1）。
- 与亮屏木鱼页 `device_touch` 进入**同一个**有效敲击队列，共享累计/经文/音频/RGB/持久化/同步语义；**无第二计数路径**。

**验收锚点**（FR-E-002）：目标外壳与安装结构下，单次与连续敲击稳定生成候选信号；携带、取放和普通环境振动误触发率以目标外壳演示签收；ADC 输入不越界。

**官方组件版本**：无官方组件；模拟前端（比较器料号、限流/钳位、阈值）属「功能级锁定，料号不提前冻结」工程项（09-08 附录 §10 / spine Deferred）。

**已知坑 / 冻结门禁**：
- **比较器与模拟前端料号、输入范围、阈值均未冻结**，冻结前不得写入承诺性参数。
- 误触发：携带/桌面振动不可大量误触发；比较器唤醒后仍须 ADC 确认才计，避免只靠电平跳变计数。
- IO9 是 ADC1_CH8：配置 ADC 衰减时保证输入不越界（前端钳位职责，不靠软件硬扛）。
- 该输入只产生事件计数，**不保存、不上报原始波形**；单一外壳只做一次传感器/声学标定（spine 原句）。
- 1 秒 20 次稳定性与完成遮罩期间忽略输入是验收硬项（FR-E-003 / spine 工程验证门禁）。

## 8. Air780EGP 4G（引脚与职责）

> **legbot 用 ML307R；EWF 4G = Air780EGP**。AT/HTTPS/退避经验另源 `main_control`（spine AD-14），本文件**只列引脚与职责、不引 ML307R 内容**（不复制其 AT 命令、联网策略或引脚常量）。

**引脚与职责**（spine 板级合同）：

| 信号 | GPIO | 职责 |
| --- | ---: | --- |
| UART TX / RX | IO43 / IO44 | 4G AT 串口；从 `main_control` 协议驱动中抽离板级引脚常量 |
| DTR | IO10 | 模组休眠/唤醒（复用 `main_control` DTR 经验） |
| RST | IO15 | 模组复位 |
| NET_STATUS | 不接 ESP32 | 载板侧可留测试点；不进入 EWF 网络状态判断 |
| GNSS_VCC | NC/TP（无 ESP32 GPIO） | GPS 默认关闭；`IO8` 留作 NC/测试点，不由 ESP32 驱动 |
| IO8 | NC/测试点 | 不配置，不连接 M100 GNSS_VCC |

**职责事实**：
- MVP 唯一产品联网链路 = Air780EGP 4G HTTPS JSON；在活动窗口内上报、回到低功耗，**不维持长连接**（AD-14 / FR-E-008）。
- ESP32-S3 自带 BLE/Wi‑Fi **仅硬件能力保留，固件不配置为产品通道**。
- GPS 保留控制能力但默认关闭；不引入 Air780EGP 独立业务云。
- AT 经单一 UART 入口与单一事务所有权（AD-10）；网络就绪时序、注册/PDP、HTTPS JSON、超时恢复与退避全部复用 `main_control` 已验证设计。

**官方组件版本**：Air780EGP 是合宙模组，无 ESP-IDF managed component；AT 驱动/BSP 从 `main_control` 迁移（不含其原板引脚常量）。

**已知坑**：
- GPIO43/44 是 ESP32-S3 **UART0 默认映射**：调试 console 必须改到 USB-Serial-JTAG，否则与 4G UART 冲突（见 §9）。
- **分轨供电**：Air780EGP 走系统主电源轨（持续 >1A / 瞬时 >2A 能力）；AMS1117 类 LDO 不得承担其主供电；USB VBUS 不得反向给模组/电池非预期供电（spine §电源分轨）。
- 不沿用 legbot ML307R 的「上电至少 10 秒后 UART 可用」等模块专属时序——Air780EGP 上电时序以 `main_control` 为准。
- 发射峰值下电池轨不得掉压重启（spine 工程验证门禁）。

## 9. USB-Serial-JTAG（IO19/20）

**事实**（AD-11 / FR-E-010 / 源文档 §5.6）：ESP32-S3 原生 USB-Serial-JTAG：D−=IO19、D+=IO20，承担 `esptool`/`idf.py flash`、USB CDC 日志与 OpenOCD 调试；**不上 CH340X**、**不在同一 USB PHY 上开发 USB-OTG**。

**EWF 调试通道**：唯一调试通道（spine AD-11）。因此 GPIO43/44 让给 Air780EGP UART；console 输出必须配置到 USB-Serial-JTAG（`CONFIG_ESP_CONSOLE_USB_SERIAL_JTAG` 一类配置），避免占用业务串口。

**已知坑**：
- **USB 连接时禁用自动 light sleep**，防止调试串口失联/随机重启——见 [troubleshooting/ESP32-S3-自动轻睡眠随机重启与USB日志失联](../troubleshooting/ESP32-S3-自动轻睡眠随机重启与USB日志失联.md)。
- 同一 USB 口不启用 USB-OTG 业务（FR-E-010 验收）。
- 上电后 PC 应识别 USB CDC 并完成烧录与日志输出；若固件把 console 指回 UART0，4G 会收乱码（见 §8 坑）。

## 10. 按键与电源：PWR / BOOT / EN

**事实**（FR-E-001 / AD-13 / spine）：

| 信号 | GPIO | 职责 |
| --- | ---: | --- |
| BOOT | IO0 | 启动绑带；保留下载路径（配合 RESET/EN 进入下载） |
| PWR | IO46 | 运行态输入（短按唤醒/循环三页）；固件**只读** |
| RESET | EN | 独立按键/测试点 |

**职责语义**：
- **PWR 长按开关机由板级电源电路负责**，固件**不接管硬件关机**、不模拟第二套软件关机（AD-13 / FR-E-007）；运行态 PWR 短按 = 熄屏唤醒或木鱼→经文→统计循环。
- 充电：USB-C；充电期间暂停实体/触摸输入、经文推进与音频；屏幕仍可显示充电/电量/同步（FR-E-001 / AD-13）。
- GPIO46 是 strapping pin：固件只能配置为**输入**，不能输出驱动或改变下载绑带（源文档语义沿用）。
- 已持久化累计数与轮次重启后恢复（FR-E-001 验收）；固件不得实现 PMIC 关机/Deep-sleep/Restart/仅关屏的「软件关机」路径来替代板级 PWR 硬断。

**已知坑**：
- legbot 运行态 **BOOT0 长按 = 离线语音输入**的职责**删除**（EWF 无离线语音）。
- 不要试图在固件里把 PWR 长按映射成任何软件关机/外骨骼动作（legbot 曾有「PWR 持续按住 → 外骨骼 BLE 关机」逻辑，EWF 不存在）。
- 启动绑带：下载要求 GPIO0=0、GPIO46=0；复位采样窗口内 PWR/QMI8658A 输出不得把 IO0/45/46 推到错误电平（spine 工程验证门禁）。

## 11. RGB 状态灯（IO3）

**事实**（spine 板级合同 / 09-08 附录 §4.3）：RGB DATA = IO3，**用户状态灯，不作为调试灯**；仅表达：敲击确认、待同步、低电量、故障（FR-E-009）。使用克制的颜色与占空比，不与主屏争夺注意力。

**EWF 新增**：legbot IO3 = GPS WAKE_UP；GPS 业务删除后改作 RGB 数据脚。

**已知坑**：RGB 不是调试指示灯；调试日志/状态不要优先占用它表达内部状态，须与「用户可辨识状态」一致。
