# 显力科技嵌入式 C Agent 工作规则

本文件用于指导 Agent 修改显力科技自研嵌入式 C/H、BSP/HAL、驱动、协议、启动代码、测试和固件构建配置。目标是交付最小、安全、可评审、证据真实的改动。

本文件可独立执行，不要求运行时读取员工版。只有将本文件复制或合并到目标项目的 `AGENTS.md`、`CLAUDE.md`，配置为规则文件，或由 Agent 显式读取后才会生效。

## 工作边界

- 遵守法律、合同、认证、公司规范、项目规则和作用域更近的模块规则；下级规则可以加强，不得擅自放宽强制要求。
- 只修改用户授权的范围。保留已有未提交内容，不为格式顺手重构，不清理非本任务问题。
- 未经明确授权，不创建或切换分支，不提交、推送、打标签、烧录、部署、发布或操作生产系统。
- 缺少芯片、板卡、工具链、SDK/RTOS 版本、硬件所有者或项目补充规范时，先查项目真源；仍无法确定且会影响行为时停止并报告。
- 不得自行批准规则例外。例外必须记录规则、精确条款、范围、风险、替代控制、证据、批准人和期限。
- 法律、人身安全、生产秘密、签名根、认证/授权、反回滚和证据真实性不得事后追认。

## 修改前检查

- 读取目标目录及父目录中的 Agent/项目规则。
- 记录当前分支、基准 SHA 和工作区已有修改。
- 找到公开头、实现、测试、构建清单、生成真源、项目补充规范和硬件资源表。
- 确认改动属于应用、服务、驱动、HAL/BSP 中哪一层，以及硬件和资源由谁所有。
- 识别 API/ABI、协议、持久化、并发、ISR、DMA/cache、电源、安全和发布影响。
- 把需求写成可验证行为；缺陷优先建立复现或回归测试。

## 不可妥协的红线

- 不输出、复制或提交密码、Token、私钥、生产凭据和敏感个人数据；发现时只报告位置、类型和风险，并要求轮换。
- 不把编译、Host、mock、fake clock 或自报日志写成目标板、HIL 或物理测量通过。
- ISR 和硬实时路径不阻塞、不分配释放内存、不做慢 I/O 或普通日志，不调用未证明 ISR-safe 的 API。
- `volatile` 不替代原子、锁、队列、临界区、内存屏障或 cache 一致性操作。
- 不绕过 BSP/HAL 和资源表争用 GPIO、总线、DMA、时钟、外设和电源域。
- 不忽略可失败调用，不让半初始化对象伪报成功；释放失败不得清空仍拥有的句柄。
- 不依赖有符号溢出、结构体/位域线格式、本机端序、未对齐强转、未定义行为或无界字符串操作。
- 不凭记忆生成芯片、SDK、RTOS、寄存器、Kconfig 或能力宏；只使用精确版本官方证据。
- 不手改生成物，不重排第三方代码，不引入来源、许可证或漏洞状态不明的依赖。
- 不改写共享 Git 历史，不执行会丢失工作区内容的操作。

## Windows PowerShell 编码规则

公司自有文本默认使用 UTF-8 无 BOM、LF 和文件末尾单个换行。看到 `纭`、`锛`、`涓`、`寮€`、`�` 等可疑字符时立即停止，显式按 UTF-8 重读；禁止把污染文本写入代码、文档、提交信息和生成物。

Windows PowerShell 5.1 在读取、写入、管道或运行可能输出中文的命令前，先执行：

```powershell
$Utf8NoBom = New-Object System.Text.UTF8Encoding -ArgumentList $false
[Console]::InputEncoding = $Utf8NoBom
[Console]::OutputEncoding = $Utf8NoBom
$OutputEncoding = $Utf8NoBom
```

搜索优先使用 `rg` 和 `rg --files`。必须使用 PowerShell 读取时：

```powershell
Get-Content -LiteralPath "path\to\file.md" -Encoding UTF8 -Raw
[System.IO.File]::ReadAllText(
    (Resolve-Path -LiteralPath $Path).Path,
    [System.Text.Encoding]::UTF8
)
```

修改受控文件优先使用补丁。禁止依赖 PowerShell 5.1 默认的 `Set-Content`、`Out-File`、`>` 和 `>>`；必须写入时：

```powershell
$Utf8NoBom = New-Object System.Text.UTF8Encoding -ArgumentList $false
[System.IO.File]::WriteAllText($Path, $Text, $Utf8NoBom)
[System.IO.File]::AppendAllText($Path, $Text, $Utf8NoBom)
```

必须经 `cmd.exe` 处理中文时使用：

```powershell
cmd /d /c "chcp 65001>nul & your-command"
```

未经授权不得修改员工的全局终端、系统区域或 Git 编码配置。

## C/H 编码规则

这些规则适用于公司自有 `.c/.h`，不用于机械重排第三方代码和生成物。
应用格式和文档规则时，不得改变既有函数签名、公开结构、硬件资源取值和运行时行为；行为变化必须来自任务需求并接受相应验证。

### C 语言与工具链

- 默认使用 ISO C17。锁定编译器、链接器、构建工具、SDK、RTOS、芯片、板卡、ABI、字节序和关键编译选项；不得使用 `latest`、`stable` 作为发布工具链事实。
- GNU、编译器、SDK 和芯片扩展必须隔离在 BSP、HAL 或小型平台适配器，并注明精确版本和原因。
- 新增或修改平台符号前，依次查目标版本官方文档、同版本头文件、必要实现或勘误、能力宏、配置条件、组件依赖和调用上下文。
- 无参数函数写成 `function(void)`。头文件不得定义外部可写对象；`extern` 只能声明，并在一个 `.c` 中提供唯一实现。
- 函数式宏不得重复求值或隐藏控制流、锁和所有权；优先使用 `static inline`。非法配置必须编译期失败，禁用代码不得长期保存在 `#if 0` 中。

### 文件头

每个公司自有 `.c/.h` 必须以下列 Doxygen 文件头开始，文件名、职责和日期必须准确：

```c
/**
 * @file     file_name.c
 * @brief    一句话说明文件职责
 * @details  说明模块边界、状态、资源或硬件所有权。
 * @author   显力科技
 * @date     YYYY-MM-DD
 */
```

`@date` 记录首次创建日期，修改历史由 Git 保存。

### `.c` 文件布局

按以下顺序组织：

1. 文件头；
2. 对应的自身头文件；
3. 标准库头文件；
4. SDK、RTOS 和第三方头文件；
5. 公司和项目头文件；
6. 日志 TAG；
7. 宏、常量、私有类型和模块变量；
8. `static` 内部函数声明；
9. 公开函数实现；
10. `static` 内部函数实现。

include 分组之间空一行。所有内部函数必须为 `static`，并在文件顶部的内部函数声明区声明；默认在公开函数之后实现。

### `.h` 文件布局

按以下顺序组织：

1. 文件头；
2. 头文件保护宏；
3. 标准库、SDK/第三方和项目 include；
4. 可选 `extern "C"` 包裹；
5. 业务宏和编译期常量；
6. 类型定义；
7. 公开函数声明；
8. 关闭 `extern "C"` 和保护宏。

公开头必须可以单独 include 编译。保护宏使用全局唯一的 `XLKJ_<PRODUCT_OR_PATH>_<MODULE>_H`；可能供 C++ 调用的公开 C 头必须添加 `extern "C"`。

### 排版与命名

- 使用 4 空格，禁止 Tab；使用 Allman 花括号；控制语句始终加花括号；每行一个语句；120 列为软上限。只格式化本次修改的最小范围。
- 目录、C/H 文件、局部变量、参数和结构字段使用 `snake_case`。
- 公开函数使用 `module_verb_object()`；谓词使用 `is_/has_/can_/should_`；ISR-safe、已持锁、回调和任务入口分别使用 `_isr/_from_isr`、`_locked`、`_callback`、`_task`。
- typedef 使用 `snake_case_t`；回调和句柄类型分别以 `_callback_t`、`_handle_t` 结尾。
- 宏、枚举值和公开编译期常量使用带模块前缀的 `UPPER_SNAKE_CASE`。
- 模块级 `static` 对象使用 `s_` 前缀，日志框架固定 `TAG` 除外。原则上禁止跨模块可写 `extern` 全局变量。
- 名称必须表达单位和边界，使用 `_ms/_us/_ticks/_hz/_bytes/_capacity/_count/_index/_handle/_cb` 等后缀；布尔量使用正向语义。

### 注释、Doxygen 与日志

- 注释使用中文，解释原因、约束、所有权、并发、硬件依据和错误恢复，不逐行复述代码。
- 每个公开函数必须有中文 Doxygen，并按需说明 NULL、范围、单位、所有权、阻塞/超时、线程/ISR 上下文、幂等性和错误。
- 每个业务宏、枚举值、结构字段、模块常量和模块变量必须有简洁中文说明。
- 产品运行日志的描述文本使用中文；芯片、协议、寄存器、函数、宏和稳定错误码可以保留英文。
- 每个使用日志的 `.c` 文件定义稳定、简短、ASCII 的本地 TAG，例如 `static const char *TAG = "MODULE_NAME";`；不使用日志的文件不得定义无用 TAG。
- 日志必须按级别使用并限频，禁止输出密码、Token、私钥、认证头、密钥材料和个人敏感数据；ISR 不使用普通日志。

### 函数、API 与错误处理

- 函数只承担一个清晰职责；公开 API 保持最小，不得为测试方便扩大接口。
- 输入指针使用 `const`；输出和输入输出参数使用 `_out/_inout`。指针合同说明 NULL、容量、对齐、生命周期、所有权和调用上下文。
- 在信任边界校验 NULL、长度、容量、索引、枚举、值域、状态、权限和上下文。不得比较无关对象指针或通过试探解引用验证地址；使用平台批准的地址分类机制。
- 操作 API 返回项目统一状态或平台错误。每个可失败调用必须选择传播、转换、重试、降级或终止；只有合同允许且确实无害时才能用 `(void)` 忽略返回值。
- `init/start/stop/deinit` 必须说明幂等性。初始化失败反序释放本次资源；释放失败保留句柄、所有权和诊断状态，不得伪报 deinit 成功。
- 断言只验证程序员不变量，不用于处理外部输入、资源不足、通信、用户操作和可恢复硬件故障。
- 禁止 VLA；递归默认禁止；`goto` 只允许跳向同一函数的单一清理出口；外部枚举 `switch` 必须安全处理未知值。

### 整数、指针、数组和字符串

- 协议、寄存器、存储格式和跨平台接口使用 `stdint.h` 定宽类型；大小和容量使用 `size_t`。
- 窄化、符号混合、加乘、移位和回绕必须先证明范围。禁止有符号溢出、除零、负移位、超位宽移位和用强转压制真实告警。
- 禁止读取未初始化对象、use-after-scope/use-after-free、解引用 one-past 指针、未定序修改、错误有效类型和未同步数据竞争。
- 线格式逐字段处理端序；不得把字节数组强转为协议结构，也不得直接序列化结构体或用位域映射协议/寄存器。
- 数组和字符串接口必须携带容量。禁止无界写；检查 `snprintf` 的负值和截断；重叠复制使用 `memmove`，二进制数据不得使用字符串函数。

## 内存、并发与 ISR 规则

- 动态内存必须有大小上限、溢出检查、所有者、失败/释放路径和碎片评估；ISR/硬实时禁止，高频路径优先池化或预分配。
- 分配和释放 API 必须匹配；`realloc` 使用临时指针。共享或引用计数模型必须定义计数同步、关闭条件和最后释放者。
- 禁止未经评估的大栈对象；记录任务栈高水位、最重错误路径和 WCET。生产构建保留栈溢出检测或等效可观测机制。
- 敏感数据使用项目验证的 secure-zero API；持久化数据校验版本、长度、完整性、掉电原子性、迁移和 Flash 寿命。
- 优先使用“单 owner 任务 + 消息”。共享对象必须记录同步原语、锁顺序、调用上下文、生命周期和关闭合同。
- 持锁时不得执行未知时长 I/O、回调或等待另一任务。队列满策略必须明确，关键终态不得静默丢失。
- 业务事务和资源竞争使用单调时钟、回绕安全比较、有界重试和总 deadline。系统同寿命 owner 可以无限等待，但必须有明确唤醒源、诊断和停止/不可停止合同。
- 原子发布必须明确 acquire/release 等内存序。ISR 中使用原子前必须证明该类型始终 lock-free，否则使用平台 ISR-safe 原语。
- ISR 只捕获最小状态、清除中断源、使用 ISR-safe API 通知任务并按平台要求 yield。浮点只有在 FPU 上下文、常驻内存和 WCET 均有证据时才可由项目批准。

## 硬件、电源与安全规则

- 依赖方向保持“应用 → 服务 → 驱动 → HAL/BSP → SDK/硬件”。资源必须有单一配置真源和生命周期所有者。
- 寄存器保留位、W1C/读清/自清、访问顺序、屏障和延时必须有目标版本手册依据；忙等只用于必要短窗口。
- 项目必须定义 cache line、内存域、DMA descriptor/payload、clean/invalidate、屏障和所有权转移；不得 invalidate 覆盖 CPU 脏数据，释放前确认 DMA 和 ISR 不再引用。
- 定义启动、运行、睡眠、唤醒、掉电和故障安全状态；不得用复位、深睡、关屏或死循环伪装硬件关机。
- 所有外部输入默认不可信；不得自创加密、认证协议或随机数。认证、授权和签名失败时默认拒绝。
- 生产安全功能必须定义安全启动、签名链、密钥注入/轮换/吊销、调试口、反回滚、SBOM、漏洞响应和 recovery；不可逆操作必须双人复核。
- 只修改生成代码的真源或生成器。第三方补丁记录上游版本、来源、许可证、漏洞和负责人。

## 验证规则

| 改动类型 | 最低验证 |
| --- | --- |
| 算法或 API | 单元/Host、边界、错误路径、调用方构建和兼容检查 |
| 协议或持久化 | 长度、整数、端序、损坏/截断/未知版本、掉电和迁移 |
| 内存或并发 | 分配失败、泄漏/峰值、锁序、队列满、取消、栈和长稳 |
| ISR 或 DMA | ISR-safe、lock-free/WCET、cache/屏障、事件风暴和目标板 |
| 驱动或电源 | 精确版本证据、异常总线、完整状态转换、目标板和仪器 |
| 安全或依赖 | 负向权限、秘密扫描、失败关闭、签名/反回滚和 SBOM |
| 工具链或发布 | 干净构建、告警、硬件矩阵、同一制品哈希和恢复方案 |

必须准确区分编译/链接、Host 测试、目标设备执行、HIL 和物理测量。不得虚构统一覆盖率；项目门槛之外，安全状态、认证失败、清理、边界、超时和关键并发交错仍须明确验证。

## Git 与发布规则

- 项目定义受保护分支、起点、命名和 merge/squash/rebase；禁止直接推送受保护分支。长期分支提升不得使用破坏祖先关系的 squash。
- 提交使用 `type(scope): 中文摘要`，一个提交一个意图；PR 写明目标、风险、兼容、已执行和未执行验证。
- PR 至少一名非作者批准。涉及安全启动/更新、危险执行器、电源、Bootloader、协议/存储或板级资源时，必须增加对应领域 Owner。
- 禁止改写共享历史；个人分支只有协调后才能使用 `--force-with-lease`。热修按项目规则回流所有受支持开发线。
- 发布 tag 只能指向已验收提交且不得移动；归档 Git SHA、工具链、配置、硬件矩阵、制品 SHA-256、批准记录和回滚或前向恢复方案。
- 必须直接提升同一已验收二进制制品，不得重新构建替代归档制品。

## 完成与报告

完成前确认：diff 只包含需求范围；没有未处理错误、资源泄漏、并发/ISR/DMA/cache 或硬件所有权违规；没有秘密、生成物误改和新增告警；项目规则、资源表和验证证据已同步。

最终报告必须包含：完成内容和影响范围；实际执行的验证及结果；未执行项及原因；剩余风险、例外和后续动作。不得把未执行的检查写成已通过。

修改本文件的规则语义时，必须在同一变更中同步更新 `显力科技嵌入式C代码编写规范-员工版.md`；已知冲突时停止采用较宽松解释并报告。
EWF 说明：本规范为 Embedded/ 固件 C 编码强制基线，详见根 AGENTS.md §设备侧强制规则
