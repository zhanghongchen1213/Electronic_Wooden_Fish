# NS4150B 点击音启动时序：短音无声的根因与生产方案

## 1. 适用范围与结论

- 目标硬件：ESP32-S3 + ES8311 + NS4150B + 扬声器，与 legbot_watch 同款音频链路，本文结论直接适用。
- 固件基线：ESP-IDF ≥5.5.4,<5.6.0，复用 legbot 的 BSP/managed_components 与音频资源基线（见 ARCHITECTURE-SPINE §结构 seed）。
- 故障对象：时长远短于功放启动时间的短反馈音——EWF 中即每次有效敲击（PVDF 实体敲击或亮屏电子木鱼点击 `device_touch`）产生的木鱼音。
- 结论溯源：本结论 2026-07-28 在 legbot_watch 目标板真机验证（修复后短音清晰可闻、连续触发正常），EWF 因芯片同款沿用。
- EWF PA 合同：NS4150B `PA_EN`(IO48) 在静音/暂停/故障时回到禁用；凡从这些状态恢复并播放短音，都经过同样的冷启动窗口。

本文区分数字音频链路与模拟功放链路：**不得仅凭“I2S 写入成功”判断扬声器已经发声**。高速连击的音频合并/限速策略见 PRD FR-E-005，不在本文展开。

## 2. 故障现象

短音播放路径全部“成功”但扬声器无声：

- 有效输入被确认，音频服务收到反馈请求；
- 资源（WAV）成功读取并写入 I2S；
- DMA 静音尾成功排空；
- 日志打印“播放完成”。

但扬声器完全无声；同一块板播放较长音频（测试音/自检音）正常。

结论：**“服务调用成功”与“数字数据已提交”都不能证明模拟功放已进入可输出状态。**

## 3. 根因

### 3.1 直接根因

NS4150B 从 `CTRL=低` 的 shutdown 态切换到 `CTRL=高` 的 enable 态，数据手册典型启动时间 `Tst` 为 **120 ms**。

故障版本每次播放前都完整关闭再开启功放，但只等待 30 ms。短音 WAV 仅约 70 ms，有效 PCM 在功放真正进入工作态之前就已播完：

| 时间点 | 故障版本动作 |
| --- | --- |
| t=0 | `PA_EN` 拉高，NS4150B 从 shutdown 启动 |
| t=0~30 ms | 软件等待 |
| t=30~100 ms | 70 ms 短音 PCM 写入/输出 |
| t≈120 ms | NS4150B 典型进入可输出状态 |
| 其后约 48 ms | I2S 仅输出 DMA 静音尾 |
| 播放结束 | `PA_EN` 再次拉低 |

日志中的资源读取、I2S 写入、DMA 排空全部成功，但功放就绪后收到的只剩静音。

### 3.2 为什么长音正常

长音（约 1.2 s）与短音共用 ES8311/I2S/NS4150B 路径；即使前约 120 ms 被功放启动过程吞掉，后续仍有超过 1 秒的有效音频，因此听感“正常”。

这是本故障最具迷惑性的地方：**长音可闻不能证明同一冷启动时序适用于约 70 ms 的短音。**

### 3.3 已排除项

- 输入/音量/持久化设置未生效，或短音被低电策略误丢弃；
- WAV 路径、RIFF chunk 或 `data_offset` 解析错误；
- 采样率、声道、位宽或 I2S slot 不一致；
- 资源静音、削波、直流偏置或幅度过低；
- codec 未恢复音量或保持 mute；
- DMA 尾部未排空导致末段被立即截断。

## 4. 最终生产方案

### 4.1 NS4150B 启动合同

常量定义于 `Embedded/components/BSP/NS4150/ns4150_bsp.h`：

```c
#define NS4150_BSP_STARTUP_SETTLE_MS 150U
```

150 ms 由数据手册典型值 120 ms 加 30 ms 裕量组成。音频服务含编译期断言，禁止把该等待回退到 120 ms 以下。

固定资源的关键顺序必须保持：

```text
ES8311/I2S start
  → NS4150B enable
  → 等待 150 ms
  → 写入有效 PCM
  → 写入一整圈 DMA 静音并排空
  → NS4150B safe off
  → ES8311/I2S stop
```

不得把 150 ms 前导静音直接写进 WAV 来掩盖硬件时序——启动等待属于 NS4150B BSP 合同，资源只表达声音内容。

### 4.2 为什么无需额外预写静音

`es8311_bsp_start()` 会先启用 I2S；ESP-IDF 的 I2S DMA 缓冲区以零初始化，音频基线还设置了 `auto_clear_after_cb=true`。因此 150 ms 等待期间输出线路保持静音，无需额外引入预写循环。

有效 PCM 播完后仍保留一整圈 DMA 零采样排空，保证最后一个有效采样已物理送出，再关闭功放与 codec。

## 5. 快速排障流程

1. 同一开机周期先播长音。
2. 若长音可闻、短音无声，**先测量或核对 `PA_EN` 到首个有效 PCM 的时间**，不要先改资源幅度。
3. 确认 `NS4150_BSP_STARTUP_SETTLE_MS >= 120`，生产值应为 150 ms。
4. 临时把长音映射到短音资源播放；若可闻，则设置、资源 ID、解析、I2S slot 与模拟线路均已基本排除。
5. 仍不确定时用示波器同时观察 `IO48/PA_EN`、ES8311 差分输出和扬声器端，量 `PA_EN` 上升到扬声器首次有效波形的延迟。

## 6. 不要使用的“修复”

- 不要仅提高 WAV 峰值或改成方波；
- 不要把 I2S 写入成功当作扬声器发声证据；
- 不要把硬件启动延时藏进资源文件；
- 不要删除 DMA 静音排空。

## 7. 回归验收要点

- 自动化：NS4150B 等待不低于 120 ms；播放顺序 `enable → delay → PCM → DMA drain → safe off`；短音资源格式、时长、非静音、无削波校验。
- 真机：冷态首次触发短音可闻；连续/快速触发无截断、爆音；音频失败不阻塞计数、持久化与同步（FR-E-005）。
