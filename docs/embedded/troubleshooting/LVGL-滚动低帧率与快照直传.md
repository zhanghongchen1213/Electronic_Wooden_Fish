# LVGL 滚动低帧率与快照直传

> 本文迁移自 legbot_watch（只读蓝本），是设备侧「CO5300 AMOLED 大面积滚动性能」的单一事实来源与防回归合同。真机数字均为 legbot 目标板（同 410×502 CO5300 / 80 MHz QSPI）实测；**EWF 落地未在自有板卡复测前，任何数字都只是蓝本证据，须以本仓目标板实测为准**（口径见 §2、§7）。
>
> 体系/命名适配：legbot 的 `watch-lvgl` 体系 ↔ 本仓 `ewf-device-ui` 体系（`lvgl-design/ewf-device-ui.pen/.html`、`squareline_studio/ewf-device.spj`）；固件路径 `components/...` → `Embedded/components/...`。涉及 BLE、GPS、4G、云、外骨骼、支付等 watch 专属字句已删除或改写为「本仓不适用」，只保留跨产品成立的渲染架构结论。

## 1. 适用范围

本文覆盖设备端会**连续产生完整显示帧**的运动路径，EWF 场景下为：

1. 常驻主壳左右横滑（`screen_shell` 内 MUYU/JINGWEN/TONGJI 三页跟手滑动与首尾循环）。
2. 设置类多栏纵滑（SHEZHI / `screen_settings`，含亮度档位、熄屏时间、音量、立即同步等设置行）。
3. 其他未来出现的大面积连续滚动页——一律先套用 §8 的分类决策树与本合同。

静态或离散更新页（设备信息、完成遮罩、状态栏变体等）不应常驻分配整屏快照，但必须关闭无意义的整页滚动、重复圆角裁剪和无变化投影。

大面积的连续运动由**快照直传**替换显示渲染路径；触摸命中、页面路由和滚动结束后的实时对象树仍由原 LVGL 逻辑负责。本仓不适用：自检结果页/自检进度页、附近外骨骼、BLE 候选页、维护页、支付页及其并发服务栈——它们不进入本文滚动链，仅作为「同类问题可能复发」的背景提醒。

## 2. 验收口径

帧率不能用动画回调次数或 `lv_timer_handler()` 调用次数代替：一帧从 LVGL 一轮刷新的**最后一块颜色 DMA 实际完成时刻**记录，多次手势拼接为连续有效运动时间轴。

正式固件每累计 60 秒有效滚动输出一次汇总，须同时满足：

- 每个 1 秒滚动窗口至少 60 个完整显示帧。
- P99 帧间隔 ≤ 20 ms；最大帧间隔 ≤ 33.3 ms。
- 起滑快路切换 ≤ 100 ms。
- 运动期间周期**快路缺失 = 0**；只要出现一次快路不可用，本周期即判定失败。
- 无花屏、错色、明显撕裂、触摸丢失、按钮误提交、WDT 或 SPI 超时。

静态页没有「稳定 60 FPS」的物理含义。其等价验收是：页面根不可滚动、切屏无整屏动画、无变化模型刷新不产生新脏区、局部交互不触发全量模型投影，且从输入到完整 DMA 显示完成 ≤ 100 ms。**不得为了让静态页输出 FPS 而添加空动画或持续刷新。**

## 3. 根本原因

### 3.1 物理带宽：60 FPS 必须 80 MHz QSPI

屏幕 410×502、RGB565，一帧 `410 × 502 × 2 = 411,640 字节`；60 FPS 仅像素就需要约 24.7 MB/s。四线 QSPI 每时钟传 4 bit，理论字节带宽 = SPI 时钟 ÷ 2：

- 20 MHz ≈ 10 MB/s、40 MHz ≈ 20 MB/s：物理上达不到 60 FPS。
- 80 MHz ≈ 40 MB/s：才给命令、窗口设置、DMA 间隙和软件合成留出余量。

因此 60 FPS 架构要求 CO5300 工作在目标板实测稳定的 **80 MHz QSPI**；降到 40/20 MHz 不是同一性能目标下的合格降级方案。CO5300 规格资料标称上限 50 MHz——80 MHz 是性能配置而非无风险量产结论；量产前必须完成信号完整性、温度与长期稳定性复测；若最终必须降至规格范围，应重新评估帧率目标或显示架构。

### 3.2 真凶是 LVGL 每帧重复渲染复杂对象树

设置类纵滑时大视口持续失效，内容含多个圆角容器、文字、图标、分段/行控件与裁剪关系。LVGL 以 16 行内部 DMA 双缓冲分块工作，每块不仅要传输，还要重新执行对象遍历、圆角遮罩、文字混合与裁剪。

legbot 蓝本目标板（80 MHz QSPI、后台服务并发）实测优化前基线：

| 指标 | 设置多栏纵滑优化前（蓝本实测） |
|---|---:|
| 有效运动时间 | 10.052 s |
| 完整帧 | 94 |
| 平均 FPS | 9.350 |
| 最低 1 秒窗口 | 10 帧 |
| P99 / 最大帧间隔 | 100.0 / 110.0 ms |
| `lv_timer_handler` 平均 / 最大耗时 | 98,838 / 101,579 µs |
| 完整帧 flush 平均 / 最大耗时 | 95,688 / 98,267 µs |
| 平均传输像素 | 约 140,430 像素/帧 |

80 MHz QSPI 传约 14 万 RGB565 像素只需数毫秒，实测一帧却接近 100 ms——**瓶颈是滚动时的软件重绘**，不是继续调刷新周期或 SPI 时钟能解决的。

### 3.3 运动期间的无效投影会放大抖动

滚动期间若继续应用普通模型投影（本仓如同步状态、充电、校时等无关字段），会重复设置相同标签/颜色/样式并扩大脏区；滚动条每帧 `lv_obj_set_y()` 也额外产生一块移动失效区。

这些操作不是个位数 FPS 的唯一根因，但会放大帧间隔抖动。**运动期间只保留熄屏、停止、显示恢复等高优先级请求；普通模型刷新合并为最新快照，滚动结束后立即应用。**

### 3.4 快照失效存在并发竞态（第一版设置快路实测未过）

蓝本第一版设置快路在 10 秒自动诊断中达 62 FPS，但正式 60 秒并发实测未通过：平均 11.274 FPS、最低 1 秒窗口 5 帧、P99 100 ms、最大帧间隔 635.4 ms、快路未就绪 328 次。

根因不是快帧合成器变慢，而是把**每次运行时模型刷新都当成画面变化**：无关刷新无条件废弃背景与内容快照；连续手势之间无法重新生成两张快照时，下一次纵滑就回退到约 100 ms/帧的 LVGL 慢路。自动诊断没有在两次手势之间持续注入这些无关刷新，因此漏掉了这一真实并发时序。

## 4. 解决方案

### 4.1 公共显示底座

- CO5300 固定 80 MHz QSPI；LVGL 刷新周期 8 ms，触摸采样 10 ms。
- 两块 16 行内部 DMA 缓冲。
- `ui_task` 独占显示事务，固定 Core 1；业务实时任务栈显式放 PSRAM 时遵循「不经 cache-off 外部栈」规则（见 §4.4）。
- 快路按 16 行分块，将「下一块 PSRAM 合成」与「上一块 QSPI DMA 传输」流水化。
- CO5300 使用**项目专用有界 QSPI panel IO**：每笔 CASET/RASET/RAMWR 都在 100 ms 内完成排队或结果回收，不依赖逐块固定延时，也不进入官方 SPI LCD IO 内部的 `portMAX_DELAY`（详见 §9 踩坑 4）。

### 4.2 常驻主壳横滑快照直传

在 PSRAM 保留「当前页 + 左相邻页 + 右相邻页」的 410×502 RGB565 快照（三主页 MUYU/JINGWEN/TONGJI 恰好 3 张）。空闲时每轮最多预热一页；起滑后**暂停 LVGL 失效绘制**，直接按 pager 实时横向偏移拼接相邻两张快照并整屏直传。

- 主壳只保留最外层 110 px 屏幕圆角裁剪（具体半径以本仓 `ewf-device-ui.html` 屏块为准），移除 pager、页容器、页根的重复软件圆角遮罩。
- 翻页有效行程调短（蓝本为 8 px），三页首尾循环不变。
- 松手或异常后恢复 LVGL invalidation、恢复实时对象树并请求一次整屏重绘。

蓝本 10 秒自诊断：平均 61.632 FPS、最低 1 秒窗口 62 帧、P99/最大 16.7/17.1 ms、渲染平均 16,096 µs、flush 平均 15,282 µs。该数据只证明方案可行，正式门禁仍以累计 60 秒有效运动为准（§7）。

### 4.3 设置类多栏纵滑：视觉签名 + 前后台双内容快照

**视觉签名决定快照何时失效**：只把真正影响该页画面像素的字段纳入规范化签名。蓝本设置页为「触觉开关、点击音开关、亮度档位、熄屏时间档位」四个字段；本仓 SHEZHI 应对应为「亮度档位、熄屏时间档位、音量、立即同步的同步状态反馈（SYNC_BUSY/OK/…）」。与画面无关的后台字段变化**不改变视觉代次，也不废弃任何快照**。

按需分配三块 PSRAM RGB565 快照：

- 410×502 静态背景（标题、分割线、底部返回区、轨道、屏幕圆角），生成时临时隐藏列表视口与滚动条。
- 两块连续内容快照（前后台双缓冲，EWF 尺寸按实际内容区高度换算；蓝本 378×608 每块 459,648 字节，合计 1,330,936 字节，离页全部释放）。

流程：

1. 首次进入设置页先生成生命周期内只读的背景与首张完整内容快照，再开放纵滑。
2. 只有视觉签名变化时向**非前台**内容缓冲生成最新画面，成功后原子切换前台索引；生成中/失败时快路继续读上一张完整快照，**绝不读半成品，也不回退慢路**。
3. 连续到达的模型刷新由 UI 服务合并为最新模型，内容代次最终追上最新视觉目标。
4. 纵滑开始后保留原列表对象树收触摸、暂停 LVGL 失效绘制；每行直接从背景/内容缓冲拷贝最终像素，禁止「先拷整幅背景、再覆盖内容」的冗余 PSRAM 读取。
5. 列表关闭 LVGL 弹性越界，内容在真实范围内**硬钳位**；边界外不产生位移或回弹动画。
6. 滚动结束后恢复 LVGL 绘制、同步滚动条、请求一次整屏重绘，并应用运动期间合并的最新模型。

蓝本去除冗余背景拷贝后 10 秒自诊断 62.266 FPS、快路未就绪 0 次；**该数据只证明合成器达标，不代表真实并发验收通过**——正式周期额外统计快路缺失，非零即失败（§7）。

### 4.4 音频与 PSRAM 边界（本仓暂不适用）

蓝本 §4.4 涉及 ES8311/I2S DMA/SPIFFS WAV 的资源边界，属 watch 音频硬件，本仓不适用。可沿用的通用规则只有一条：**给 DMA 的描述符与缓冲必须留在内部 DRAM，不可迁普通 PSRAM**；大块纯数据可显式放 PSRAM，用小型内部 staging buffer 分块送入外设。EWF 若引入音频/振动等 DMA 外设，先套用本规则再分配内存。

## 6. 回归与排障顺序

滚动卡顿时按以下顺序检查：

1. 启动日志必须显示 `QSPI=80000000 Hz`。
2. 必须看到主壳三页快照与设置页「一张背景 + 两张内容」分配成功日志；缓存总量应对应 §4.3 实际尺寸（蓝本 1,330,936 字节）。
3. 性能判断只看「完整帧」汇总，不看动画回调或主循环次数。
4. 周期「快路缺失」必须为 0；生命周期「快路未就绪」不应增长。若增长，检查首次进入是否完成背景与首张内容预热、PSRAM 缓冲是否完整分配。
5. 平均 flush 接近 16 ms 但 FPS 低 → 检查热路径是否新增逐帧日志、重复整屏重绘或额外 PSRAM 覆盖拷贝。
6. 出现 QSPI 超时 → 先检查上一笔颜色事务是否在下一笔窗口命令前成功回收、在途描述符与像素缓冲是否仍有效；**不要直接降频到带宽不足的 40/20 MHz**。
7. 设置控件拖动必须保持按钮业务 intent 零误提交；短点按、返回手势、子页返回位置恢复必须继续通过。
8. 顶部/底部继续外拖时列表与滚动条必须保持边界位置，松手后不得回弹。

## 7. 正式验收与放行（以实测为准）

蓝本最终按「产品方目标板实际手感验收 + 目标板组件回归 + 完整构建 + 并发串口观察」放行，且**未填写/推算任何未经目标板生成的帧率数字**——最低 1 秒窗口、P99、最大间隔均不推算，也不能把自动诊断当正式 60 秒并发结果。

EWF 沿用同一严格口径：若启用发布门禁，须累计 60 秒有效运动、最低 1 秒窗口 ≥ 60 帧、P99 ≤ 20 ms、最大间隔 ≤ 33.3 ms 且周期快路缺失为 0。未生成当前固件的 60 秒汇总前，只能记录「架构闭合 / 构建通过 / 主观流畅」，**不得宣称滚动页已稳定 60 FPS**。

## 8. 新增或修改 UI 时的架构选择与防回归合同

任何新增页面、列表、轮播、拖动控件或切屏动画，先按以下顺序分类：

1. **静态或离散更新**：清除页面根的 `SCROLLABLE` / `SCROLL_ELASTIC` / `SCROLL_MOMENTUM` / `SCROLL_CHAIN`；只投影当前 Screen；setter 在目标值相同即返回。
2. **小区域连续拖动**：在 binding 内直接更新局部对象，业务 intent 合并提交；禁止每个采样点读取完整状态或整屏 `lv_obj_invalidate()`。
3. **大面积连续滚动**：先在目标板记录完整 DMA 帧基线；若复杂 LVGL 重绘不满足门禁，必须用「静态背景 + 前后台内容快照 + 只读前台合成」，纳入完整帧统计与快路缺失门禁；不得靠调低动画时长伪装。
4. **整屏切换动画**：默认不允许。确有需求须先提交独立内存、失效面积、最坏帧时与故障恢复证据，并把新运动 owner 显式加入白名单；不能直接 `lv_scr_load_anim()` 绕过审查。

大面积快路必须同时满足以下不变量：

- 快照只包含当前状态真正可见的字段；隐藏字段与其他页面字段不得提高视觉代次。
- 前台快照整次 DMA 期间只读；新内容只能写后台，成功完成后才切换前台索引。
- 每次取快照前先恢复几何、再核对 LVGL 实际所需字节数与已分配容量，最后拍摄；尺寸漂移或生成失败应在本次页面生命周期熔断（一次错误、停止重试刷屏），禁止每轮重试打日志风暴。
- 起滑前先清旧脏区再暂停 LVGL invalidation；结束、离页或任一错误路径都必须恢复 invalidation 并请求一次完整重绘。
- 大 transient 快照预算互斥（如蓝本设置页与自检结果页不得同时驻留，理论峰值封顶）；离页立即释放。
- 显示事务只由 `ui_task` 提交；参数/颜色事务描述符与像素缓冲在回收前必须保持有效。
- 所有排队、DMA 等待与普通 flush 都必须有 100 ms 总边界；禁止把 `portMAX_DELAY`、固定 `vTaskDelay()` 或降频当恢复方案。
- 一帧只在最后一块颜色 DMA 完成后计数；回调数、循环数、scroll 事件数与 `lv_timer_handler()` 次数都不是 FPS。
- 快路 miss、分配失败、快照失败、提交失败、DMA 超时、显示恢复或运动期完整模型刷新任一发生，当前正式周期都不得判定通过。

全仓搜索应确认运行时只允许白名单内的滚动事件 owner；Screen 切换使用无动画 `lv_scr_load()`。修改 UI/滚动/投影/显示 IO/任务优先级后至少执行：字体覆盖校验 `missing_glyphs: 0`、SquareLine 工程校验，并在 `Embedded/` 下 `idf.py build`（ESP-IDF v5.5.4 / esp32s3）通过；真机全量烧录 Bootloader、分区表、应用与文件系统，禁止只刷应用。验证与统一校验工具见 `lvgl-design/squareline_studio/tools/`（`validate_squareline_project.py --html lvgl-design/ewf-device-ui.html`、`validate_font_coverage.py`；legbot 定向工具待本仓 Stage 4/5 重定向后补齐）。

## 9. 蓝本踩坑清单（避免重蹈）

以下为蓝本后续追加修正浓缩，全部在本仓落地时作为「必须先满足的防线」，不再重复其完整调查过程：

1. **设置内容快照尺寸漂移 + 日志风暴**：机械投影若保留原始行高（蓝本 378×688），会让拍摄对象几何漂移（合同为 378×608），`lv_snapshot_take_to_buf()` 在绘制前重算容量发现不足即返回失败；闲时循环无熔断 → 每轮重试刷屏。修复 = 拍摄前先执行交互规范化恢复合同几何 → 比较 LVGL 实际所需字节数 → 再快照；失败则本页面生命周期熔断一次，离页重进才解除。
2. **快路遗留通知串扰 → LVGL 永久等待**：颜色完成 ISR「先推进代次、再投通知」，快路可能夹在两个动作间消费掉通知；旧 `complete_pending_flush()` 取到任意通知就 `lv_disp_flush_ready()`，可能提前归还仍在发送的缓冲，后续回调缺失时 LVGL `while(draw_buf->flushing)` 永久等待。修复 = 通知只当纯唤醒信号；普通 flush 只有在「颜色完成代次真正越过本笔提交代次」时才归还缓冲，并设 100 ms 总预算，超时走同步复位恢复路径。
3. **常驻直传的驱动内部无界阻塞**：把一帧拆 16 行、每行调 `draw_bitmap()`，会进入官方 SPI LCD IO 内 `spi_device_acquire_bus()` / `panel_io_spi_tx_*()` 的 `portMAX_DELAY`，上层 10/100 ms 守卫根本约束不到。修复 = CO5300 弃用官方 `esp_lcd_new_panel_io_spi()` 热路径，改用项目专用有界 QSPI IO：32 位前缀映射为 8 位 command + 24 位 address，颜色 payload 用 QIO、切 16 行每片重发 CASET/RASET/RAMWR，排队与回收统一 100 ms 上限。
4. **后台刷新风暴放大掉帧**：旧绑定把每次模型刷新当所有页面同时变画 → 无条件废弃全部常驻快照 → UI 任务同步重建。修复 = 每页独立「规范化视觉签名 + 目标代次 + 快照缓冲代次」，只提高真实变化页面的代次；后台业务刷新与真实像素变化分开统计。另：BLE 等外部发现/扫描策略属 watch 场景，本仓不适用，但「按业务意图收敛后台活动」的原则通用。
5. **同一次交互重复读共享状态误拒 intent**：旧 `build_runtime_model()` 先读共享状态、构造约 400 行模型后再经维护快照二次读同一状态；第二次零等待加锁撞上竞争就把整个用户 intent 当「取不到事实」拒绝，表现为点击/滑动偶发无响应。修复 = 单次读取状态；纯本地导航复用最近一次成功渲染的完整模型，真实副作用仍读最新事实并走业务门禁。

蓝本排障经验也证明：遇到低帧率/卡顿/超时，**优先在正式主程序上复现并采集真实 DMA 帧统计、快路 miss 与串口证据**，不要把时间消耗在「测试固件与生产环境不一致」的调试上（栈大小、任务抢占、外设负载不同会制造伪噪声）。
