## Story

As a 设备使用者，
I want 实体敲击、木鱼点击和自动敲击走同一条输入链路，
so that 每次正式输入的计数、经文、反馈和同步语义一致。

## Acceptance Criteria

### AC 1：三类来源进入同一个 typed queue，单次事件只推进一次

**Given** `physical_pvdf`、`device_touch` 或 `automatic_tap` 事件到达
**When** 输入服务处理事件
**Then** 三类事件进入同一个有效敲击 typed queue；事件载荷保留固定来源名、产生时间/序号和可诊断拒绝原因
**And** 一个已接受事件最多推进一个可消费汉字，正式累计只增加一次
**And** 除该队列消费者外，没有任何代码路径可以推进正式累计、游标、完成状态或同步高水位

### AC 2：统一 gate 拒绝完成、故障和积压已满输入

**Given** 设备处于完成遮罩、故障锁定或离线积压已满状态
**When** 任一来源输入到达
**Then** 输入统一经过 gate，被忽略或拒绝并产出明确状态/typed 原因，不产生新字符、累计或反馈副作用
**And** 相同 gate 规则适用于三类来源，不允许 `automatic_tap` 绕过实体/触摸输入的拒绝路径

### AC 3：供电条件不引入额外拒绝分支

**Given** 设备处于 USB-C 外部供电、电池供电或外部供电并充电
**When** 三类来源输入到达且没有完成、故障或队列满 gate
**Then** 输入服务按同一规则接收或拒绝，不读取或臆造充电状态，不因供电条件增加分支
**And** PWR、BOOT0、熄屏首触等控制事件不会被误转成正式敲击；熄屏首次触摸只唤醒，亮屏后木鱼页点击才生成 `device_touch`

### AC 4：频率与背压行为可验证

**Given** 输入在 1 秒内以 1–20 次到达，或队列暂时没有消费者
**When** 输入服务投递并由队列消费者处理
**Then** 20 次输入全部按序进入统一队列或产生可诊断的有界拒绝，不静默丢弃、不重复入队
**And** 队列满时返回稳定的队列满 typed 原因；不会通过扩大队列、旁路计数或同步调用掩盖背压
**And** 每个来源的接受、拒绝、队列深度和丢弃原因可由中文日志/快照或主机测试观察

### AC 5：候选事件与正式有效事件边界清晰

**Given** Story 1.2 的 PVDF 服务发布候选 `physical_pvdf` 事件
**When** Story 2.1 输入服务消费该事件
**Then** 只有通过本 Story gate 的事件才进入正式有效敲击队列；PVDF 候选失败、超时、越界或无消费者时不能增加正式累计
**And** 不保存或上报原始 PVDF 波形，不引入 QMI8658A、BLE、Wi-Fi 或 GPS 业务输入

## Dev Notes

### 事实源与架构约束

- FR-E-003 要求 `physical_pvdf`、`device_touch`、`automatic_tap` 进入同一有效敲击队列，支持 1 秒 1–20 次；完成遮罩和故障锁定期间忽略输入。[Source: `_bmad-output/planning-artifacts/epics.md` §Epic 2 / Story 2.1；`_bmad-output/planning-artifacts/prds/prd-Electronic_Wooden_Fish-2026-09-07/prd.md` §5.3]
- AD-1 是硬性不变量：除统一队列外，任何路径不得推进正式累计；一次有效敲击只消费一个可消费汉字，充电、完成、故障 gate 的边界以当前 PRD/架构为准。[Source: `_bmad-output/planning-artifacts/architecture/architecture-Electronic_Wooden_Fish-2026-09-08/ARCHITECTURE-SPINE.md` §58–68]
- AD-7 要求服务任务通过 typed event/queue 通信，ISR 只投递事件、不做产品决策；可合并事件可丢最新，命令型事件不得静默丢弃。[Source: `ARCHITECTURE-SPINE.md` §98–106]
- AD-9 要求 `device_state` 是事实源，消费者只读取不可变快照；不得跨服务读取私有变量。[Source: `ARCHITECTURE-SPINE.md` §108–116]
- AD-13 中“充电期间暂停输入”与当前 PRD 的“三种供电条件均可用”冲突；本 Story 遵循 PRD/epics 与硬件边界，不实现充电检测或供电专属拒绝分支。[Source: `prd.md` §5.1；`ARCHITECTURE-SPINE.md` §136–140]

### Story 1.2 交接与现状

- Story 1.2 已把 PVDF 比较器唤醒、ADC 二次确认和候选事件边界放在 `Embedded/components/BSP/PVDF/` 与 `Embedded/components/services/pvdf_input_service/`；其候选来源为 `physical_pvdf`，本 Story 负责唯一消费者与正式 gate。
- 当前 event bus 的候选队列已有固定容量；Story 1.2 的 deferred note 明确指出未有消费者时可能出现第 17 条及以后投递超时，根因应由本 Story 建立消费者与背压证据解决，不能只机械增大队列掩盖问题。[Source: `_bmad-output/implementation-artifacts/deferred-work.md`]
- Story 1.2 的候选自检失败只产生 typed 原因，不写累计；本 Story 必须保留这一边界。[Source: `_bmad-output/implementation-artifacts/1-2-闭合-pvdf-唤醒与-adc-二次确认.md`]

### 目录、代码与 API 约束

- 设备工程为 ESP-IDF ≥5.5.4、目标 ESP32-S3；新增 FreeRTOS/ESP-IDF API 必须先查 v5.5.4 官方文档，不能凭其它版本经验实现。[Source: `Embedded/AGENTS.md`]
- 固件代码遵循中文 Doxygen 文件头、中文日志正文、ASCII 稳定 TAG、snake_case、EWF 前缀、无 VLA、ISR 禁止动态分配；服务任务独占业务状态，ISR 只使用 ISR-safe 投递。
- 目录按 `Embedded/components/BSP`、`platform`、`services`、`app_state`、`main` 既有布局组织。新增组件/服务必须更新相应 `CMakeLists.txt`、依赖声明和启动图，不得把业务逻辑塞入 generated UI。
- UI 仍只由 `ui_task` 访问 LVGL；本 Story 不修改 `generated/`、`bindings/`、Pen、HTML、字体或页面文案。[Source: `AGENTS.md` §3.2；`EXPERIENCE.md`]
- 跨层字段和来源以 `docs/contracts/sync-contract.md` / `.schema.json` 为权威；不得新增 `automatic_tap` 专属 cloud 累计字段或同步接口。[Source: `docs/contracts/sync-contract.md` §2–§4；`ARCHITECTURE-SPINE.md` §74]

### 状态与 UX 交接

- 设备状态词表固定为“本地已记录 / 同步中 / 已同步 / 待同步 / 同步失败”，命令维度“待设备应用”独立存在；本 Story 只提供输入接受/拒绝原因，不能伪造同步成功。[Source: `EXPERIENCE.md` Foundation / State Patterns]
- 完成遮罩只在完成确认后出现；遮罩期间输入冻结，`从头开始`/`退出` 由后续完成与跨轮 Story 实现。本 Story 只保证 gate 不产生新字符或累计。[Source: `EXPERIENCE.md` `modal-done`、UJ-4]
- 木鱼页是唯一 `device_touch` 计数触区，熄屏首触只唤醒；经文/统计/设置触摸仅导航或滚动。[Source: `UI_CONTRACT-device.md` §1、§4；`EXPERIENCE.md` Interaction Primitives]

### 不属于本 Story 的边界

- 不实现 `local_total`/`acked_total` 原子持久化、离线积压计算/排空、`action_id` 落盘或重启恢复；这些由 Story 2.2 负责。
- 不实现木鱼音频、RGB/三环反馈、故障视觉或反馈限速；只发布统一有效事件供 Story 2.3 消费。
- 不实现 CST9217/PWR 页面导航、设置持久化、BOOT0 去抖/定时器或自动模式生命周期；分别由 Story 2.4 与 2.6 负责。
- 不实现 Air780EGP、HTTPS、backend 或小程序；Epic 2 只使用本地状态与 mock，不等待真实 backend。
- 不把主机测试、静态检查、编译或文档一致性表述为 PVDF 电气、20 次/秒样机、低电或整机硬件验收；这些仍需硬件事实源与样机证据。

### Testing Requirements

- 必须有可重复的纯逻辑测试，验证来源归一、统一顺序、一次事件一次消费、gate 拒绝和队列满背压。
- 测试替身应记录 `accepted_count`、`rejected_count`、来源序列、拒绝原因和累计/游标变化；拒绝路径的累计/游标必须保持不变。

- 如执行 ESP-IDF 构建，保留命令、环境、退出码和日志路径；无样机时在完成记录中明确 `hardware_pending`。
