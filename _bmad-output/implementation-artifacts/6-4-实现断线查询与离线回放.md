## Story

As a 小程序用户，
I want 重新打开或断网后完整回放已确认进度，
so that 恢复连接不会跳字或重复。

**覆盖需求：** FR-C-015、FR-C-006、UX-DR17、AD-17、NFR4

本 Story 是 Epic 6 的**断线查询 + 离线回放（REPLAY/OFFLINE）**：在 6.3 LIVE 阅读流之上，交付  
`[READING][REPLAY]` / `[READING][OFFLINE]` 产品态、`replay_cursor`/`last_applied_seq`/`snapshot_seq` 本地持久化、回放期间新事件排队、回放结束无缝接 LIVE，以及序号空洞/重复/旧轮次的契约消费规则。  

**不**实现完成礼花/弹窗/篇章折叠（6.5）、记录/设备/设置业务（6.6–6.8）、14 态像素终验（6.9）、真机 WSS/SM-3（Epic 7）。  
**必须复用** 6.3 `readingStream` / 动画队列 / `realtimeSocket` / `getSyncSnapshot`、5.6 `api/request`、6.2 鉴权门闸——禁止第二 HTTP 栈、禁止以本地展示计数作权威恢复基准、禁止发明新 sync 端点。

## Acceptance Criteria

1. **断线/重开进入 REPLAY 或 OFFLINE（FR-C-015 / UX-DR17 / AD-17）**
   **Given** WebSocket 断开、应用重开、或本地已保存 `replay_cursor` 且权威快照进度超前于已展示水位
   **When** 页面进入查询/回放路径
   **Then** 先 `GET /api/v1/sync/snapshot` 用水位冻结补齐差量基准（`last_applied_seq = snapshot_seq`）；**禁止**用 `displayedCursor`/本地展示计数推断权威
   **And** 回放中显示 REPLAY banner：标题「回放中」、说明「新事件排队」（对拍 HTML；UI 合同合写为「回放中 · 新事件排队」）
   **And** 断线且尚未完成快照补齐/重连时显示 OFFLINE banner：标题「已断线」、说明「稍后重试」
   **And** LIVE 仍可用「已同步」；EMPTY 仍用「等待设备诵读」/「尚未有已确认经文」——不发明营销替代句

2. **回放排队与无缝接实时（FR-C-015 / NFR4 / AD-17）**
   **Given** 处于 REPLAY（正在按已确认差量顺序追赶展示）
   **When** 新的 `delta`（或等价确认推进）到达
   **Then** 新事件进入**排队缓冲**，不得插入当前回放差量中间、不得乱序、不得跳字/重字
   **And** 回放追上冻结目标且队列排空后，`uiPhase` 切回 `live`，无缝消费后续实时帧（同一 SocketTask，不重建第二连接假装「新通道」）
   **And** 动画仍走 6.3 队列：积压可加速，禁止一次渲染跳到末尾

3. **空洞 / 重复 / 旧轮次（FR-C-006 / 契约 §8）**
   **Given** 出现 `seq` 空洞、`seq <= last_applied_seq` 重复帧、或 `round_id` 与当前轮不一致
   **When** 消费入站队列
   **Then** 空洞 → 先查询补齐再续（不消费空洞之后的序号）；重复 → 丢弃；旧轮次 → 拒绝写入当前正文并触发快照重拉
   **And** 持久化键仅 `ewf_` 白名单扩展：`snapshot_seq`、`replay_cursor`、`last_applied_seq`（契约 §11.1 frontend 作用域）；登出/`reset` 必须清除；**禁止**把正式进度写入 `userAuth` 或 token 三键

4. **门禁与范围边界**
   **Given** 6.3 LIVE 已交付
   **When** 完成本 Story
   **Then** frontend 单测通过（含 6.3 回归 + 本 Story REPLAY/OFFLINE/排队/持久化护栏）；`git diff --check` 干净
   **And** 可见文案禁止 TODO/draft/placeholder/Node ID/`data-pencil-id`/调试说明
   **And** 不得改 `docs/contracts/**`、Embedded、backend 业务逻辑；不得引入 Alova/第二请求库；不得手改 `heart-sutra.generated.ts`；不得做完成弹窗

### 必须作出的裁决（推荐项；实现须写入注释）

**裁决 A：`replay_cursor` 语义**
- **推荐：`replay_cursor` = 本地已展示到的可消费步进（对齐 `displayedCursor` 持久化镜像）。** 重开后若快照 `round_cursor > replay_cursor`，从 `replay_cursor` 起动画追到快照游标；追赶期间为 REPLAY。
- 权威完成度 / 进度条分子仍用快照/`delta` 的 `round_cursor`（与 6.3 裁决 E 一致），不要用 `replay_cursor` 冒充正式进度。

**裁决 B：REPLAY 期间新事件排队**
- **推荐：独立 `pendingDeltas` 数组；REPLAY 时 `applyDelta` 改为 enqueue；`flushPendingAfterReplay()` 在展示追上 `replayTargetCursor` 后按 `seq` 升序逐条 `applyDelta`。**
- 若 flush 中再次出现 hole/round_mismatch → 中断 flush，走快照 resync（清空或重建 pending，以快照为准）。

**裁决 C：冷启动动画策略（覆盖 6.3 裁决 C）**
- **推荐：若存在持久化 `replay_cursor` 且 `0 < replay_cursor < snapshot.round_cursor`，强制 `animate=true` 从 replay_cursor 追赶（产品回放）。** 若无持久化或 `replay_cursor===0` 且缺口很大，仍允许一次性水合到快照（避免首登超长回放）；但**只要用户曾展示过进度（replay_cursor>0）就必须可感知回放**。
- 纯 OFFLINE（尚无快照）不播假字。

**裁决 D：OFFLINE vs error**
- **推荐：网络/WS 可恢复断开 → `offline` + 退避重试；契约版本拒绝/鉴权策略关闭（1008）→ `error` 且不重连。** 快照业务失败可 `offline` 重试直至 max_attempts，耗尽后 `error` 并保留已展示前缀。

**裁决 E：持久化写入时机**
- **推荐：`displayedCursor` 每步进、`lastAppliedSeq`/`snapshotSeq` 每次成功应用后 `setStorage`；节流可合并到同一 tick，但进程被杀前最近一次成功态必须可恢复。** 登出 `clearTokens` 同时清三水位键。

**裁决 F：banner 展示形态**
- **推荐：单行或双行均可，字面 = HTML「回放中」+「新事件排队」/「已断线」+「稍后重试」。** 若用单行，允许 `回放中 · 新事件排队`（中间点号对齐 UI 合同）；禁止英文或调试态文案。

**裁决 G：与 6.5 交接**
- **推荐：本 Story 稳定 `uiPhase` 含 `replay`/`offline`；暴露 `isReplaying` getter。** 6.5 仅在 `live`/`replay` 完成后的完成确认上弹窗，不在 OFFLINE 误弹。
