## Story

As a 小程序用户，
I want 修改设备音量、亮度和熄屏时长并知道何时生效，
so that 离线命令不会被误认为已应用。

**覆盖需求：** FR-C-017、FR-C-008、UX-DR20、AD-5

本 Story 是 Epic 6 的**设置镜像页 + 命令下发 + 待设备应用/已生效呈现**：在 6.1 设置壳 + 6.2 鉴权门闸之上，消费已交付的 backend `POST /api/v1/sync/command`（Story 5.4）与 `GET /api/v1/sync/snapshot`（4.6/5.x），交付  
`[SETTINGS][BASE]`（默认三控件 +「已生效」）与语义态 `[SETTINGS][PENDING]`（「待设备应用」），控件符合 MINI-06 / UX-DR20；提交后旧修订、重复提交与离线失败不得覆盖最新选择。

**不**实现 14 态像素终验与印谱装饰终验（6.9）、真机命令应用回传（Epic 7 / 7.2）、backend「立即同步」`sync_now`、改契约字节、改 Embedded。  
**必须复用** 5.6 `api/request`、6.2 `ensureAuthenticated`、6.1 `PageShell`/令牌/`pages/settings` 壳、既有 `getSyncSnapshot` / `StateSnapshot`、5.4 `SettingsCommandRequest` 字段闭包——禁止第二 HTTP 栈、禁止发明 wire 字段、禁止把「待设备应用」伪装成「已生效」、禁止在本地假装设备已应用。

## Acceptance Criteria

1. **三控件与默认值（UX-DR20 / FR-C-017 / DESIGN settings-controls）**
   **Given** 用户进入设置页且快照可用（或尚无快照时用契约默认）
   **When** 渲染音量 / 亮度 / 熄屏控件
   **Then** 使用：
   - 音量：0–100 滑杆，当前值数字同时可见；默认 **50**
   - 亮度：低 / 中 / 高 分段，选中态可见；wire 值 `low|mid|high`；默认 **mid（中）**
   - 自动熄屏：5秒 / 15秒 / 30秒 分段；wire 值 `5|15|30`；默认 **15**
   **And** 布局/文案对齐 `ewf-miniapp-ui-export.html` SETTINGS.BASE（页标题「设置」、胶囊「设备镜像」、主 CTA「保存并下发」）；触区 ≥44×44
   **And** 生产可见文案禁止 TODO/draft/placeholder/Node ID/`data-pencil-id`/调试说明

2. **下发与修订派生态（FR-C-008 / AD-5 / UX-DR20）**
   **Given** 用户调整控件并点击「保存并下发」
   **When** `POST /api/v1/sync/command` 成功（`code=0`）返回 17 字段快照
   **Then** 以响应快照为准更新权威镜像；若 `applied_revision < command_revision` 显示「待设备应用」，仅当 `applied_revision ≥ command_revision` 显示「已生效」
   **And** 「待设备应用 / 已生效」**不是** wire 字段——只由修订对派生（与 `StateSnapshotService.commandApplied` / 6.7 `commandStatus` 同构）
   **And** 请求体 wire 仅：`volume`、`brightness`、`timeout`、`action_id`、可选 `base_revision`；禁止客户端提交权威 `command_revision`/`applied_revision`

3. **刷新 / 推送后仍诚实呈现（FR-C-008 / EXPERIENCE setting-mirror）**
   **Given** 命令已提交但设备尚未回传应用修订（或 mock 未抬升 `applied_revision`）
   **When** 页面 `onShow` 重新拉快照，或收到可应用的 `command_state` / 刷新成功
   **Then** 仍显示「待设备应用」，直到修订对满足已生效判定
   **And** 权威控件值来自最新成功快照/命令响应中的 `volume`/`brightness`/`timeout`（backend 只留最新），不得用失败响应或过期代数覆盖

4. **旧修订、重复提交、离线失败不覆盖最新选择（FR-C-008 / NFR4）**
   **Given** 用户连续改选、重复点保存、或网络失败
   **When** 处理响应
   **Then**：
   - 每次**新**提交使用新 `action_id`；同 `action_id` 重放由 backend 幂等，前端不得二次递增本地草稿修订幻想
   - 在途请求用代数/`_submitGen` 丢弃过期响应，失败保留用户当前草稿（或最近一次成功权威值——见裁决 E），不得把旧成功响应写回覆盖更新草稿
   - `20006 COMMAND_STALE_REVISION`：采用响应携带的完整快照刷新权威镜像与控件，提示可理解短句后允许再次保存；不得静默丢弃服务端最新载荷
   - 离线/传输失败：保持「待设备应用」或失败可重试语义，控件不回滚到更旧的已丢弃选择（除非用户未改且权威快照另有值）

5. **门禁与范围边界**
   **Given** 5.4 命令下发与 6.1–6.7 frontend 基线已交付
   **When** 完成本 Story
   **Then** frontend 单测通过（控件域/默认值/修订派生/单飞提交/过期响应丢弃/`20006` 采用快照/禁用词 + 既有回归）；`git diff --check` 干净
   **And** 不得改 `docs/contracts/**`、Embedded、backend 业务逻辑；不得引入第二请求库；不得在本 Story 做 6.9 像素终验或 Epic 7 真机 ACK

### 必须作出的裁决（推荐项；实现须写入注释）

**裁决 A：数据入口**
- **推荐：读 `GET /sync/snapshot`；写 `POST /sync/command`。** 进入页 / 重试 / 下拉（若启用）走 snapshot；保存走 command。不用 `/stats` 拼设置。

**裁决 B：提交交互**
- **推荐：显式 CTA「保存并下发」。** 滑杆/分段只改 draft，不在 `changing` 过程中自动连发 POST（避免刷修订与竞态）。松手后可更新 draft 数字显示。

**裁决 C：draft vs 权威**
- **推荐：** `snapshot`（或等价权威三字段+修订对）为 cloud 镜像；`draft` 为编辑态。水合成功时 `draft ← 权威`。提交成功 `权威 ← 响应` 且 `draft ← 响应`。提交失败保留 draft。用户编辑中若后台刷新到达：若 `!dirty` 则跟随权威；若 `dirty` 则不覆盖 draft（只更新修订态展示所需的权威修订对，避免把别人的旧响应写进控件）——用 `_fetchGen` + dirty 门闸实现。

**裁决 D：`action_id`**
- **推荐：** 每次用户触发的新提交生成新 UUID（`crypto.randomUUID` 或等价）；禁止复用篇章动作族 `action_id`；禁止跨次提交复用同一 id（除非有意重放——本 Story 不做手动重放按钮）。

**裁决 E：`base_revision`**
- **推荐：提交时携带 `base_revision = 当前权威 command_revision`。** 与 5.4 CAS 对齐；缺省也可 LWW，但带基线可发现并发冲突。`20006` 时采用响应快照（裁决 F）。

**裁决 F：`20006` 与完整快照**
- **推荐：** 识别业务码 `20006`，用 `data` 中 17 字段快照刷新权威+draft，applyStatus 重算，submitPhase=`fail` 或专用 stale 提示（文案短句，非实现说明）；用户可再改再发。禁止忽略 data 继续用本地过期修订当基线硬撞。

**裁决 G：单飞与过期响应**
- **推荐：** submit 单飞（busy 时二次点击忽略或 join）；`_submitGen` 丢弃过期完成回调。fetch 与 submit 可共享「权威写入」门闸，避免旧 GET 覆盖新 POST 结果。

**裁决 H：WS `command_state`**
- **推荐：本 Story 门禁以 REST 为准（onShow + 提交响应）。** 若低成本可从现有 WS 连接解析 `command_state`（revision+载荷）更新权威，则作为增强；不得为此大改 `readingStream` 完成态/回放。真机 ACK 翻转完整闭环归 Epic 7.2。缺省实现：用户回到设置页或下拉即可看到已生效。
