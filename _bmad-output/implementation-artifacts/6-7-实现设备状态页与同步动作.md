## Story

As a 小程序用户，
I want 查看设备电量、4G、最后同步和待处理状态，
so that 我能判断设备是否需要操作。

**覆盖需求：** FR-C-017、FR-C-018、UX-DR19、UX-DR21、AD-2

本 Story 是 Epic 6 的**设备状态页呈现 + sync-action 相位**：在 6.1 设备壳 + 6.2 鉴权门闸之上，消费已交付的 backend `GET /api/v1/sync/snapshot`（Story 4.6/5.x），交付  
`[DEVICE][BASE]`（电量 / 4G / 最后同步 / 待同步数 / 待设备应用 / 同步短句）与 `[DEVICE][FAIL_RETRY]`，以及 loading / empty / fail / refreshed 可操作状态；`sync-action` 展示 busy / pending / fail / ok，动作可重复且单飞。

**不**实现设置镜像与命令下发（6.8）、14 态像素终验与印谱装饰终验（6.9）、backend「立即同步」写路径 `sync_now`（5.2/5.4 deferred；契约篇章动作族尚未落地该枚举）、真机联调（Epic 7）。  
**必须复用** 5.6 `api/request`、6.2 `ensureAuthenticated`、6.1 `PageShell`/令牌/`pages/device` 壳、既有 `getSyncSnapshot` / `StateSnapshot`——禁止第二 HTTP 栈、禁止改 backend/契约字节、禁止发明 wire 字段、禁止把待同步伪装为已同步、禁止展示主控无法确认的充电状态。

## Acceptance Criteria

1. **设备快照只读呈现（FR-C-017 / UX-DR19 / AD-2 / AD-5）**
   **Given** `GET /api/v1/sync/snapshot` 返回 17 字段 `StateSnapshot`
   **When** 打开设备页或刷新成功
   **Then** 展示：
   - 电量：`battery_percent` → `NN%`（**禁止**「充电/未充电」等主控无法确认文案；即使冻结 HTML 样例含「· 未充电」也不得照抄）
   - 4G：`network_mode` → 文案映射 `connected→有信号` / `no_signal→无信号` / `disabled→已关闭`；图标+文字双编码
   - 待同步：`max(0, local_total - acked_total)` → `N 条`；差值 >0 时不得把页眉/同步条写成「已同步/设备与云端一致」的伪装成功
   - 设置状态：`applied_revision >= command_revision` →「已生效」，否则「待设备应用」（派生，非 wire 字段）
   - 页眉胶囊与同步条：按派生相位用冻结短句（见 Dev Notes 文案表）
   **And** 正式状态只来自该快照（及同次请求派生量）；禁止用本地假电量/假 4G/假待同步数

2. **最后同步无 wire 时间戳时的诚实呈现**
   **Given** 契约/快照**没有** `last_sync_at` 字段
   **When** 渲染「最后同步」行
   **Then** 使用**客户端**在每次快照拉取成功时记录的本地时刻做相对短句（成功瞬间「刚刚」；其后可用「N 分钟前」等短相对语）；从未成功拉取时显示「尚未同步」
   **And** 禁止发明后端 wire 字段或伪造「刚刚」在失败态

3. **sync-action：刷新 / 立即同步意图 / 失败重试（FR-C-017 / UX-DR19 / EXPERIENCE）**
   **Given** 用户点击刷新、立即同步意图或失败重试
   **When** 请求处于 busy / pending / fail / ok
   **Then** `sync-action` 展示真实阶段：请求在途=`busy`；成功且待同步数>0=`pending`；成功且待同步数=0=`ok`；失败=`fail`
   **And** 主 CTA 文案对齐冻结 HTML BASE：「刷新设备状态」；失败态提供「重试同步」（或同语义）；「立即同步」与刷新**共用同一单飞拉取**（不得并发双发），不调用不存在的 `sync_now` 写接口
   **And** 空态/失败态说明「是什么+能做什么」，不显示伪造数字

4. **视觉与文案卫生（UX-DR21 / UI_CONTRACT / MINI-06）**
   **Given** `ewf-miniapp-ui-export.html` DEVICE.BASE 与 `UI_CONTRACT-miniapp.md`
   **When** 渲染设备页
   **Then** 使用纸面令牌、`devstatus-row` + 低对比刻线、`state-banner`、`sync-action`；触区 ≥44×44
   **And** 可见文案禁止 TODO/draft/placeholder/Node ID/`data-pencil-id`/调试说明；生产属性不得残留设计节点标识

5. **门禁与范围边界**

   **When** 完成本 Story
   **Then** frontend 单测通过（映射/待同步派生/命令态派生/单飞/禁充电文案/禁用词 + 既有回归）；`git diff --check` 干净

**关键真源结论**

1. **设备页只信 snapshot。** 待同步数 = 后端镜像的 `local_total - acked_total`；不得把差值藏起来假装已同步（AD-2）。
2. **禁止充电态。** UX-DR19 / FR-C-017 / PRD 明确主控不确认充电；HTML「76% · 未充电」是样例装饰冲突——**产品真源优先**，只渲染 `NN%`。
3. **「立即同步」写路径未交付。** `RoundActionRequest` 仅 `restart|exit`；5.2/5.4/SyncController 均声明不做 `sync_now`。本 Story **前端不发明写 API**；三意图共用 snapshot 刷新 + 真实 sync-action 相位。
4. **最后同步无服务端字段。** 用客户端成功拉取时刻；失败不得伪造「刚刚」。
5. **UI 合同 DEVICE 仅 BASE / FAIL_RETRY。** loading/empty/refreshed 是页内状态（EXPERIENCE），不是新 Pen 帧；像素终验归 6.9。
6. **主 CTA 对齐 HTML：「刷新设备状态」。** 失败用「重试同步」；「立即同步」可作为同按钮在 pending 相位的语义别名或次要文案，但仍只触发刷新单飞。

### 必须作出的裁决（推荐项；实现须写入注释）

**裁决 A：数据入口**
- **推荐：仅 `GET /sync/snapshot`。** 不用 `/stats` 拼设备行；不用 WS 作权威（WS snapshot/command_state 可在后续增强，本 Story 以 REST 刷新为准）。进入页、下拉、刷新、重试、立即同步意图均走同一 `fetchSnapshot`。

**裁决 B：待同步数**
- **推荐：`pendingCount = max(0, snapshot.local_total - snapshot.acked_total)`。** 与 5.3 `pending_sync` 语义同构；展示 `N 条`。

**裁决 C：命令行文案**
- **推荐：`applied_revision >= command_revision` →「已生效」，否则「待设备应用」。** 与 backend `commandApplied` / AD-5 一致；色调 pending 用次要强调色（HTML 已生效用 `#a66b3a` 示例，待应用同族或 banner 板「待设备应用」）。

**裁决 D：充电文案**
- **推荐：电量只显示 `NN%`。** 禁止「充电中/未充电」。`battery_percent===0` 仍显示 `0%`（backend 未初始化也是 0——不另发明「—」除非整页 empty）。

**裁决 E：network_mode 文案**
- **推荐：** `connected→有信号`，`no_signal→无信号`，`disabled→已关闭`；非法值当 `无信号` 并不得抛未捕获异常。

**裁决 F：最后同步**
- **推荐：** 成功拉取写 `lastSyncedAt=Date.now()`；UI「刚刚」/相对短句；无成功记录→「尚未同步」。不请求后端新字段。

**裁决 G：立即同步 vs 刷新**
- **推荐：同一单飞 REST 刷新。** sync-action 相位：busy→(ok|pending|fail)。pending 当且仅当成功且 `pendingCount>0`。不 POST `sync_now`、不改 `RoundActionRequest`。真机强制设备上报留给 Epic 7 / 后续 backend story。

**裁决 H：empty 判定**
- **推荐：** 首次进入未完成请求=`loading`；请求失败且无缓存=`fail`；成功始终 `ready`（含全 0 快照）——**不用**「全 0」当 empty（避免与未初始化 0 电量混淆）。可选：成功但 `firmware_version===''` 时页眉/同步条用弱提示「等待设备上报」，数字仍诚实显示。壳层旧句「等待设备状态」可复用于该弱提示，不得假造高电量。
