## Story

As a 小程序用户，
I want 首次打开时完成登录并直接进入唯一设备，
so that 不需要额外绑定步骤。

**覆盖需求：** FR-C-012、UX-DR16、UX-DR21

本 Story 是 Epic 6 的**登录直达与权限态**：在 6.1 已交付的登录路由壳 + 5.6 唯一 `api/request` 上，闭合 `uni.login` → `POST /auth/login/wechat-mini` → `saveTokens` → `switchTab` 阅读页，以及 `[LOGIN][BASE]` / `[LOGIN][PERM_ERROR]` 两态。  
**不**实现阅读流（6.3）、回放（6.4）、完成礼花（6.5）、记录/设备/设置业务数据（6.6–6.8）、14 状态卫生终验（6.9）。  
**必须复用** 5.6 `request.ts`/`storage.ts`/`constants.ts` 与 6.1 壳层——禁止第二套 HTTP、第二套令牌键、绑定/迁移/多设备选择页。

## Acceptance Criteria

1. **登录直达唯一设备（FR-C-012 / UX-DR16）**
   **Given** 用户首次打开、重复打开（已清令牌或新会话）或从 401 失效回到登录页
   **When** 用户完成微信登录流程（`uni.login` 取 code → `POST /api/v1/auth/login/wechat-mini`，`requireAuth: false`）
   **Then** 成功信封 `code===0` 且 `data` 含 `accessToken`/`refreshToken`/`expiresIn`/`deviceId` 时：调用既有 `saveTokens`，本地缓存非权威 `deviceId`（若需要），再 **`uni.switchTab` 到 `/pages/reading/index`**（阅读为唯一设备主入口）
   **And** 全程**不出现**绑定页、迁移页、设备选择页或第二设备身份入口；页面与路由表不得新增此类路径
   **And** 重复登录（同一微信身份）仍直达阅读页；不要求用户再选设备

2. **权限失败态可执行（UX-DR21 / FR-C-012）**
   **Given** 微信授权失败、用户拒绝、`uni.login` 无 code、后端业务错误（含 `40300` 身份不匹配、`50200` 上游不可用、`40000` 参数错误等）或登录响应非成功
   **When** 登录页进入 `[LOGIN][PERM_ERROR]`（或等价页面态）
   **Then** 显示**一句话原因**（产品短句，优先用清洗后的信封 `message`；无可用 message 时用冻结文案「权限错误」）+ **可执行动作**（主按钮文案对齐 HTML：「请重新授权」或「微信登录」重试；点击重新走 `uni.login` 流程）
   **And** 颜色不是唯一通道：失败态同时有文字；不把空态当成零值成功
   **And** 登录按钮 loading 防连点；失败时不清掉未过期的无关 UI，但**不得**在失败路径写入半套 token

3. **信封错误与令牌过期恢复（FR-C-011 消费面）**
   **Given** 登录请求返回业务错误，或冷启动/业务请求触发令牌过期与 401 单飞
   **When** 页面恢复或 `redirectToLogin` 触发
   **Then** 统一经 `api/request` 解释信封；登录接口 `showError: false` 由页面呈现权限态，避免与 toast 双重噪音（可选轻量 toast，但权限态文案必显）
   **And** 复用 5.6：`redirectToLogin` 栈顶判重，**禁止**重复 `reLaunch` 闪烁；刷新失败清令牌后只跳一次登录
   **And** 页面可见文案**禁止**实现说明、调试标签、Node ID、`data-pencil-id`、`TODO`/`draft`/`placeholder`、AI 思维链

4. **门禁与范围边界**
   **Given** 6.1 壳层与 5.6 单飞测试基线
   **When** 完成本 Story
   **Then** frontend 单测通过（含 5.6 单飞回归 + 本 Story 登录/权限态护栏）；`git diff --check` 干净
   **And** 不得改 `docs/contracts/**`、Embedded、backend 业务逻辑（backend 登录已由 4.4 交付，本 Story **只消费**）；不得引入 Alova/第二请求库、H5/App 分支、头像昵称 OBS 完善流、可点击木鱼

### 必须作出的裁决（推荐项；实现须写入注释）

**裁决 A：成功后的导航 API**
- **推荐：`uni.switchTab({ url: '/pages/reading/index' })`。**
- 理由：阅读是 tabBar 页；`reLaunch` 到 tab 路径在部分基础库行为不一致。失败/登出回登录继续用 `reLaunch`（5.6 已定）。

**裁决 B：冷启动未登录拦截点**
- **推荐：`App.onLaunch` 统一门闸 + 登录页自身不二次跳转；一级 tab 页若检测到无 token 可再调共用 `ensureAuthenticated()`（内部走 `redirectToLogin`）。**
- 避免只在 reading 拦截导致深链/其它 tab 漏网。

**裁决 C：权限态文案来源**
- **推荐：优先信封 `message`（清洗后非空）；否则固定产品短句「权限错误」+ 动作「请重新授权」。**
- 禁止把 HTTP 状态码、业务码数字、堆栈、`errcode` 直接展示给用户。

**裁决 D：协议勾选**
- **推荐：登录页内 checkbox +《用户协议》《隐私政策》可点开极简本地页（纯文案）；未勾选 toast「请先阅读并同意协议」类产品句。**
- 不接 OBS、不强制头像昵称。

**裁决 E：deviceId 持久化**
- **推荐：可存 `ewf_device_id`（展示/调试缓存）或仅 Pinia 内存；若落盘必须与 token 白名单策略一致——登出/清 token 时同步删除；不得当作多设备选择键。**
- 权威身份仍在 backend `identity.json`。

**裁决 F：与 6.3 的交接**
- **推荐：本 Story 登录成功后阅读页仍可保持 6.1 空态「等待设备诵读」；不拉取快照/WebSocket。**

## Latest Tech Information

- **uni.login（mp-weixin）：** `uni.login({ provider: 'weixin' })` 返回一次性 `code`；发往自有后端换 JWT。小程序端**永不**嵌入 AppSecret；官方 code 短时单次有效。
- **不要**在 mp-weixin 路径使用 App 端 `onlyAuthorize`/oauth appsecret 配置套路（与 EWF 后端 code2Session 模式冲突且有泄密风险）。
- **switchTab vs reLaunch：** tab 页用 `switchTab`；清空栈回登录用 `reLaunch`（5.6）。
- Pinia：`state()` 预声明字段；登录 loading 放 store 或页面 ref 均可，但防连点必须有。
