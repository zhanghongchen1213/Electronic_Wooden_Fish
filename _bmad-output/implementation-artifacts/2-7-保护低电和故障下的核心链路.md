## Story

As a 设备使用者,
I want 低电、显示故障或外设异常时仍不丢失计数,
so that 设备的关键诵读状态优先得到保护。

**覆盖需求：** FR-E-009、AD-13、NFR7/SM-7、NFR9/SM-C1

## Acceptance Criteria

### AC 1：低电/发射峰值/落盘冲突时先完成累计与轮次落盘

**Given** 电量进入低电等级、4G 活动窗口即将发射，或 progress 事务组尚未落盘完成
**When** 系统同时存在反馈输出、同步开窗与持久化需求
**Then** 调度顺序保证：先完成 `local_total`/`acked_total`/`round_*` 事务组落盘（progress owner），再执行非关键反馈或通信；不得用 `esp_restart` / `esp_deep_sleep_start` / 空循环 / 驱动 LTC2954 `KILL` 模拟关机或“自救”
**And** 低电状态以 typed 事实表达（`watch_power_level_t` + `battery_percent` + 低打扰诊断码），供 Epic 3 投影 `SHELL VAR:lowbatt`；**禁止**伪造充电检测结果或引入充电暂停输入/音频/同步分支（PRD final：三种供电条件同一功能路径）

### AC 2：续航模型证据输入 + 失败只按 PRD 风险收敛

**Given** 设备按约 30 分钟/天敲击、其余时间待机的使用模型（SM-7）
**When** 执行活动窗口、显示与音频路径的功耗/掉压测量准备
**Then** 固件侧提供可观测的低电等级、优先落盘决策日志/快照，并回填/更新 `docs/embedded/guides/低功耗策略与实测验收.md` 的证据模板入口（软件路径可标 `IMPLEMENTED`，实测格保持 `DEFERRED`/`hardware_pending`）
**And** 若样机一天续航或发射掉压未达标，只按 PRD §14 收敛活动窗口时长、电池容量或默认亮度/熄屏——**不得**借此扩展 MVP（常开 4G、BLE/Wi-Fi 回退、堆叠音效、充电专属状态机等）

### 裁决（推荐，实现采用）

1. **充电**：不检测、不暂停、不实现 `SHELL VAR:charging` 产品行为（UX 旧变体待 bmad-ux 对齐；本 Story 不投影 charging）。
2. **优先序**：`FLUSH_PROGRESS` > 已入队敲击消费 > 非关键 feedback > sync 开窗；低电不丢已接受事件。
3. **fault_locked**：仅核心持久化连续失败（+ 预留显示注入）；与反馈通道故障严格分离。
4. **UI**：只产 typed 事实与中文日志；`SHELL VAR:lowbatt/fault` 文案/颜色属 Epic 3。
5. **验证分级**：host/编译 ≠ 样机 SOC/掉压/续航；后者一律 `hardware_pending`。
