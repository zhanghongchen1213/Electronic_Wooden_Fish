## Story

As a 小程序用户，
I want 页面在冻结纸面和底部导航上保持一致，
so that 我能在阅读、记录、设备和设置之间稳定切换。

**覆盖需求：** UX-DR1、UX-DR3、UX-DR16、UX-DR22、AD-18

本 Story 是 Epic 6 的**壳层与导航基线**：把 `cloud/frontend` 从 Story 5.6 的「可测 request 层」扩成可构建的 **uni-app Vue 3 + TypeScript + Vite + Pinia** 微信小程序工程，落地 MINI-06 画布/令牌/四项底部导航骨架。  
**不**实现微信登录直达（6.2）、阅读流（6.3）、回放（6.4）、完成礼花（6.5）、记录/设备/设置业务数据（6.6–6.8）、14 状态卫生门禁终验（6.9）。  
**必须复用** 5.6 已交付的 `src/api/request.ts` / `storage.ts` / `constants.ts`——禁止第二套 HTTP 出口或第二套令牌键。

## Acceptance Criteria

   **And** 生产 `.env`、开发 `.env.development` 与统一 `VITE_API_BASE_URL`（含 `/api/v1`）可被构建读取；不得引入第二 base、不得依赖 `.env.development.local` 运行时覆盖

### 必须作出的裁决（推荐项；实现须写入注释）

**裁决 A：脚手架来源**
- **推荐：以官方 `@dcloudio/vite-plugin-uni` + Vue3/TS 模板为底，在现有 `cloud/frontend` 目录演进；不整仓复制 miaowu frontend，不引入多端 conditional 编译垃圾。**

**裁决 B：底部导航实现**
- **推荐：优先 `pages.json` 原生 `tabBar` 四项（阅读/记录/设备/设置），自定义样式用 `tabBar.list` + 选中色对齐 `#a66b3a`；若原生 tabBar 无法满足纸面/56px/无边框质感，再用自定义 `bottom-nav` 组件 + 隐藏原生 tabBar。**
- 无论哪种，触区 ≥44×44、四项始终可达、文案四字固定不可改名。
- 登录页 **不进** tabBar。

**裁决 C：页面填充深度**
- **推荐：四页只放 `page-header` 标题 + 纸面留白/产品空态一句；不实现 readingline/statcard/settings-controls。**
- 空态文案用产品口吻（如「等待设备诵读」），禁用「占位」「TODO」。

**裁决 D：依赖边界**
- **推荐：Pinia 官方 store；HTTP 仅既有 `api/request`；不引入 Alova、axios、uni-network。**
- UI 组件库非必须；MINI-06 以自绘纸面为准，避免通用 UI kit 破坏无盒化。

**裁决 E：构建证明**
- **推荐：CI/本地门禁以 `vitest run` + `build:mp-weixin`（或 `uni build -p mp-weixin`）为准；不要求本 Story 通过微信真机预览。**
- 真机与合法域名属 Epic 7 / 部署假设 A-7。

**裁决 F：与 6.2 的交接面**
- **推荐：6.1 交付可打开的 login 路由页 + tab 四页；6.2 在 login 页接 `wx.login` → `POST /auth/login/wechat-mini` → `saveTokens` → `switchTab` 阅读页，并做权限失败态。**
