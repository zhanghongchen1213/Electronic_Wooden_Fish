## Story

As a 设备用户，
I want 完成《心经》后从头开始而不覆盖旧篇章，
So that 每次诵读和历史都能被区分。

**覆盖需求：** FR-C-003、FR-C-004、FR-C-016、AD-19

## Acceptance Criteria

1. **末字确认后才进入完成态（FR-C-003 / FR-C-004 / FR-C-016 / §7）**
   **Given** mock device 经 JWT 身份上报与当前权威同 `round_id` 的轮次，且 `round_cursor == consumableHan`，并置位 `pending_completion=true`（或请求 `round_state=completed` 表达「请确认完成」）
   **When** backend 边界校验成功并确认高水位写路径
   **Then** 权威事务组写为 `round_state=completed`、`pending_completion=false`，响应 17 字段快照反映完成态
   **And** 完成确认前：权威 `pending_completion==true` 时提交更大的新 `round_id` → `20001`（承接 5.1 裁决 B，不得覆盖未确认轮次）
   **And** **禁止**仅凭 `consumableHan` 对任意差量盲推游标或自动翻转 `completed`（AD-3 / AD-19）；完成翻转只发生在本 Story 的确认规则命中时
   **And** 矛盾组合在确认规则之外被拒绝：权威已 `completed` 时再报 `pending_completion=true`，或确认前同时要求「未达末字却 `round_state=completed`」→ `20001`，不写盘

2. **完成锁定期间正式输入不推进游标（FR-C-004）**
   **Given** 权威 `round_state=completed`（完成锁定）
   **When** 设备再次提交同轮次的同步上报（含试图增大 `round_cursor`、改回 `in_progress`、或新 `round_id` 而无篇章动作）
   **Then** 轮次四字段保持冻结（`round_id` / `round_cursor=consumableHan` / `completed` / `pending_completion=false`）
   **And** 试图换轮或改游标 → `20001` + 完整基准；同轮合法镜像/高水位 no-op 或推进**不得**改动已冻结游标与完成态
   **And** 高水位规则仍遵守 5.1：`local_total > cloud.acked_total` 可推进累计；`local_total < cloud.acked_total` → `20003`；同 `action_id` 重放仍幂等

3. **从头开始 / 退出动作幂等（FR-C-004 / FR-C-016 / §7 / §9）**
   **Given** 客户端以篇章动作族 `action_id` 请求「从头开始」或「退出」
   **When** 请求重复、乱序或重试
   **Then** 「从头开始」只创建一个新 `round_id`（`:=` 旧 `round_id + 1`），`round_cursor=0`、`round_state=in_progress`、`pending_completion=false`；**不**清零 `local_total`/`acked_total`；旧完成态被新进行中轮次接替，累计与可归档历史语义保留（日统计写入属 5.3，本 Story 不写 `daily_stats.json`）
   **And** 「退出」保留 `round_state=completed` 与当前 `round_id`/`round_cursor`，不创建新轮次
   **And** 同一 `action_id` 重复提交返回与首次确认一致的权威快照（同一 `round_id`）；新 `action_id` 才允许再次 restart
   **And** 在未完成确认（权威非 `completed`）时请求 restart → `20001`；exit 在非完成态上为幂等 no-op 或 `20001`（见裁决 C，实现须在 javadoc 钉死一种）

### 必须作出的裁决（推荐项；实现须写入 javadoc）

**裁决 A：完成确认触发条件**
- **推荐：** 当且仅当同时满足：① 请求 `round_id` 等于权威 `round_id`（权威尚无轮次时允许首轮建立）；② `round_cursor == consumableHan`；③ 请求表达完成意图（`pending_completion==true` **或** `round_state==completed`）；④ 高水位校验未命中硬冲突（`20003`/`20005`/`20001` 域外）——则权威写入 `round_state=completed`、`pending_completion=false`。
- 未达末字却报 `completed` → `20001`，不写盘。
- 仅 `pending_completion=true` 但游标 &lt; 末字 → `20001`（不得提前完成态）。
- 确认成功后响应必须可读完成态（供 mock/小程序后续消费）；**不**推 WS。

**裁决 B：完成锁定与高水位**
- **推荐：** `round_state==completed` 时冻结轮次四字段；同步上报若试图修改 `round_id`/`round_cursor`/`round_state`/`pending_completion` → `20001`。
- 同轮次、轮次字段与权威一致（或请求轮次字段可被规范为与权威相同）时，允许按 5.1 推进/no-op 高水位与派生镜像。
- `pending_completion==true` 且尚未确认完成：继续拒绝更大 `round_id`（5.1）；允许同轮把游标推到末字以便命中裁决 A。

**裁决 C：exit 在非完成态**
- **推荐：非 `completed` 时 exit → `20001`**（与 restart 对称，避免静默 no-op 掩盖客户端状态机错误）。
- 已 `completed` 时 exit 写入/保留篇章动作 `action_id`，轮次字段不变；同 `action_id` 重放返回同一快照。

**裁决 D：篇章动作路径与请求体**
- **推荐：`POST /api/v1/sync/round-action`**，body = `{ "action": "restart"|"exit", "action_id": "<opaque>" }`。
- 理由：与 `/report` 同控制器族；避免把 restart/exit 塞进 §6.1 上报闭包（会污染高水位语义）；`action` 为 REST 裁决字段（契约未冻结该路径/字段名）→ **必须**登记 deferred，**不得**改契约文件。
- 身份与拒绝带基准规则同 5.1。

**裁决 E：restart 与累计**
- **推荐：** `round_id' = round_id + 1`，`round_cursor=0`，`in_progress`，`pending_completion=false`；`local_total`/`acked_total` **原样保留**。
- 仅当权威已 `completed` 时允许 restart；完成后未 exit 亦可直接 restart（产品 UJ-4 两动作独立）。
- 同 `action_id` 已执行过 restart → 返回已创建的那一个 `round_id`，不递增。
