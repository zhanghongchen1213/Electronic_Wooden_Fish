## Story

As a 唯一设备用户，
I want 登录后直接得到我的固定设备上下文，
so that 我不需要处理绑定、迁移或多设备选择。

本 Story 覆盖 FR-C-001、FR-C-011、FR-C-012，是 Epic 4 的第四道门禁。
Story 4.3 已提供 Java 17 + Spring Boot 3.3.7、`/api/v1`、`ApiResponse`、
`GlobalExceptionHandler` 和 `application*.yml` 基线；本 Story 在其上闭合微信
`code2Session`、JWT access/refresh、固定 `device_id` 与鉴权过滤器。

本 Story 只实现 backend 身份入口与鉴权基础设施：不实现进度/高水位同步、快照、命令、
统计、WebSocket、frontend 页面或并发 401 单飞队列。frontend 的登录直达、刷新队列和
权限态在 Epic 6 消费本 Story 的接口；Epic 5/4.5 复用本 Story 的 `UserContext`、
`device_id` 和身份 JSON，不重新发明身份模型。

## Acceptance Criteria

1. **首次登录、重复登录与刷新**

   **Given** 微信 `code`、EWF AppID/AppSecret 配置和当前单设备身份规则已就位
   **When** 客户端调用 `POST /api/v1/auth/login/wechat-mini`，或调用
   `POST /api/v1/auth/refresh` 刷新有效 refresh token
   **Then** backend 通过 `WechatMiniClient` 的 `code2Session` 取得 openid，按固定规则
   建立/读取同一个 `device_id`，并返回 `ApiResponse` 成功信封
   **And** 成功 `data` 至少包含 `accessToken`、`refreshToken`、`expiresIn` 与
   `deviceId`；重复登录得到相同 `deviceId`，refresh 不创建新身份
   **And** 登录成功不返回 openid、session_key 或其他微信会话材料。

2. **单身份单设备与隔离**

   **Given** `cloud/backend/data/identity.json` 不存在
   **When** 首个有效微信身份登录
   **Then** 只创建一份 `schema_version: 1` 的身份文件，落点为 `app.data-dir/identity.json`，
   内容只承载契约规定的 `device_id`，写入使用同目录临时文件、`fsync`/`FileChannel.force`
   与原子 rename
   **And** 不创建 `progress.json`、`commands.json`、`device_state.json` 或
   `daily_stats.json`，这些文件属于 4.5/后续 Story。

   **Given** 已有身份文件且新的 code2Session 返回相同 openid
   **When** 重复登录或并发重复登录
   **Then** 返回同一 `device_id`，不重复建号、不覆盖身份文件；同一 openid 的读-判空-写
   在单实例内受互斥保护。

   **Given** 已有身份文件且新的 code2Session 返回不同 openid
   **When** 该身份尝试登录或取得受保护资源
   **Then** 返回可执行的权限错误（HTTP 403 + `40300`），
   不提供绑定、解绑、换机迁移、多设备选择或第二套设备身份，不修改既有身份文件。

3. **JWT 与路径分级**

   **Given** 4.3 的 Spring Boot 3.3.7 工程和现有 `jwt.*` 配置存在
   **When** backend 签发、刷新或校验令牌
   **Then** 使用 JJWT 0.12.6、HS256、配置中的 access 过期时间（当前基线 7200000ms）
   与 refresh 过期时间（当前基线 2592000000ms）；令牌包含 `sub`（固定身份/设备标识）、
   `type`（`access` 或 `refresh`）、`iat`、`exp`，refresh 不能作为 access 使用
   **And** 解析必须校验签名、过期时间、token type 与 `device_id`；短 secret 或缺失配置
   fail closed，不用弱密钥生成令牌。

   **Then** 使用不依赖 Spring Security 的 `OncePerRequestFilter`（注册顺序为 1）和
   `UserContext` ThreadLocal；每次请求无论成功、失败或异常都在 `finally` 清理上下文，
   防止线程池复用泄漏。

   **And** PUBLIC 白名单只包含精确方法/路径：
   `POST /api/v1/auth/login/wechat-mini`、`POST /api/v1/auth/refresh`、
   `GET /api/v1/health`（以及 4.3 保留的根探活 `/`）；其余 `/api/**` 一律要求
   `Authorization: Bearer <access-token>`。不要用宽泛 `startsWith` 放行 `/auth`。

4. **无效 code、令牌和权限失败**

   **Given** code 为空/重复格式非法、微信返回 `errcode`、AppID/AppSecret 仍是配置占位值、
   token 缺失/损坏/过期/类型错误或身份设备不匹配
   **When** 调用登录、刷新或受保护 endpoint
   **Then** 始终返回统一 `{code,message,data}` 信封；参数协议错误使用 HTTP 400 + `40000`/`40001`，
   令牌缺失/非法/过期使用 HTTP 401（`40103`/`40102`/冻结的 `40101`），身份不匹配使用
   HTTP 403 + `40300`；微信上游不可用或配置占位值使用 HTTP 502 + `50200`；错误文案给出
   “重试/重新登录”这类可执行动作
   **And** 不把微信 `errcode`、异常栈、AppSecret、JWT 或 session_key 原样透出给客户端。

5. **微信调用与敏感数据边界**

   **Given** 微信 `jscode2session` 可能返回 `application/json` 或 `text/plain`
   **When** `WechatMiniClient` 发起 code2Session
   **Then** 先以 `String` 读取响应，再由 Jackson 解析；请求参数固定为 `appid`、`secret`、
   `js_code`、`grant_type=authorization_code`，调用官方 endpoint
   `https://api.weixin.qq.com/sns/jscode2session`
   **And** 使用独立的直连 `RestTemplate`（JDK HttpClient、禁用系统代理、HTTP/1.1、连接超时
   10s、读取超时 15s、稳定 User-Agent），不把支付/OBS/手机号/小程序码 client 迁入 EWF。

   **Then** `session_key` 只在换取 openid 的瞬间存在，立即清空且绝不持久化、响应或日志；
   openid 只用于本次映射与稳定设备标识计算，日志最多输出脱敏片段或不可逆摘要，不能输出原文。
   不记录响应原文前 240 字符（响应可能包含 session_key）；上游排障只记录 errcode、非敏感 errmsg
   或长度/摘要。

6. **测试与可复现门禁**

   **Given** backend 仍是单实例 JSON 零库工程
   **When** 执行 `cd cloud/backend && mvn -q test`
   **Then** 测试不访问真实微信网络，使用 `MockRestServiceServer`/等价 HTTP 替身覆盖：
   text/plain JSON、空/畸形响应、微信 `errcode`、占位 AppID/Secret、超时/解析失败
   **And** MockMvc 覆盖首次/重复/并发同 openid 登录、不同 openid 被拒绝、重启后 identity
   映射保持、缺失/非法/过期 access token、refresh token 误用、`UserContext` finally 清理、
   公开路径与受保护路径分级、统一错误信封和敏感日志窄扫描。

   **And** 至少提供 4 条可失败 RED→GREEN 证据：移除 Bearer 校验、把 refresh 当 access 接受、
   取消同 openid 互斥、把 session_key 写入日志/响应；每条记录命令、首个失败断言、恢复后结论。
   测试必须使用临时 `app.data-dir`，不得污染工作区的 `cloud/backend/data/`。

### 身份文件与设备标识裁决

`docs/contracts/sync-contract.md` §11 冻结 `identity.json` 为单身份单设备映射，字段只有
`device_id`（带 `schema_version: 1`）。为使重启后仍能判断“是否同一个微信身份”，本 Story
采用稳定设备标识：对本次 code2Session 返回的 openid 做 SHA-256，再使用 URL-safe 编码并加
`ewf-` 前缀。该值只作为不透明 `device_id`，不记录 openid 原文；测试只验证同值/异值关系。

流程固定为：

1. 读取 `identity.json`；缺失时按上述规则生成 device_id 并原子创建文件。
2. 已有文件时重新计算 device_id；相等则继续签发 JWT，不相等则返回 403 且不改文件。
3. 文件存在但 JSON 损坏、schema_version 非 1 或 device_id 为空时返回可诊断存储配置错误，
   禁止“修复”为新设备，否则会把旧身份的进度与新身份混在一起。
4. 同 openid 并发登录必须在单进程互斥区内完成读-判空-写；身份 JSON 的原子写仍是最后一道
   崩溃保护，不能把“先查后写”当作原子性。

该裁决与迁移经验中的 `openIdSha256` 哨兵建议一致，同时不扩展契约的后端文件集合；
4.5 应提取并复用原子 JSON 基元，而不是建立第二套身份文件。

### JWT 实现边界

- JJWT 固定 0.12.6；Maven 依赖只加入 `jjwt-api`（compile）和 `jjwt-impl`、`jjwt-jackson`
  （runtime），不引入 Spring Security、数据库、Redis、OAuth client 或第二 JWT 库。
- HS256 key 使用 `Keys.hmacShaKeyFor(UTF_8(secret))`；secret 少于 32 bytes、为空或仍为
  `replace-with-*` 占位值时，登录/refresh 应明确失败，不在启动时让 4.3 探活失效。
- parser 预构建为线程安全实例；捕获 `ExpiredJwtException` 与其它 `JwtException`，不把解析异常
  堆栈写进响应。access token 只带身份最小 claim，refresh token 只用于刷新。
- `OncePerRequestFilter` 不依赖 Spring Security：认证失败必须通过 Jackson 序列化 `ApiResponse`
  写回 HTTP 401，不能让 Filter 绕过统一信封。`UserContext.clear()` 放在最外层 `finally`，
  即使 controller 抛异常也要执行。
- 本 Story 不实现 logout、解绑、换机、tokenVersion、角色/租户和 WebSocket；这些都不是
  FR-C-001 的 MVP 入口。后续若需要 tokenVersion，必须先扩展同步契约/identity schema 并单独审查。

### 微信 client 实现边界

- code2Session 请求必须带 `appid`、`secret`、`js_code`、`grant_type=authorization_code`；
  微信响应可为 `text/plain`，所以禁止直接 `getForObject(..., Code2SessionResponse.class)`。
- 40013（invalid appid）只返回“检查 backend、微信开发者工具和公众平台 AppID 一致”的短提示；
  不把 AppSecret、响应原文或 session_key 放到日志。网络/解析失败给用户“稍后重试”，日志保留
  非敏感 errcode/URI 以便定位。
- 经验文档建议记录 body 前 240 字符，但这会与 `cloud/AGENTS.md` 的 session_key 禁止日志规则
  冲突；本 Story 以更高优先级敏感数据规则为准，只记录摘要/长度/errcode，不记录 body 原文。
- 只实现 code2Session。access_token、手机号、unionId、头像、小程序码、OBS、支付和管理后台
  client 均为非目标；不要因为迁移源码存在就复制。

  Security 的 JWT 入口；来源：<https://docs.spring.io/spring-framework/docs/6.1.5/javadoc-api/org/springframework/web/filter/OncePerRequestFilter.html>。

  `application-local.yml` 与 `local` profile 为准，不新增运行时覆盖层。来源：
  <https://docs.spring.io/spring-boot/reference/features/external-config.html>。
- 微信官方 code2Session endpoint 与参数契约以开发者文档为准：
