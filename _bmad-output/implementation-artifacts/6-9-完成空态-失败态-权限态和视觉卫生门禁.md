## Story

As a 小程序用户，
I want 在所有非正常状态下仍得到清晰、可操作的页面，
so that 错误不会破坏阅读体验。

**覆盖需求：** FR-C-018、FR-C-019、UX-DR21、UX-DR23、UX-DR24、UX-DR25、UX-DR26、NFR9

本 Story 是 Epic 6 的**收口门禁**：在 6.1–6.8 已交付的六类页面业务能力之上，闭合  
（1）FR-C-018 空态/失败态/权限态的**可见、可操作、非纯色传达**；  
（2）FR-C-019 / UX-DR24 的 **MINI-06 14 状态对拍 + 文案/属性卫生扫描**；  
（3）前序 Story 明示 defer 的印谱 `style-signature`、图标双编码、触区与对比终验。

**不**实现 Epic 7 真机联调、不改 `docs/contracts/**`、不改 Embedded、不改 backend 业务逻辑/错误码、不发明第二 HTTP 栈、不从历史候选稿抄布局。  
**必须复用** 6.1 `PageShell`/令牌/`tokens.scss`、6.2 登录/权限、6.3–6.5 阅读态、6.6 记录、6.7 设备、6.8 设置、5.6 `api/request`、既有 `*_COPY` 常量与各页护栏测试——本 Story 以**补齐缺口 + 统一门禁**为主，禁止重写业务 store 核心路径。

### 必须作出的裁决（推荐项；实现须写入注释）

**裁决 A：范围**
- **推荐：仅 `cloud/frontend` + `deferred-work.md` + 本 story 文档。** 禁止改 Java、契约、Embedded、Pen/HTML 真源文件（只读对拍）。

**裁决 B：14 态验证方式**
- **推荐：表驱动护栏（文案金句 + store/UI 相位可达）+ 对照 HTML BASE 的令牌/结构清单。** 不要求截图像素 CI；人工逐屏检查记录在 Completion Notes。质量策略 best_effort：自动化能钉的钉死，像素色差记证据而非阻塞错误码发明。

**裁决 C：队列已满**
- **推荐：设备页（及可选阅读弱条）当 `max(0, local_total-acked_total) >= 1000` 显示「队列已满」+「等待同步排空」；可操作动作为「刷新设备状态」。** 不调用不存在的排空 API；不把队列已满伪装成已同步。

**裁决 D：低电量**
- **推荐：阈值 `battery_percent <= 20`（常量 `LOW_BATTERY_PERCENT = 20`）。** 文案「电量偏低」+「请尽快连接电源」（避免「充电中」产品态）。icon+文字；不影响计数权威。

**裁决 E：待校时**
- **推荐：不伪造。** `STATE_COPY.clockPending = '待校时'` 仅作词表预留；无 backend 信号则不渲染。在 deferred 登记：若日后快照/统计增加 trust 字段再接。不得用「今日=0」猜待校时。

**裁决 F：印谱组件**
- **推荐：单一 `StyleSignature` 组件 + 页级 props（variant: login|reading|records|device|settings|overlay）。** 阅读页保留 17 槽基线；其它页 seal+刻线。禁止每页复制三套绝对定位魔法数而不注释 HTML 参照。

**裁决 G：卫生扫描范围**
- **推荐：扫描 `src/pages`、`src/components`、`src/utils/constants.ts`、`App.vue`、`styles/`。** 测试文件可含英文 draft 讨论则排除 `*.test.ts`。禁用词至少：`TODO`、`draft`、`placeholder`、`data-pencil-id`、`data-pencil-name`（生产）、常见 Node id 样例（`qljP7` 等若出现）。store 编辑槽继续用 `edit` 不用 `draft`。

**裁决 H：对比度验证**
