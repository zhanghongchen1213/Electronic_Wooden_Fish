# Electronic_Wooden_Fish — EXPERIENCE.md

> 本文件是行为权威，视觉参考 DESIGN.md；两者冲突时按各自职责分别解释。功能边界以 PRD/架构（epics E3/S3/S4）为上限，本文不扩范围。

## Foundation

- **双表面**：
  - 设备：CO5300 410×502 AMOLED，UI 系统 LVGL 8.4（`ui_task` 独占）；输入包括 CST9217 触摸、PWR、PVDF（`physical_pvdf`）和木鱼点击（`device_touch`）。
  - 小程序：uni-app（微信），阅读纸面；不提供电子木鱼，也不是输入源，只呈现 backend 已确认进度（FR-F-002）。 视觉真源为 miniapp-design/ewf-miniapp-ui.pen，同名 HTML 由作者导出。
- **共享语义**：同步状态词表（本地已记录 / 同步中 / 已同步 / 待同步 / 同步失败）+ 命令「待设备应用」（独立维度）；未校时「待校时」（AD-6）。

## Information Architecture

**设备（三主页 + 下滑设置；PWR 短按：熄屏唤醒 / 亮屏按 木鱼→经文→统计 循环）**
```text
├ 木鱼页      7字带｜心经进度字数/百分比｜今日敲击｜累计敲击｜电子木鱼(唯一可点敲区)
├ 经文页      一篇连续经文流：流尾最新字大字高亮 + 已确认前文可回看 + 心经总进度（无选经入口）
├ 统计页      今日敲击 + 累计敲击（近7/30与连续归小程序）
└ 下滑 → 设置页  亮度(三档·默认中) ｜ 自动熄屏(5/15/30·默认15) ｜ 音量(0-100·默认50) ｜ 立即同步 ｜ 木鱼版本 ｜ 木鱼ID（首屏最多4行，向上滑查看第二页）
顶部状态栏常驻：左侧 4G/Wi-Fi/蓝牙/GPS 状态组件 · 右侧电池符号/百分比 · 同步
```

**小程序（登录后直达唯一设备；单栏流）**
```text
阅读页(主)   持续累积心经正文｜离线回放｜总进度百分比｜完成弹窗
记录页       今日/近7/近30/累计/连续天数
设备页       电量/充电 · 4G · 最后同步 · 待同步数 · 待设备应用 · 失败 + 刷新/立即同步/重试
设置页(镜像)  音量/亮度/熄屏（离线显“待设备应用”，ACK 后刷新）
```

小程序四个一级面共用四项底部导航：`阅读`、`记录`、`设备`、`设置`；当前项使用 `{colors.mini.focus}`，其余项使用 `{colors.mini.text.muted}`。方向稿以 390×844 手机画布、顶部安全区 62px、底部导航 56px 为基线。

### 诵读周期与计数语义

- 一次“当前诵读”是从 canonical《心经》首个可消费汉字到末个可消费汉字的一次完整推进；长度由 `scripture_chars_total` 提供，不是用户可调上限，也不会因 7 字带容量而溢出。
- `round_consumed` 是当前诵读已确认字数；`round_percent = clamp(round_consumed / scripture_chars_total × 100, 0, 100)`。达到 100% 后进入完成锁定，选择“从头开始”创建新的 `round_id`，旧篇章保留在记录/归档中。
- `today_taps` 是 backend 按配置时区归档的已确认有效敲击；未校时时设备显示“待校时”。`total_taps` 是跨所有诵读周期的已确认有效敲击高水位，新周期不会清零。
- 设备可显示本地即时值，但必须用“同步中/待同步”标记未确认差值；小程序只显示 backend 已确认值。

## Voice and Tone

- 诵经语境：极简、平静、少打扰；只用**状态短句**（如「待同步」「待校时」「待设备应用」）与两个动作（从头开始 / 退出）。
- 不用营销词、不加感叹号；错误/空态给出「是什么 + 能做什么」，如「尚未同步」「网络不可用，稍后重试」。

## Component Patterns

行为规则；视觉规格统一见 DESIGN.md 的 Components 章节：

| 组件 | 行为规则 |
| --- | --- |
| `statusbar` | 常驻显示电量/充电、4G、同步状态；四个信号位置各保留一个图标槽，由运行时颜色/图标补丁切换状态，不复制隐藏节点。 |
| `connectivity-rail` / `signal-status` | 固定承载 4G、Wi-Fi、蓝牙、GPS 四项状态；每项支持 connected/no-signal/disabled，图标与文字/线条双编码。图标可见不代表业务链路启用。 |
| `battery-status` | 右侧显示电池符号与百分比；充电和低电量有独立符号/文案。 |
| `charcell` | 固定 7 槽；新字右入、旧字左移；标点随相邻字出现且不消耗敲击；空位不预览未来字。 |
| `glyph-current` | 只强调流尾最新已确认字；高亮保持到下一有效字，旧字回到普通正文层级。 |
| `scripture-progress` | 设备与小程序均展示当前诵读已确认字数、总可消费字数和百分比；小程序使用 `confirmed_chars`、`scripture_chars_total`、`percent` 字段；达到 100% 后保持 N/N，不允许溢出。 |
| `round-index` | 只用于辅助显示当前诵读序号/状态，不解释为字数上限。 |
| `today-taps` / `total-taps` | 分别表示今日有效敲击与跨诵读周期累计有效敲击；未校时/未确认差值按状态词表提示。 |
| `stat-card` | 统计页将 `today-taps` 与 `total-taps` 以同构大数卡呈现；设备不显示近 7/30 日或连续天数。 |
| `woodfish` | 木鱼页唯一可计数触区；点击进入 `device_touch`，其它页面普通触摸不计数。 |
| `woodfish-anatomy` | `woodfish` 内的非交互视觉子组件；只承载器物识别，不接收输入、不独立计数。 |
| `tap-rings` | 木鱼页三道椭圆环；两种有效输入都触发 160ms 金色闪光后恢复，连续输入只合并光效、不合并字符。 |
| scripture-history | 小程序经文流每行恒定 17 个字符槽，标点占槽但不计敲击；最新字落在已有前缀后的下一个槽位，垂直滑动只回看已确认前文，新字到达自动回到流尾。设备经文页的 13 槽规则由设备契约单独治理。 |
| settings-list / row / slider | 小程序设置镜像使用音量 0–100 滑杆、亮度低/中/高分段控件、熄屏 5/15/30 秒分段控件；提交后按命令修订号显示待设备应用或已生效。 |
| `sync-btn` / `sync-action` | 同步动作显示 busy/ok/pending/fail；失败可重试，不虚构成功。 |
| `modal-done` | 仅在完成确认后出现；遮罩期间输入冻结；从头开始新轮次，退出保留历史。 |
| `readingline` / `char-focus` | 小程序把每个 backend 已确认字 append 到当前诵读正文；已有前缀永不覆盖或清空，自然换行并可回看，最新尾字放大高亮且下划线始终在其下方。 |
| `reading-archive` | 完成后保留当前篇章正文；“从头开始”在下方开启新篇章区块，旧篇可折叠查看。 |
| `statcard` / `devstatus-row` | 统计和设备状态只读 backend 已确认数据；空值/失败不显示伪造数字。 |
| `state-banner` | 离线、待同步、失败等状态用短句 + 图标表达，不只依赖颜色。 |
| `setting-mirror` | 设备未确认时显示「待设备应用」，收到应用修订后才显示「已生效」。 |
| `device-identity` | `木鱼版本` 与 `木鱼ID` 共用同一行几何与字阶；值来自设备状态，不由页面复制生成。 |
| `empty` | 明确是什么状态及可执行动作；不把空态当作零值成功。 |
| `confetti` | 仅在 backend 确认完成后展示，且为短促反馈。 |
| `bottom-nav` | 四项一级面始终可达；当前项强调，触区不小于 44×44。 |

敲击反馈链：一次有效敲击 → 下一字进入 7 字带或经文流；最新字大字高亮；木鱼页显示 160ms 三环金光；木鱼音播放；今日敲击与累计敲击各 +1（音频失败不阻塞，AD-12）。空/失败态各自提供一句话与动作；本地待同步数据**绝不**以正式进度呈现（AD-2）。

组件 ID 以表面为命名空间：设备统计卡使用 `device/stat-card`，小程序记录卡使用 `mini/statcard`，两者视觉与数据密度不同，不视为同一组件变体。

### 最新字与三环反馈契约

1. **输入归一**：`physical_pvdf` 与木鱼页 `device_touch` 进入同一有效敲击队列；木鱼页两种来源都触发三环，充电、完成遮罩、故障锁定和熄屏首触不触发。
2. **木鱼页**：新可消费汉字从右侧进入 7 字带，旧字左移；最新槽使用 `{typography.device.glyph}` + `{colors.brand.amber.400}`，保持到下一有效字；三道透明椭圆环在 0–40ms 切换 `{colors.brand.amber.300}`，40–160ms 回到 idle 描边。该切换是**描边色运行时补丁**：母版只导出 idle 白色描边，金色由 `bindings` 在 `ui_task` 内下发，不建立金色环节点变体（避免与固件常量形成双真源）。
3. **经文页**：`physical_pvdf` 追加到同一篇 `scripture-history` 流尾；每行固定 13 个字符槽，标点占槽但不计数；最新字落在前文之后的下一个槽位并使用大字高亮，前面所有已确认字永久保留。页面没有电子木鱼，因此不绘制三环。
4. **滚动**：经文页默认跟随流尾；向上滑动回看已确认前文，向下滑回流尾。回看期间若有新有效敲击，追加后立即将视口锚回流尾。
5. **小程序**：只消费 backend 已确认序列；每字 append 一次，正文固定 17 槽且统一 18px；最新字使用 28px 焦点色，下划线同步移动到该字下方并持续存在；前缀、顺序和标点不被覆盖。
6. **高速/降动效**：1 秒 20 次时字符队列完整保留，三环动画不建立独立等待队列；减少动效偏好下跳过插值，直接呈现一次 flash 状态后恢复。

## State Patterns

**设备可呈现状态（设计帧须覆盖）**：`亮屏·主页`｜`熄屏`｜`首触唤醒`｜`充电中(输入暂停、可显示充电/电量/同步)`｜`低电量`｜`待校时`｜`同步:本地已记录/同步中/已同步/待同步/同步失败`｜`命令待设备应用`｜`故障锁定`｜`完成遮罩`；7字带子态 `空带占位/填充中/满带`；木鱼环 `idle/flash`；经文流 `流尾/回看`；当前诵读 `进行中/已完成`；四项信号各自 `connected/no-signal/disabled`。

**小程序可呈现状态**：`登录直达`｜`阅读·空心经等待设备诵读`｜`阅读·在线追加`｜`阅读·离线回放中(新事件排队)`｜`阅读·断线(查询/回放模式)`｜`阅读·完成100%`｜`独立完成弹窗`｜`空态:无历史/首登`｜`失败态:同步失败/队列已满/低电量/待校时/待设备应用/权限错误`；记录/设备/设置各自 `加载/空/失败/已刷新`。

> 闭包校验基线：以上状态清单逐帧落到 pen/HTML（Stage4），任一缺帧=未完成；每帧用 `data-pencil-name="[UI][PAGE][STATE…]…"` 标注。

状态建模优先级：**组件变体 > 整屏变体**。Pen 中相同页面骨架只保留一个 canonical screen，并用组件状态板承载局部变化；同名 HTML 由作者导出，除目标组件外结构保持一致。只有布局、信息架构或输入边界真实变化时才建立整屏变体。

**纯色/图标类瞬时反馈不进入状态建模**：三环金光（描边色）、信号与电量的颜色/图标切换、同步点色都属于运行时补丁，只登记规格（色值与时长）而不复制节点。设备侧状态对照板集中在母版区：`ZauNI`（7 字带与进度）、`Hlo77`（今日敲击 trusted/untrusted）、`fWCbZ`（同步五态）、`qLhoo`（状态栏 12 态）、`JZhSx`（三环 IDLE/FLASH）。

## Interaction Primitives

- 设备：左右滑三主页 · 下滑进设置 · PWR 短按(唤醒/循环) · 熄屏首触只唤醒 · 木鱼页点击=`device_touch`；经文页实体 `physical_pvdf` 仍可推进，普通屏幕触摸不计数；充电/遮罩/故障中任何输入忽略。
- 经文页：垂直滚动只浏览已确认/本地已记录的正文；设备页保持 13 槽，小程序页保持 17 槽；新字到达时追加到已有前缀后的下一个槽位并自动锚回流尾。
- 小程序：点击/滑动阅读行（仅查看）；下拉刷新设备/记录；按钮触发立即同步/重试/设置下发；WebSocket 断开自动切查询/回放。
- 时间：设备端「今日」在未校时前只显「待校时」；日界以 backend 配置时区为准（AD-6）。

## Accessibility Floor

- 对比：正文/底 ≥7:1（Stage3 实测校准）；强调色不作为唯一信息通道（同步态同时有点+文字/图标）。
- 字号：设备 glyph ≥ 大字号；小程序可调字体跟随系统；正文行高 1.7。
- 动效：三环金光固定 160ms、礼花短促；提供极简度偏好——减少动效时取消插值但保留一次状态确认，不做常驻动画（SM-C1）。
- 设备不支持屏幕阅读器（个人原型，作为已知边界记录）；小程序关键操作有可读 text，不用纯色块传达状态。

## Responsive & Platform

- 设备端固定 410×502 AMOLED 画布；不引入响应式重排，状态栏、7 字带和木鱼触区按 UI_CONTRACT-device 的净空执行。
- 小程序以 390×844 作为方向稿和对拍基线；内容区使用 20px 页面边距，底部导航保留 56px 高度及底部安全间距。实际微信设备只允许等比例缩放，不改变连续正文流与当前字聚焦语义。

## Inspiration & Anti-patterns

- **借鉴 legbot_watch**：只借鉴 resident shell、按需设置屏、纵向列表和组件状态补丁的组织方式；不搬运其外骨骼、支付或多设备业务。
- **保留**：设备 `DEVICE-01` 的三环短反馈、组件优先状态建模、经文 append-only 流，以及小程序 `MINI-06` 的连续正文与最新字下划线。
- **拒绝**：为单个颜色/数值新增整屏、预览未来经文、复制第二篇历史流、在小程序放置可点击木鱼，或以装饰背景包裹全帧。

## Key Flows

主角：Hongchenke（作者 / 诵经者）。下列流程名与 PRD UJ 同名，作为设计帧的“主角流程”覆盖依据。

### UJ-1 · 实体木鱼在线短诵
1. 设备亮屏；熄屏时实体敲击会唤醒设备。
2. 用木鱼棒敲 PVDF → 有效敲击确认。
3. 设备立即：字进入 7 字带；播放木鱼音；显示 160ms 三环金光；更新今日敲击与累计敲击。
4. （高潮）1 秒 20 次时：全计数、音频合并成节奏、7字带加速追平、不丢字。
5. 活动窗口内上报高水位；后端确认；小程序把新字追加到正文；状态从「同步中→已同步」。

### UJ-2 · 离线敲击并恢复
1. 4G 不可用或小程序未开，继续敲击。
2. 设备本地记录、7字带照常；状态栏显「待同步」。
3. 重启后本地高水位恢复，可离线续敲。
4. （高潮）网络恢复后补传；后端按差值推进一次；小程序按已确认差量顺序追加回放后接实时，已有正文前缀保持不变；漏/重/乱序 = 失败。
5. 未校时时「今日」显「待校时」，不把敲击错归某天。

### UJ-3 · 屏幕电子木鱼替代实体
1. 亮屏在木鱼页。
2. 点击电子木鱼 → 该次以 `device_touch` 进入同一有效队列。
3. （高潮）与实体敲击同一累计/经文/音频/同步链路，结果完全一致。
4. 边界：熄屏首触只唤醒；充电/完成遮罩/故障中不计数。

### UJ-5 · 经文页回看已诵内容

1. Hongchenke 切到经文页，屏幕默认停在当前轮次经文流尾。
2. 实体木鱼被监测到后，新可消费汉字追加到流尾，成为唯一以大字高亮的当前字；已有正文保持不变。
3. Hongchenke 向上滑动，回看此前已经敲出的正文；不出现未来字，也不生成第二篇历史副本。
4. 回看期间再次敲击，正文继续 append，视口自动回到流尾，让最新字重新成为屏幕焦点。
