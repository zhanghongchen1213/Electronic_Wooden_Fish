# 技术与体验验证附录

## 暂定设备状态

1. **低功耗待机**：无敲击时主控和 4G 模组尽量休眠，由振动事件唤醒。
2. **活动窗口**：识别到有效敲击后进入短暂活动状态，完成本地记录并尝试实时上报；活动结束后再次休眠。
3. **离线缓存**：无网络或上报失败时保留带设备序号和时间信息的事件。
4. **补传同步**：网络恢复后按序补传，后端按设备序号去重，小程序恢复到正确经文位置。

以上是待验证的工作模型，不是已经锁定的芯片或通信协议方案。

## 第一轮实体验证

购买 2～3 个不同尺寸的中空木鱼，分别验证：

- 电路板、电池、4G 天线和 Type-C 接口的可用空间；
- 木鱼棒敲击时振动传感器的信号强度和重复性；
- 手持、放置、装入包中和移动过程中的误触发情况；
- RGB 灯的可见性、散热、走线和外观影响；
- 外壳改造难度、重量和可携带性。

## 小程序第一版体验草案

- **诵经页**是默认入口，突出当前字、上下文、今日计数、进度和同步状态。
- **经文页**负责选择经文和断点续读，不在主页面塞入过多设置。
- **记录页**提供日/周/月趋势、连续天数、敲击次数和佛经字数。
- 设备电量、4G 状态、最后同步时间和待同步数量属于必要状态，放在设置或设备页。
- 同步状态至少区分：本地已记录、上传中、已同步、待补传、上传失败。

## 待在 PRD 中决定的规则

- 有效敲击的防抖窗口、连续敲击最小间隔和不同力度的识别阈值；
- 每个经文字符、标点、换行和段落如何消耗一次敲击；
- 经文结束后是暂停、循环、等待用户选择，还是自动进入下一部经文；
- 多设备或设备重置后的数据归属与进度恢复；
- 小程序打开时是否进入“实时会话”状态，设备是否需要获得该状态；
- 4G 协议采用 HTTP 还是 MQTT，以及设备身份、事件幂等和鉴权方式。
