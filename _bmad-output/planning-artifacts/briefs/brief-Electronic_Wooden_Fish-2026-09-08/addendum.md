## 3. 最终硬件合同

| 子系统 | 方案 | 状态与边界 |
| --- | --- | --- |
| 主控 | 标准 ESP32-S3-N16R8 模组 | 已决定；原生 USB-Serial-JTAG，不使用 CH340X |
| 4G/GPS | `main_control` 已验证的完整 Air780EGP 模组组件 | 已决定；4G 进入 MVP，GPS 默认关闭，主板只接模组接口 |
| 显示 | 410×502、CO5300、QSPI AMOLED | 已决定使用 `legbot_watch` 同款模组；FPC/电源/初始化仍受验证门禁约束 |
| 触摸 | CST9217 | 已决定；地址、坐标方向和中断极性按目标模组实测 |
| 实体敲击 | PVDF 压电薄膜 | 已决定为唯一 MVP 主传感器 |
| 唤醒与确认 | 低功耗比较器 GPIO 唤醒＋ESP32 ADC 二次确认 | 功能级锁定；比较器和模拟前端料号不提前冻结 |
| 音频 | ES8311＋NS4150B＋单声道扬声器 | 已决定；音效失败不得阻塞计数或同步 |
| 电量 | CW2015 | 已决定；共享 I²C，实际地址和电芯曲线需上电核验 |
| 状态灯 | 单路 RGB | 已决定；只表达敲击确认、待同步、低电量和故障 |
| IMU | QMI8658C | 已决定上板但默认不启用；只接 INT1，不参与 MVP 计数 |
| 电源 | 单节锂电池、USB-C、硬件 PWR、4G/3.3V/音频/AMOLED 分轨 | 功能级锁定；充电期间暂停输入与音频；具体 IC 和容量后续冻结 |

### 3.1 GPIO 基线

| 功能 | 信号 | ESP32-S3 GPIO | 约束 |
| --- | --- | ---: | --- |
| BOOT | BOOT0 | IO0 | 启动绑带；保留下载路径 |
| PWR | 运行态输入 | IO46 | 启动绑带；固件只读，长按开关机由板级电源完成 |
| RESET | EN | EN | 独立按键或测试点 |
| PVDF | ADC | IO9 | ADC1_CH8；前端必须限流、钳位并控制输入范围 |
| PVDF 唤醒 | 比较器数字输出 | IO11 | 低功耗 GPIO 唤醒；醒来后仍由 ADC 判断有效敲击 |
| 共享 I²C | SDA / SCL | IO1 / IO2 | CW2015、CST9217、ES8311、QMI8658C 共用 |
| CST9217 | TP_RST / TP_INT | IO38 / IO39 | 触摸复位与中断 |
| QMI8658C | INT1 | IO41 | 未来 WoM 扩展；INT2 不接 |
| CO5300 | RST / CS / SCL / D0 / D1 / D2 / D3 / EN | IO4 / IO40 / IO5 / IO6 / IO7 / IO12 / IO42 / IO47 | 沿用 `legbot_watch` 屏幕资源基线 |
| ES8311 | I2S_DO / WS / DI / BCLK / MCLK | IO13 / IO14 / IO17 / IO18 / IO21 | 沿用 `legbot_watch` 音频资源基线 |
| NS4150B | PA_EN | IO48 | 静音、暂停或故障时回到禁用状态 |
| Air780EGP | UART_TX / UART_RX | IO43 / IO44 | 从 `main_control` 协议驱动中抽离板级引脚常量 |
| Air780EGP | DTR / RST / NET_STATUS / GNSS_VCC | IO10 / IO15 / IO16 / IO8 | 保留模组休眠、复位、网络观测和 GPS 开关能力 |
| RGB | DATA | IO3 | 用户状态灯，不作为调试专用灯 |
| USB | D− / D+ | IO19 / IO20 | ESP32-S3 原生 USB-Serial-JTAG |

GPIO45 保持未连接或按 ESP32-S3 模组要求处理，不连接 QMI8658C。GPIO33–37 不作为通用 GPIO。该表是木鱼 BSP 的默认合同；若目标模组数据手册或原理图审计证明冲突，必须先更新架构和决策日志再调整。

## 4. 输入与反馈合同

### 4.1 正式输入源

- `physical_pvdf`：PVDF 比较器负责唤醒，ADC 波形负责确认。
- `device_touch`：只允许木鱼页电子木鱼点击生成正式敲击。
- 微信小程序不是敲击输入源，不显示可点击电子木鱼。

两类正式输入进入同一有效敲击队列，共享本地累计数、经文游标、完成锁定、音频、RGB、持久化与同步语义。不得维护两套计数路径。

### 4.2 熄屏与充电

- 熄屏时实体有效敲击直接计数并触发短亮屏。
- 熄屏时第一次触摸只唤醒，不计数；亮屏后的下一次电子木鱼点击才计数。
- USB-C 充电期间暂停实体和触摸敲击、经文推进及音频；屏幕仍可显示充电、电量和同步状态。

### 4.3 音频与 RGB

- 首次默认音量为 50/100；0 等价于静音，设置跨重启保留。
- 低速时一次有效敲击对应一次短木鱼音。
- 高速时计数全部保留，音频按短间隔重触发或合并为可辨识节奏，不允许 20 个完整样本无控制叠加。
- RGB 使用克制的颜色和占空比表达敲击确认、待同步、低电量和故障，不与主屏争夺注意力。

## 5. 设备屏幕合同

### 5.1 通用导航

- 主页由木鱼页、经文页、统计页组成，可左右滑动，页面不承载 BLE/Wi-Fi/GPS 业务。
- 顶部状态栏在三页常驻，固定显示电量/充电、4G、同步/待同步状态。
- 从主页下滑进入设置页；返回后保持原主页。
- PWR 短按：熄屏时唤醒；亮屏时按木鱼→经文→统计顺序循环。持续按住不生成软件关机动作。

### 5.2 木鱼页

- 电子木鱼是主视觉和唯一可计数触摸区域，点击一次生成一次 `device_touch` 输入。
- 经文带固定为 7 个可见字形位置，汉字和标点共同占位。
- 经文带只展示最近已经诵出的内容；新一轮开始时未填充位置使用低对比度占位，不预览未来文字。
- 每次有效敲击推进下一个汉字，新字从右侧进入，已有字整体左移，最左侧退出。
- 汉字之间出现的标点跟随相邻汉字在同一步自动插入，但正式敲击数只增加 1。
- 动画队列不得丢字。积压增长时缩短位移时间；积压清空后恢复正常节奏。
- 页面同时显示本轮进度和今日计数。同步未确认不阻塞本地动画，但状态栏必须标记同步中或待同步。

### 5.3 经文页与统计页

- 经文页显示大号当前字、少量前后文和本轮进度；MVP 不显示选经入口。
- 统计页只显示今日敲击数和累计敲击数；近 7/30 日与连续天数属于小程序。

### 5.4 设置页

- 亮度：低/中/高三档，默认中档。
- 自动熄屏：5 秒、15 秒、30 秒，默认 15 秒。
- 音量：0–100 滑块，默认 50。
- 立即同步：触发一次 4G 同步，并显示进行中、成功、待同步或失败。
- 小程序提供同一组设置。两端同时修改时，使用单调递增修订号，后写入者生效。

### 5.5 完成状态

- 《心经》末字确认后，设备和小程序显示完成反馈与“从头开始 / 退出”。
- 遮罩期间所有敲击输入均忽略，不增加本地或云端累计数。
- “从头开始”创建新轮次、游标回到首字，历史统计保留。
- “退出”保留完成状态和历史，离开当前诵经呈现。

## 6. 小程序合同

- 不显示电子木鱼，不产生敲击事件。
- 主体验是阅读行自动滚动与当前字聚焦；服务端每确认一个汉字，小程序按顺序显示一次。
- 动画落后时动态加速，不能跳过、合并正式字符或重复回放。
- 离线积压恢复后先按顺序快速回放，再接续实时新增；回放期间的新事件排队。
- 记录页显示今日、近 7 日、近 30 日、累计和连续天数。
- 设备页显示电量、4G 信号/注册、最后同步、待同步数量和失败状态，并控制与设备端相同的设置。
- 小程序命令先由 backend 持久化。设备处于在线活动窗口时，在下一次 HTTPS 响应中取得并按修订号应用；设备休眠或离线时，小程序显示“待设备应用”，不得冒充已经生效。

## 7. 4G 与数据合同

- MVP 唯一设备业务链路为 Air780EGP 4G；ESP32-S3 自带 BLE/Wi-Fi 在固件中不配置为产品通道。
- 复用 `/Users/hongchenke/Documents/Github/main_control/components/BSP/GPS` 的 AT、DTR、网络状态、HTTPS 单事务所有权和退避经验；不复制其 GPIO 常量。
- 设备通过 HTTPS JSON 上报 `local_total`、`acked_total`、经文版本、轮次/游标、命令修订号、电量、网络和固件状态。
- 敲击活动窗口内保持 PDP/HTTPS 上下文可复用；稳定网络下 95% 的有效敲击应在 1 秒内被小程序展示。
- 弱网或网络中断时继续本地累计。恢复后按累计高水位补传，后端按差值幂等推进，不依赖逐事件重放。
- 设备屏幕使用本地进度即时呈现；小程序只展示后端已确认进度。两者差异通过同步状态显式表达。
- backend 是日统计的权威，按配置时区切分日期。设备从 Air780EGP 网络时间或 HTTPS 响应取得可信日期；硬断电后尚未校时时，“今日”显示为“待校时”，不得把未知日期的敲击错误归入当天。

## 8. 参考项目边界

### 8.1 `legbot_watch`

可复用：CO5300/CST9217/CW2015/QMI8658C/ES8311/NS4150B BSP、共享 I²C 管理、LVGL 多主页、顶部状态栏、下滑设置、PWR 页面循环和亮屏首帧时序。

不可照搬：ML307R、BLE 业务、外骨骼页面、QMI8658C INT2→GPIO45 的板级合同、四主页数量和手表产品状态。

### 8.2 `main_control`

可复用：Air780EGP UART/AT、DTR 休眠与唤醒、网络注册/PDP、HTTPS JSON、超时恢复、GPS 开关和状态模型。

不可照搬：IO7/15/16/17/18/8 的原板引脚常量、外骨骼景区管理 payload、定位业务和 ESP-IDF v5.1.5 项目约束。

## 9. 验证门禁

### 9.1 硬件

- 检查 GPIO0/45/46 启动绑带、GPIO19/20 USB、模组保留脚和所有外设无冲突。
- 对 CW2015、CST9217、ES8311、QMI8658C 执行 I²C 扫描；具体地址只以目标物料和实板结果为准。
- 验证 PVDF 前端不会越过 ADC 输入范围，比较器可从低功耗状态可靠唤醒，携带和桌面振动不会大量误触发。
- 验证 Air780EGP 发射峰值下电源轨无掉压重启，并测量活动窗口、屏幕、音频和待机功耗。
- 验证 CO5300 初始化、首帧、三档亮度、熄屏/唤醒、CST9217 坐标和 7 字动画刷新。
- 验证 ES8311/NS4150B 的木鱼音、音量 0/50/100、高速合并节奏和扬声器腔体。

### 9.2 产品与软件

- 分别以实体敲击和设备点击执行单次、慢速连续和 1 秒 20 次输入，最终计数与经文完全一致。
- 断网、重复 HTTPS、设备重启和 backend 重启后，累计高水位、游标、轮次和历史统计正确。
- 稳定网络样本中至少 95% 的敲击在 1 秒内出现在小程序；不达标时记录设备落盘、4G、HTTPS、backend 和 WebSocket 分段耗时。
- 完成遮罩、从头开始、退出、充电暂停、熄屏首触和 PWR 页面循环均按合同工作。
- 小程序离线回放和实时新事件并发时不漏字、不重字、不乱序。
