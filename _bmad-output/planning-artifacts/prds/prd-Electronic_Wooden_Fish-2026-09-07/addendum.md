# 电子木鱼 PRD 附录

本附录保留适合下游 UX、架构和原型验证，但不应被误读为已锁定实现的内容。

## 1. 市场调研记录

### 1.1 检索边界

本次轻量检索关注完整组合：实体木鱼棒击/振动识别、设备独立联网（尤其 4G）、小程序或应用把每次敲击按顺序映射到经文字符、离线事件缓存/恢复补传/去重、历史统计。结论仅适用于公开可检索的一手或官方页面，不宣称绝对不存在未公开产品，也不推断市场规模。

### 1.2 完全匹配

截至 2026-09-07，未找到公开可核验、同时满足上述完整组合的市售产品。

- [Dhikr Tracker / Tasbih](https://tasbihapp.com/)：支持触觉点按、离线计数、历史/连续天数、云同步和 BLE 实体念珠，并提供 Maker Mode；不是木鱼输入，不是 4G 独立设备，也没有“一敲一字”经文游标。
- [Kliqit / JapBuddy](https://www.kliqit.io/)：支持离线计数、自动云同步、统计和 BLE 实体计数器；必须以手机为中继，按 mantra 次数计数，不是振动棒击和逐字经文。

- [智能木鱼专利 CN106020455A](https://patents.google.com/patent/CN106020455A/zh)：提出振动传感、处理器/存储、RF 和灯光模块，面向联网特效；是先前技术/概念，不是当前个人市售完整产品，需在后续专利边界检查中参考。
- [立创开源电子木鱼](https://oshwhub.com/oldtreee/dian-zi-mu-yu)：敲击可模拟键盘输出《心经》，但无蜂窝联网、离线队列、云端统计和微信小程序。

### 1.5 对 PRD 的影响

需求仍有意义，真正的差异化不是“电子木鱼”或“计数”单点，而是完整可靠链路：**真实木鱼动作 → 事件序号 → 手机关闭仍记录 → 蜂窝/断网补传 → 经文逐字推进 → 历史可回看**。需要把“未检索到完全匹配”作为有边界的研究发现，不作为市场规模或商业成功承诺。

## 2. 技术与体验工作模型（非锁定）

推荐先验证以下最小闭环：

1. 低功耗待机。
2. 振动唤醒并在活动窗口中完成防抖、有效敲击判断。
3. 事件先本地落盘，再尝试 4G 上传。
4. 离线事件携带设备序号和时间，恢复后按序补传。
5. 服务端以设备身份 + 事件序号幂等去重。
6. 小程序依据已接受事件恢复经文游标和同步状态。
7. 设备回到休眠，RGB 只在有效敲击时短暂反馈。

体验基线：单次不超过 3 分钟、每天不超过 10 次、每日总使用时长不超过 30 分钟；当前字点亮并适度放大，RGB 用柔和呼吸和少量状态色表达有效敲击、联网、低电量和待同步，诵经页避免统计信息喧宾夺主。

协议（HTTP/MQTT）、芯片、缓存介质、鉴权方式和固件升级方式均未锁定。

## 3. 第一轮原型验证

### 3.1 结构与功耗

- 购买 2–3 个不同尺寸的中空木鱼，记录板、电池、天线、Type-C 的容积、重量、散热和安装难度。
- 测量待机、振动唤醒、4G 注册、单次上报和补传的功耗，验证“一天”目标，不以手机小程序打开作为省电前提。
- 以单次≤3分钟、每天≤10次、每日总时长≤30分钟作为初始负载，分别记录待机、唤醒、注册、上报和补传功耗。

### 3.2 识别与误触

- 为轻、中、重三档有意敲击建立样本，测量召回率、重复计数和连续敲击最小间隔。
- 模拟拿取、放下、包内携带、桌面移动和邻近振动，记录误触事件。
- 在地铁通勤和包内移动场景中重复测试，并记录信号强度/波形重复性、外观影响、改造难度、重量和便携性。
- 依据数据冻结力度阈值、防抖窗口和活动窗口，而不是先凭感觉锁死。

### 3.3 同步与游标

- 在在线、断网、断电重启、重复上报、部分补传和服务端拒绝条件下验证事件不丢失、不重复、按序推进。
- 验证小程序关闭再打开、切换经文和经文结束自动切换后的显示与统计。
- 固定统计窗口为“日、近7日、近30日”，避免“周/月”口径漂移。

## 4. 待决机制

| 主题 | 当前方向 | 待决原因 | 负责人 / 冻结时点 |
| --- | --- | --- | --- |
| 经文结束 | 自动切换；MVP 单部心经循环 | 多经文“下一部”顺序和提示方式尚未明确 | 创作者 / 扩展第二部经文前 |
| 传输协议 | 4G 活动窗口内上传 | HTTP/MQTT 的功耗、重试和服务端成本需实测 | 创作者 / 同步闭环实验前 |
| 账号绑定 | 单设备、单微信账号 | 重置、换设备和历史数据归属需定义 | 创作者 / 服务端联调前 |
| 纠错 | 先保证事件可靠，再考虑人工校正 | 误触率和校正会不会破坏“一敲一字”需观察 | 创作者 / 首轮识别实验后 |
| 固件升级 | MVP 不做自动 OTA | 升级期间如何保护待同步事件尚未定义 | 创作者 / 首次 OTA 需求出现前 |
