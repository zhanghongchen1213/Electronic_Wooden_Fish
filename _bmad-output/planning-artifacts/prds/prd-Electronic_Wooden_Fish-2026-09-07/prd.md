# PRD：电子木鱼

## 0. 文档目的与权威边界

本 PRD 是电子木鱼的产品行为权威，供 Embedded、cloud、UX、架构和后续 Epic/Story 工作使用。产品只分为两个层：**Embedded 嵌入式层**与 **cloud 软件层**。`cloud/backend` 和 `cloud/frontend` 是 cloud 层的实现目录，不是两个产品层。

本 PRD 定义愿景、用户旅程、功能需求、跨层合同、并行开发边界、成功指标和验收口径，不重复芯片数据手册、原理图逐脚接线或具体代码实现。实现时按以下顺序取事实：硬件定稿与网络清单 → 两份 Pen/HTML → UX 合同与架构主干 → 两侧 AGENTS → 现有迁移代码。

本文关联资料：

- 硬件：`docs/hardware/定稿/`、`docs/hardware/电子木鱼-硬件网络清单.json`、`docs/hardware/电子木鱼-硬件原理图设计基线.md`。
- Embedded 视觉：`Embedded/lvgl-design/ewf-device-ui.pen` 与 `Embedded/lvgl-design/ewf-device-ui-export.html`。
- cloud 视觉：`cloud/miniapp-design/ewf-miniapp-ui.pen` 与 `cloud/miniapp-design/ewf-miniapp-ui-export.html`。

本项目是个人开发原型，只维护一台设备和一个固定 cloud 实例，不设计量产认证、多设备迁移、复杂账号、CI/CD 或云运维体系。

## 1. 产品愿景

电子木鱼把实体木鱼棒的触感、设备屏幕里的电子木鱼、木鱼音、经文逐字推进和可回看的数字记录连接起来。用户不需要先打开手机，实体敲击即可在设备上产生即时反馈；cloud 随后把已确认的经文进度和历史记录呈现在微信小程序中。

产品首先服务于创作者本人，是一个可以持续使用的个人原型，而不是一次性演示或待量产的消费电子产品。核心价值是“一敲一字”在物理动作、视觉节奏、声音反馈、离线记录和历史积累之间形成连续闭环。

MVP 固定使用《般若波罗蜜多心经》。实体 PVDF 敲击和设备触摸电子木鱼属于同一正式输入模型；微信小程序不产生正式敲击，只负责呈现 cloud 已确认的经文、统计和设备设置。

## 2. 产品边界与层间责任

```text
Embedded 嵌入式层
  BSP 驱动、有效输入、低功耗唤醒、本地累计、屏幕/触摸、音频、RGB、电源、4G、本地持久化和设备 UI

cloud 软件层
  cloud/backend：身份、JSON 持久化、高水位幂等、经文轮次、统计、命令和实时通道
  cloud/frontend：微信登录、经文阅读流、离线回放、记录、设备状态和设置镜像
```

- Embedded 负责判断 `physical_pvdf`、`device_touch` 和 `automatic_tap` 三类正式输入，先本地落盘并反馈。
- cloud 负责确认累计高水位、经文游标、轮次完成、历史统计和设备命令状态。
- cloud/frontend 只呈现 cloud 已确认的正式进度；设备可展示带“同步中/待同步”标记的本地即时镜像。
- 小程序关闭或设备离线时，设备继续本地记录；恢复后按累计高水位同步。
- Embedded Epic 1–3 与 cloud Epic 4–6 可独立并行推进；只有 Epic 7 在 HTTPS、命令应用、状态收敛和端到端验收时同时修改两层。
- BLE、Wi‑Fi 和 GPS 只可作为设备状态组件或硬件保留能力，不进入 MVP 业务链路。
- `FR-E-*` 表示 Embedded 需求，`FR-C-*` 表示 cloud 需求。backend/frontend 目录归属不改变需求层级。

## 3. 目标用户与关键旅程

### 3.1 目标用户

主要用户是 Hongchenke：具备机械设计、硬件电路、ESP32 固件、后端和 uni-app 开发能力，希望做一个自己愿意反复使用的桌面/便携原型。

MVP 不面向量产消费者、多人共修、社交用户或需要多设备管理的用户。

### 3.2 UJ-1：Hongchenke 用实体木鱼完成在线短诵

- **进入：** 设备已开机，小程序可打开也可关闭；设备处于待机或活动窗口。
- **路径：** Hongchenke 用木鱼棒敲击；PVDF 唤醒并确认有效事件；设备立即显示、发声、点亮 RGB、更新本地累计；Air780EGP 在活动窗口内通过 HTTPS JSON 同步。
- **高峰：** 1 秒内连续 20 次时，所有事件都计数，设备音频限速合并，木鱼页 7 字带动态加速追平。
- **结果：** backend 按累计高水位幂等推进经文；小程序在稳定网络目标内逐字聚焦显示。

### 3.3 UJ-2：Hongchenke 离线敲击并恢复

- **进入：** 小程序关闭、4G 不可用或设备尚未校时。
- **路径：** 设备继续本地累计、显示和反馈；状态栏显示待同步；设备重启后恢复本地高水位。
- **恢复：** 网络恢复后补传当前累计数；backend 只按差值推进一次；小程序按已确认差量顺序回放。
- **结果：** 不漏字、不重字、不乱序；若设备尚未取得可信日期，今日统计显示“待校时”而不是错误归档。

### 3.4 UJ-3：Hongchenke 用屏幕电子木鱼替代实体敲击

- **进入：** 屏幕亮起并位于木鱼页。
- **路径：** 点击电子木鱼；该点击作为 `device_touch` 进入与 PVDF 相同的有效敲击队列，推进当前诵读、播放音频并更新 7 字带。
- **边界：** 屏幕熄灭时第一次触摸只唤醒；完成遮罩中和故障锁定中不计数。主控不检测充电状态，因此 USB-C 外部供电、电池供电和外部供电并充电时均沿用同一功能路径，不暂停输入、经文、音频或同步。
- **结果：** 设备触摸和实体敲击产生同一份本地累计、同步状态和历史结果。

### 3.5 UJ-4：Hongchenke 完成《心经》并开始新轮次

> 说明：UJ-4 是 UJ-1 在单轮《心经》耗尽后的完成态分支场景，不是并列的独立旅程。

末字确认后，设备立即进入完成锁定；小程序收到 backend 确认后显示完成反馈和弹窗。遮罩期间所有输入忽略。“从头开始”创建新轮次并把游标回到首字；“退出”保留完成状态和历史统计。

### 3.6 UJ-5：Hongchenke 用 BOOT0 开关自动敲击

- **进入：** 设备处于开机运行态，短按并释放 BOOT0（GPIO0）。
- **路径：** 设备切换到自动模式，每 3 秒生成一次内部自动敲击事件；事件进入与实体敲击、设备触摸相同的有效敲击队列，按同一逻辑完成经文、音频、RGB、设备 UI、本地持久化和 cloud 同步，UI 同步呈现自动模式状态和真实敲击变化。
- **退出：** 用户再次短按并释放 BOOT0 后停止生成后续自动事件；已经进入队列的事件按统一队列完成，不补发、不回滚。
- **边界：** 自动模式只存在于开机运行态，不跨重启持久化，不改变关机态的 PWR/BOOT0 下载路径；不检测充电状态，任何供电状态均可使用。
- **结果：** 自动敲击与真实敲击共用累计、经文、音频、RGB、持久化、同步和历史口径，不产生独立计数。

## 4. 术语表

- **Embedded**：设备固件与硬件行为所在层，负责驱动、正式输入、设备 UI、音频、电源、4G 和本地持久化。
- **cloud**：软件层，包含 `cloud/backend` 与 `cloud/frontend` 两个实现目录，负责权威状态、同步、统计、命令和小程序呈现。
- **有效敲击**：Embedded 确认并写入本地累计的一次正式输入，来源可以是 `physical_pvdf`、`device_touch` 或 `automatic_tap`。
- **自动模式**：开机运行态下由 BOOT0 短按切换的临时模式，按固定 3 秒周期生成自动敲击事件，再次短按退出。
- **自动敲击事件 `automatic_tap`**：由 Embedded 定时器生成、但按真实敲击相同路径处理的内部有效敲击事件；其数量并入 `local_total`/`acked_total`，不新增独立累计字段或 cloud 同步接口。
- **本地累计数 `local_total`**：设备已经确认的有效敲击总数，掉电后仍可恢复。
- **已确认累计数 `acked_total`**：cloud 已按设备身份和累计高水位接受的总数。
- **离线积压**：`local_total` 高于 `acked_total` 的差值。
- **经文游标 `round_cursor`**：当前轮次下一个待消费的《心经》汉字位置。
- **轮次 `round_state`**：当前《心经》循环的进行中或已完成状态。
- **命令修订 `command_revision`**：设备设置或篇章命令的单调递增版本。
- **可信时间**：设备从 Air780EGP 网络时间或 HTTPS 响应取得、可用于当天统计的日期依据。
- **在线活动窗口**：设备因敲击、同步或控制进入的有限 4G 通信时间段。
- **待设备应用**：cloud 已保存小程序命令，但设备尚未在下一次 HTTPS 活动中取得并执行。
- **canonical《心经》**：三端共享的唯一可消费汉字序列及其 `scripture_version`。

## 5. 嵌入式层功能需求（Embedded）

本节只定义产品行为；驱动落图和引脚事实以 `docs/hardware/定稿/`、`docs/hardware/电子木鱼-硬件网络清单.json` 与硬件原理图基线为准。现有迁移代码只作为可保留候选，不能覆盖定稿事实。

### 5.1 FR-E-001：电源、充电与复位

设备支持单节锂电、USB-C 外部供电/充电、PWR 按键（接收 LTC2954 `PWR_INT`）、BOOT0 下载控制和 EN 复位测试点。本文所称“同时充电”是指 USB-C 外部供电且电池正在充电；主控不检测充电状态，产品不建立“充电中”分支。USB-C 外部供电、电池供电和外部供电并充电时，输入、经文推进、音频、显示、持久化和同步均保持可用。

**验收：** 在 USB-C 外部供电、电池供电和外部供电并充电三种条件下，输入、经文、音频、显示、持久化和同步均可正常使用；已持久化的累计数和轮次在重启后恢复；下载流程仍为 BOOT0 保持低电平后长按 PWR 上电，运行态 BOOT0 短按只切换自动模式，不改变下一次下载流程。

### 5.2 FR-E-002：PVDF 与低功耗唤醒

PVDF 是唯一 MVP 实体输入。低功耗比较器输出唤醒信号，ESP32 ADC 对信号做二次确认；QMI8658A 上板但默认不启用，仅作未来扩展预留，不参与 MVP 主计数。

**验收：** 目标外壳和安装结构下，单次与连续敲击能稳定生成候选信号；携带、取放和普通环境振动的误触发率以目标外壳演示签收判定（见 §12.1 验收方式）；ADC 输入不越界。

### 5.3 FR-E-003：统一有效敲击队列

实体 PVDF、亮屏电子木鱼点击和 `automatic_tap` 都进入同一个有效敲击队列，支持 1 秒内 1–20 次输入；完成遮罩和故障锁定期间直接忽略。

**验收：** 三类输入的累计、经文、音频、RGB、持久化和同步结果完全一致；1 秒 20 次不出现明显漏记或重记（以连续多组 20 次/秒演示签收判定，见 §12.1 验收方式）；完成遮罩期间累计不增加；不存在因供电/充电状态而拒绝输入的分支。

### 5.4 FR-E-004：本地高水位与离线积压

设备持久化 `local_total`、`acked_total`、`round_id`、`scripture_version`、`round_state`、`round_cursor`、`pending_completion`、待同步事件段和 `action_id`；查询/回放侧保存 `snapshot_seq`、`replay_cursor`。自动模式运行态只存在内存，掉电或重启后默认关闭；离线积压上限为 1000 次。

**验收：** 网络关闭、小程序关闭或设备重启时仍可记录；掉电恢复后 `local_total`、`round_id`、`round_cursor`、`round_state` 与 `pending_completion` 不互相矛盾；重复同步不重复计数；达到上限时实体、触摸和自动输入均按同一规则拒绝并明确提示。

### 5.5 FR-E-005：核心音频反馈

设备使用 ES8311＋NS4150B＋扬声器输出木鱼音，默认音量 50/100，音量 0 等价于静音；高速连击限速合并声音。

**验收：** 音频失败不阻塞计数、持久化和同步；音量设置跨重启保留；1 秒 20 次不会叠加成不可辨识噪声（听感以样机演示签收判定，见 §12.1 验收方式）。

### 5.6 FR-E-006：设备屏幕与三主页

AMOLED 提供木鱼页、经文页、统计页和下滑设置页。屏幕四周保留 110px 圆弧；顶部状态栏左侧依次展示 4G、Wi-Fi、蓝牙、GPS 四个信号组件，分别支持有信号、无信号、关闭/未启用状态，右侧使用电池符号和百分比展示电量，不展示主控无法确认的充电状态。Wi-Fi、蓝牙、GPS 仅表达设备状态，不改变 MVP 只有 Air780EGP 4G 业务链路的边界。

木鱼页固定 7 个字形位置，最近已诵字左移、新字从右侧进入，只呈现最近已诵内容，空位以低对比度占位，不预览未来经文；标点随相邻字出现但不消耗敲击。页面显示“心经进度”字数、总可消费字数和百分比，以及“今日敲击 N 次”和“累计敲击 M 次”。设备即时进度可含本地尚未确认的新字，须以“待同步/同步中”状态标记。“当前诵读”指从 canonical《心经》首字推进到末字的一次完整诵读；总字数由后续同步契约与实现阶段的 canonical 产物确定，7 字窗口不是字数上限。到达末字后进度保持 100%，进入完成锁定；选择“从头开始”创建新的诵读周期，历史保留。

经文页以大号当前字配合少量已确认前后文展示心经进度；统计页显示今日敲击数与累计敲击数，近 7 日、近 30 日与连续天数由软件层小程序的记录页承担。

**验收：** 7 字带在慢速和 1 秒 20 次输入下不丢字、不预览未来经文；设备页可见 4G/Wi-Fi/蓝牙/GPS 有/无/关闭状态与电池符号+百分比，且无充电状态依赖；心经进度同时显示字数和百分比；今日与累计敲击均可辨识；未校时显示“待校时”；熄屏实体敲击短暂亮屏；三页和设置页均可恢复。

### 5.7 FR-E-007：触摸与 PWR 导航

CST9217 支持左右滑动三主页、下滑设置、设置控件、完成弹窗和电子木鱼点击；只有木鱼页的电子木鱼点击产生 `device_touch` 正式敲击，经文页、统计页与设置页的触摸不计数。熄屏首次触摸只唤醒；PWR 短按负责唤醒或循环三页，BOOT0 短按负责切换自动模式，长按不由固件模拟关机。设置页提供三档亮度（默认中档）、5/15/30 秒自动熄屏（默认 15 秒）、0–100 音量（默认 50）和立即同步。

**验收：** 触摸不绕过完成锁定、不清除历史；非木鱼页触摸不产生敲击；每次 BOOT0 短按只切换一次自动模式，模式中每 3 秒生成一次自动敲击，再次短按停止后续生成；自动模式不跨重启持久化；亮度、熄屏、音量和立即同步设置跨重启保留。

### 5.8 FR-E-008：Air780EGP 4G 活动窗口

MVP 只使用 Air780EGP 4G HTTPS JSON。设备在实体敲击、设备触摸、自动敲击、立即同步或待应用命令窗口内复用通信上下文；不配置 BLE/Wi‑Fi 产品链路。GPS 保留控制能力但默认关闭。供电或充电状态不改变通信、输入或同步路径。

**验收：** 稳定网络下端到端目标 SM-3（95% 有效敲击在 1 秒内被小程序展示）成立，本 FR 的设备→backend 上报环节不得单独突破该端到端口径；弱网时本地继续记录，恢复后补传；Air780EGP 发射峰值不引发掉压重启。

### 5.9 FR-E-009：状态与低打扰反馈

设备通过 CW2015、RGB、AMOLED 和音频表达电量、4G、同步、待应用、低电量、有效敲击、自动模式和故障状态；不表达主控无法确认的充电状态。

**验收：** 各状态可由对应通道辨识并在样机上可演示；自动模式状态与真实敲击反馈一致且可识别；低电量与故障有明确、低打扰的呈现，不打断诵经节奏；不存在依赖充电检测的反馈或功能分支。

### 5.10 FR-E-010：USB-Serial-JTAG

设备使用 ESP32-S3 原生 USB-Serial-JTAG 完成烧录、CDC 日志和 JTAG 调试，不使用 CH340X 或 USB-OTG 业务。

**验收：** 上电后 PC 可识别 USB CDC 并完成烧录与日志输出；同一 USB 口不启用 USB-OTG；不依赖 CH340X。

### 5.11 FR-E-011：BOOT0 自动模式

开机运行态下，用户短按并释放 BOOT0（GPIO0）时，设备进入自动模式；按下/释放必须经过去抖，只有运行态中的完整短按才生效，长按、抖动、启动采样窗口内的电平和下载流程中的 BOOT0 均忽略。自动模式以短按释放被确认的时刻为周期锚点，每 3 秒生成一次 `automatic_tap`，并按真实敲击相同路径完成输入确认、经文推进、音频、RGB、设备 UI、本地持久化和 cloud 同步。用户再次短按并释放 BOOT0 时，设备退出自动模式并停止生成后续事件。

**验收：** 每次 BOOT0 短按只产生一次进入或退出切换；按键去抖、长按和启动/下载电平测试不产生误切换；自动模式事件按 3 秒周期生成，连续 10 个周期的单周期误差不超过 ±100 ms，不重复、不补发；退出切换与周期到期并发时按同一事件队列顺序处理，退出后不生成新的自动事件，但已入队事件完成统一处理；完成锁定、故障锁定或队列已满时不绕过对应 gate；自动模式中的 UI 变化、累计、经文、音频、RGB、持久化、同步和历史结果与真实敲击一致；自动模式可在木鱼页之外保持运行并在返回后正确呈现状态；到达完成锁定时停止自动模式并清除定时器，新轮次需再次显式启用；模式不跨重启持久化；USB-C 外部供电、电池供电和外部供电并充电时均可使用；不改变 BOOT0 下载路径。

## 6. cloud 软件层功能需求（cloud）

cloud 是一个统一的软件层，包含 `cloud/backend` 与 `cloud/frontend` 两个实现目录。它们在实现上分别承担服务端和微信小程序职责，但在产品需求、Epic/Story 分组和验收口径上属于同一层。cloud 是经文进度、设备状态、历史统计和命令状态的服务端权威；小程序只呈现 cloud 已确认的数据，不把本地待同步数据伪装成正式进度。

### 6.1 身份、经文和状态权威

#### 6.1.1 FR-C-001：单身份单设备

cloud 将唯一微信身份映射到一台固定设备。MVP 不提供多设备、解绑、换机迁移或公开账号治理。

**验收：** 同一微信身份始终绑定同一台设备；不同身份不共享设备高水位与统计；页面不出现绑定、迁移或多设备治理入口。

#### 6.1.2 FR-C-002：固定经文版本

cloud、Embedded 和小程序使用同一版固定《般若波罗蜜多心经》可消费汉字序列与 `scripture_version`。canonical 文本只允许一个落盘来源，三端通过构建或打包流程嵌入/生成。

**验收：** 任一参与方版本不一致时停止推进并报告配置错误；不做自动映射、选经或导入。

#### 6.1.3 FR-C-003：经文游标与轮次

Embedded 在本地候选推进 `round_id`/`round_cursor`，cloud 维护并确认已接受的轮次状态、游标和完成锁定；cloud 不按经文长度盲推游标，而是校验设备上报的轮次边界后记录确认结果。标点、空格和换行随相邻汉字出现，不单独消费敲击。

**验收：** 重复或乱序提交不造成跳字、重字或游标回退；每次有效敲击最多推进一个可消费汉字。

#### 6.1.4 FR-C-004：完成、从头开始与退出

末字确认后进入完成锁定；“从头开始”创建新轮次并把游标回到首字；“退出”保留完成状态和历史统计；完成锁定期间任何输入不计数。

**验收：** 只有收到完成确认后才进入完成态；新轮次不清除旧篇章和累计统计；锁定期间没有新字符或计数。

#### 6.1.5 FR-C-005：历史统计与可信时间

cloud 提供今日、近 7 日、近 30 日、累计和连续天数。离线差量按 cloud 确认日期归档；连续天数以配置时区内存在已确认敲击计算；设备无可信日期时不伪造当天统计。

**验收：** 统计只来自 cloud 已确认数据；离线差量按确认日期归档；无可信日期时设备显示“待校时”，cloud 不生成错误的当天记录。

#### 6.1.6 FR-C-006：状态查询与恢复基准

cloud 为设备和小程序提供带单调序号的状态快照、差量和恢复基准。小程序断线后以查询响应冻结的快照水位补齐，不能以自身展示计数推断权威状态。

**验收：** 查询和实时推送在同一快照水位上收敛；序号出现空洞时先查询补齐；恢复后不重复已展示字符。

### 6.2 同步、命令和持久化

#### 6.2.1 FR-C-007：高水位幂等同步

cloud 接收 `local_total`、`acked_total`、`round_id`、`round_cursor`、`round_state` 和设备状态，按设备身份比较累计高水位，只对高于已确认值的差量确认一次，并返回最新确认高水位、差量和轮次状态。

**验收：** 重复提交相同或更低高水位不增加计数；响应可被 Embedded 与小程序用于对账；高水位冲突返回明确业务错误。

#### 6.2.2 FR-C-008：命令修订与待设备应用

cloud 保存音量、亮度、熄屏时长、立即同步和篇章命令的最新 `command_revision`。设备离线时显示“待设备应用”；设备在下一次 HTTPS 活动中取得并应用新修订，随后回传已应用修订，旧修订不得覆盖新修订。

**验收：** 多次离线修改最终只保留最新修订；设备应用修订后状态收敛为“已生效”；重复获取或回传命令均幂等。

#### 6.2.3 FR-C-009：实时推送与断线补齐

cloud 通过 WebSocket 推送已确认差量、当前字、游标、轮次、完成状态、同步状态和设备状态；连接断开时使用查询/回放路径补齐，恢复后继续消费新序号。

**验收：** 断线期间不丢失已确认差量；重连只补齐未展示内容；WebSocket 与查询结果一致。

#### 6.2.4 FR-C-010：JSON 文件持久化

cloud 以单实例单进程运行，使用临时文件、`fsync` 和 `rename` 原子落盘，在 `cloud/backend/data/` 保存身份、高水位、游标、轮次、命令、设备状态和统计，不引入任何数据库服务。

**验收：** 进程重启后全部状态恢复；写入中断不会留下半写状态；仓库和运行环境不依赖 SQLite、PostgreSQL 或其他外部数据库。

#### 6.2.5 FR-C-011：统一接口、鉴权和错误语义

cloud 对外接口统一使用 `/api/v1` 和 `{code,message,data}` 信封；成功 `code=0`，业务错误保持 HTTP 200 并通过业务码表达，协议错误使用对应 HTTP 状态。微信登录、令牌刷新和设备身份校验遵循单身份单设备模型。

**验收：** 所有公开接口返回统一信封；并发 401 只触发一次刷新，刷新失败能唤醒所有等待请求并回到登录入口；敏感会话信息不写入日志。

### 6.3 微信小程序体验

#### 6.3.1 FR-C-012：登录直达唯一设备

小程序登录后直接进入唯一设备，不提供绑定、迁移和多设备治理流程；权限失败提供明确重试动作。

**验收：** 首次登录、重复登录和权限失败均有对应状态；登录成功不经过不存在的设备选择页。

#### 6.3.2 FR-C-013：心经持续阅读流

小程序主界面完全依据 `cloud/miniapp-design/ewf-miniapp-ui.pen` 与 `ewf-miniapp-ui-export.html` 复刻为持续累积的《心经》阅读纸面。正文只追加 cloud 已确认汉字，已有前缀不覆盖、不清空；每行保持 17 个字符槽，标点计槽；当前字只聚焦已确认内容。

**验收：** 页面没有可点击电子木鱼；正文按确认顺序逐字追加；未来经文不预览；只显示一组心经进度、百分比与进度条。

#### 6.3.3 FR-C-014：在线逐字动画

每个 cloud 已确认汉字按顺序追加并展示一次；已有内容持续可见；队列积压时动态加速，但不得跳过、合并或重复字符。最新字使用 Pen/HTML 规定的焦点样式和下划线。

**验收：** 每个确认字符恰好消费一次；队列清空后恢复基线节奏；渲染环节不单独突破端到端实时性目标。

#### 6.3.4 FR-C-015：离线积压回放

小程序重新打开或断线后，按 cloud 差量顺序回放；回放期间的新事件排队，回放结束后无缝接入实时动画。

**验收：** 回放不跳字、不重字、不乱序；回放期间产生的新事件不会插入旧差量中。

#### 6.3.5 FR-C-016：完成反馈

收到 cloud 完成确认后保留全文和 100% 进度，显示短促礼花与“从头开始/退出”弹窗；待确认时不提前声称完成；弹窗期间不展示新推进。

**验收：** 完成弹窗只由确认状态触发；从头开始创建新 `round_id`；退出保留已完成篇章和历史统计。

#### 6.3.6 FR-C-017：记录、设备和设置页面

小程序提供记录页、设备页和设置页。记录页显示今日、近 7 日、近 30 日、累计和连续天数；设备页显示电量、4G、最后同步、待同步、待设备应用和失败状态，不展示主控无法确认的充电状态；设置页镜像音量、亮度、熄屏时长，并通过 cloud 下发命令。

**验收：** 三页完全按 Pen/HTML 视觉和状态闭包复刻；设备页不依赖或伪造充电状态；设置提交后显示“待设备应用”，收到已应用修订后才显示“已生效”；刷新、立即同步和重试可重复执行。

#### 6.3.7 FR-C-018：空态、失败态和权限态

小程序覆盖首次登录、无历史、离线、同步失败、队列已满、低电量、待校时、待设备应用、篇章完成和权限错误。每种状态使用产品状态短句和可执行动作，不展示实现说明。

**验收：** 每种状态有可见且可操作的页面；本地待同步数据不混入正式进度、记录和统计；页面不出现 AI 思维链、Node ID、TODO、draft 或 placeholder。

#### 6.3.8 FR-C-019：视觉真源对拍

小程序实现必须以 `cloud/miniapp-design/ewf-miniapp-ui.pen` 为视觉真源，以同名 HTML 为对拍基线；不从历史候选稿或迁移项目复制页面结构。

**验收：** 登录、阅读、记录、设备、设置和完成弹窗的布局、令牌、字体、状态文案和导航触区通过逐屏对拍；HTML 与 Pen 的页面边界和卫生检查通过。

## 7. 跨层同步合同

统一字段：`device_id`、`local_total`、`acked_total`、`round_id`、`scripture_version`、`round_state`、`round_cursor`、`pending_completion`、`command_revision`、`battery_percent`、`network_mode`、`audio_config_version`、`firmware_version`、`snapshot_seq`、`replay_cursor`。设置与篇章动作使用 `action_id` 去重；自动模式只作为 Embedded 的临时运行态，不作为独立 cloud 字段持久化。

统一事件来源：`physical_pvdf`、`device_touch`、`automatic_tap`。`automatic_tap` 由 Embedded 内部生成，进入与真实敲击相同的有效队列；其数量并入 `local_total`/`acked_total`，不新增独立的 cloud 计数或同步字段。统一状态：本地已记录、同步中、已同步、待同步、同步失败（累计同步状态）与待设备应用（命令下发状态，不与累计同步状态并列）。

字段与状态语义以 `docs/contracts/sync-contract.md` 为准，不在嵌入式层/软件层文档中重复定义；`scripture_version` 等仅在此出现的字段，其权威定义同样在该合同，详见 §4 术语表末条。

跨轮次与恢复边界必须遵循以下不变量：

- 离线差量按 `round_id` 分段提交；无法归属轮次或缺少基准高水位时拒绝确认，不把一个累计高水位盲推到新轮次。
- 设备本地到达末字但 cloud 尚未确认时进入 `pending_completion`；完成确认前不得创建新轮次。“从头开始”使用幂等 `action_id`，重复请求返回同一 `round_id`。
- 设备应用命令时原子写入字段和 `applied_revision`；只有 `applied_revision == current_revision` 才显示“已生效”。设置命令与立即同步/篇章动作分别使用可重放的 `action_id`，不能互相覆盖。
- 查询快照返回 `snapshot_seq`，WebSocket 从 `snapshot_seq + 1` 续订；`seq <= last_applied_seq` 丢弃，出现空洞先查询补齐。小程序回放持久化 `replay_cursor`，事件携带 `round_id`，旧轮次事件不得写入当前篇章。
- 设备重置导致 `local_total` 低于 cloud 基准时返回可恢复的冲突状态，禁止静默回退或无限重试；设备必须按 cloud 基准重建本地高水位后再继续。
- `local_total`、`acked_total`、`round_id`、`round_cursor`、`round_state`、`pending_completion` 和相关 `action_id` 作为同一持久化事务提交，掉电恢复后不得出现高水位、轮次与游标不匹配。

## 12. 非功能需求与成功指标

### 12.1 验收方式

> 验收方式：本项目为个人原型，MVP 不冻结“明显 / 大量 / 可辨识”等主观量词的判定阈值；SM-3、SM-7 等已写明的数字目标仍是验收目标。主观量词由创作者在目标外壳样机上逐条演示签收判定。

- **SM-1：可靠输入。** 单次和 1 秒 20 次连续输入不出现明显漏记、重记或乱序。
- **SM-2：动画连续性。** 木鱼页 7 字带和小程序阅读行不丢正式字符、不重复播放。
- **SM-3：端到端实时性。** 稳定 4G 网络下，95% 的有效敲击在其发生 1 秒内被小程序展示（端到端口径：设备敲击 → backend 确认 → frontend 渲染）。
- **SM-4：离线恢复。** 设备离线累计、重启、重复提交和网络恢复后，高水位、游标、轮次和统计最终一致。
- **SM-5：持久化。** backend 重启后高水位、游标、配置和历史统计不丢失。
- **SM-6：个人使用。** 创作者完成原型后愿意持续使用（工程期内不可直接判定，列为首轮样机后的回看项）。
- **SM-7：一天续航。** 约 30 分钟/天实际敲击、其余时间待机的使用模型下，设备至少支撑完整一天（最终以样机功耗实测为准）。
- **SM-8：自动模式一致性。** BOOT0 自动模式以 3 秒周期生成事件；事件的 UI、经文、音频、累计、持久化、同步和历史结果与真实敲击一致，退出后不再生成新的自动事件。
- **SM-C1：** 不以同时常开 BLE/Wi‑Fi/4G、堆叠音效或增加功能数量换取“在线感”，避免牺牲续航和核心诵经节奏。

## 14. 工程验证入口

工程验证结果回写架构主干 `ARCHITECTURE-SPINE.md`（见 `../../architecture/architecture-Electronic_Wooden_Fish-2026-09-08/`）、`docs/hardware/` 和对应 `docs/` 层级规格：

1. GPIO0/45/46 启动绑带、GPIO19/20 USB、GPIO9 ADC、GPIO11 比较器、GPIO43/44/10/15 Air780EGP UART/DTR/RST、GPIO8 PWR_INT 重映射；GPIO16 按定稿硬件保持未连接；下载按“BOOT0 保持低电平→长按 PWR 上电”验证，运行态 BOOT0 短按不得改变下载采样。
2. CO5300 FPC 供电、QSPI、亮屏/熄屏、CST9217 地址与触摸坐标。
3. CW2015、CST9217、ES8311、QMI8658A 的 I²C 地址、电平和上拉。
4. PVDF 模拟前端、比较器阈值、20 次/秒连续输入、误触发和硬断电持久化。
5. BOOT0 短按去抖、3 秒自动敲击周期、再次短按退出、自动模式 UI 投影，以及自动事件与真实敲击的一致性。
6. USB-C 外部供电、电池供电和外部供电并充电三种供电条件下，输入、经文、音频、显示、持久化、4G HTTPS 和同步均可用；不以主控充电检测作为验收前提。
7. Air780EGP 发射峰值、HTTPS 活动窗口、命令待应用、音频峰值和一天续航。

残余风险与 MVP 裁剪（若下列验证不通过，则重新冻结对应 MVP 边界，不静默扩范围）：20 次/秒输入可靠性不达标 → 收敛为设备明确的节流上限；Air780EGP 发射峰值导致掉压 → 缩短活动窗口或调整电源/模组选型；一天续航不达标 → 增大电池或下调默认亮度与熄屏时长；1 秒端到端实时不达标 → 保留离线一致性与回放，弱化“在线实时”承诺。
