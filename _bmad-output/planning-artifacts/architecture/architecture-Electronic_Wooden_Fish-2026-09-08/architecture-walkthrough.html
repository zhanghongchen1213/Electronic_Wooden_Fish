本轮关键决定
P-1后端零数据库：JSON 原子文件 —— 单实例单进程，临时文件 + fsync + rename，cloud/backend/data/ 落盘，重启全恢复。覆盖 PRD FR-B-009 与旧根文档的「SQLite」决定；零库写法借鉴 legbot_watch/cloud。 P-2backend 权威 + 幂等高水位同步 —— 设备带 local_total / acked_total / round_id 在活动窗口一次性上报；backend 只对高于已确认的差值推进一次，重复/回退为 no-op；轮次只由设备本地推进，backend 校验确认并回传。 P-3WebSocket 推送 + 快照水位补齐 —— 小程序断线后以「查询响应冻结的快照水位 S」为基准，只消费序号 > S 的实时差量，防空洞与重叠。 P-4旧根文档 architecture.md 已并入本主干后删除 —— 引脚表、电源、同步字段、验证门禁等保真迁移（对账见 reviews/reconcile-arch-parity.md）。

01两层一契约

嵌入式沿用 legbot_watch 范式；软件层以「活动窗口 + 幂等高水位」连接，不常开会话、不逐事件重放。

嵌入式层 Embedded

分层 BSP/Driver + FreeRTOS 服务任务事件驱动固件
唯一输入
physical_pvdf（比较器唤醒 + ADC 确认）与木鱼页点击 device_touch 进同一队列，无第二计数路径；熄屏首触只唤醒。
产品事实源
不可变 device_state 快照；UI/音频/4G 只读，服务经 typed event 通信。
板级
BSP 独占 GPIO/总线/电源，封装上游 managed_components；USB-Serial-JTAG（IO19/20）为唯一调试通道，IO43/44 让给 4G UART。
反馈
音频/触屏失败不阻塞计数与同步；高速连击合并音效；动画不丢字。
网络
仅 Air780EGP 4G HTTPS 一条业务链路；BLE/Wi‑Fi/GPS 不进入 MVP。

02跨层同步时序

一次活动窗口内：本地先反馈 → 幂等上报 → backend 确认并回传轮次状态 → WebSocket 推送差量 → 回低功耗。

sequenceDiagram
  participant D as 设备 Embedded
  participant A as Air780EGP 4G
  participant B as backend
  participant M as 小程序
  D->>D: 本地落盘 local_total · 动画/音效即时反馈
  D->>A: 活动窗口发起 HTTPS 上报(高水位 + round_id/游标 + 已应用修订)
  A->>B: POST 幂等同步包
  B->>B: 按高水位推进一次 · 按确认时间归档 · 翻转已应用命令
  B-->>A: acked_total · 差量 · 确认后轮次 · 待应用命令 · 可信时间
  A-->>D: 响应；设备以确认轮次收敛本地镜像并应用命令
  B-->>M: WebSocket 推送已确认差量(序号 > 快照水位 S)
  D->>D: 回到低功耗离线记录

03不变量一览 · 19 条 AD

完整 Binds/Prevents/Rule 见 ARCHITECTURE-SPINE.md。这里给每条一句话定位。

跨层同步（AD-1…6 · AD-19）
AD-1统一输入两类正式输入进同一队列，无第二计数路径；熄屏首触只唤醒；一敲即一「可消费」字。
AD-2云端权威backend 是已确认高水位/游标/轮次/完成/统计/命令的唯一权威；小程序只呈现已确认，设备本地镜像须标同步态。
AD-3幂等同步活动窗口 + 高水位幂等；轮次只由设备推进、backend 校验确认并回传，不按经文长度盲推。
AD-4经文版本单一文本源、构建期一致、版本不一致即停；只含所需字形，不选经不导入。
AD-5命令修订command_revision = 已应用修订高水位，随窗口携带幂等翻转，不依赖单次 ACK。
AD-6可信时间日统计归 backend 配置时区；设备「今日」非权威、未校时显「待校时」。
AD-19消费语义一敲一字、标点随附不耗敲；不预览未来经文；从头开始新建轮次、退出保留完成态。
嵌入式层（AD-7…15）
AD-7服务范式FreeRTOS 服务任务 + typed event；ISR 只投事件；命令型事件不得静默丢。
AD-8BSP 独占BSP 独占引脚/总线/电源并封装 managed_components；新芯片登记 CMake。
AD-9事实源device_state 不可变快照，服务只发 typed update，UI/音频/4G 只读。
AD-10单一仲裁共享 I²C / AT UART / LVGL 任务各一入口，单一事务所有权。
AD-11调试通道USB-Serial-JTAG(IO19/20) 唯一烧录/日志/JTAG；IO43/44 让给 4G。
AD-12不阻塞音频/触屏失败不阻塞计数持久化同步；连击合并音效；动画不丢字。
AD-13电源分轨供电；低电先落盘计数；充电暂停输入；PWR 关机归板级电路。
AD-14单 4G仅 Air780EGP 4G HTTPS 产品链路；BLE/Wi‑Fi/GPS 不进 MVP。
AD-15本地持久化高水位/游标跨重启可恢复；设置保留；不存绝对敲击时间。
软件层（AD-16…18）
AD-16后端骨架miaowu Spring Boot 3.3.7 + /api/v1 信封；零库 JSON 原子文件、单实例、重启可恢复。
AD-17前端差量WebSocket 推送 + 快照水位 S 补齐基准；只消费序号 > S，空洞先查再续播；回放接实时。
AD-18前端基线uni-app（Vue3+TS+Vite）仅微信小程序；单 VITE_API_BASE_URL + 统一请求封装。
跨层铁律（易踩）
  • 小程序没有可点木鱼，不是输入源。
  • 设备不存、不上报 PVDF 原始波形；单一外壳只标定一次。
  • backend 不按 total % 经文长度自行推游标/完成——只校验并确认设备上报。
  • 「待设备应用」≠ 已生效：靠已应用修订高水位翻转，不靠单次 ACK。
  • 断线补齐以查询响应快照水位为基准，前端不自算「已展示游标」。
